## 83. buildTime: Math.round и кламп ≥1 вместо целочисленного деления C ✔ ИСПРАВЛЕНО

- подсистема: buildings-grid / серьёзность: bug

- канон: 0x0041c944.c (FUN_0041c944), ветка стройки: '*(short *)(local_50 + 6) = (short)((*(int *)(&DAT_0045d848 + (char)*local_50 * 0x10) * 0x3c) / local_20);' — то же выражение в ветке восстановления из пепелища.
- вердикт: Порт (buildings.js:83-84) действительно считает Math.max(1, Math.round(time*60/Math.max(1,workers))). Канон в 0x0041c944.c — строки 466-468 (шаг стройки) и 497-498 (восстановление из пепелища) — содержит ровно процитированное выражение: (short)((*(int*)(&DAT_0045d848 + kind*0x10) * 0x3c) / local_20), т.е. знаковое целочисленное деление C с усечением к нулю, без округления и без клампа результата. local_20 — счётчик работников (цикл по жителям, строки 362-377, минус local_1c на 453), деление выполняется только под охраной 0 < local_20, так что кламп делителя в порте маскирует состояние, которого движок избегает guard'ом, а Math.round и Math.max(1, результат) — реальные расхождения. Пример аудитора верен: 60/7 = 8 в движке против Math.round(8.571) = 9 в порте; расхождение возникает при любой дробной части ≥ 0.5, т.е. часто.
