# Экран создания героя: канон и план переноса

> Более поздняя и полная спецификация этих экранов — `docs/MENU_CANON_SPEC.md`
> (09.08); при расхождениях верить ей. Экран реализован: `knyaz2/web/static/creation.js`.

Разбор снят с декомпилята 2026-08-08. Всё ниже — из движка, догадок нет;
там, где нужного адреса пока не хватает, это сказано отдельным пунктом.

## 1. Что это за экран

Рисует его `0x430DF4(param)`, где `param` — какая из двух стрелок сейчас
нажата (1, −1 или 0). На экране:

| Что | Откуда |
|---|---|
| фон на весь экран | спрайт из `0x6B35C0` |
| картинка выбранного героя | `0x6B35C8 + вид * 8`, координаты из таблицы `0x461D44` / `0x461D48` (шаг 0x10), вид = байт героя `+0xFC` |
| «Свободный опыт» | подпись `0x46141C`, число — слово `+0x48` героя |
| шесть характеристик | имена из массива `0x46144C` (шаг 8), значения — БАЗОВЫЕ байты `+0xC0+i` |
| двадцать навыков | продолжение того же массива имён, значения — байты `+0xD2+i` |
| «Максимальный вес» | подпись `0x46154C` (это запись 40 таблицы подписей), число `((+0xD1) * 1000 / 3 + 20000) * 0.001` форматом `%4.1f` |
| «Максимальный отряд» | подпись `0x461554` (запись 41), число `min(9, (+0xCC >> 4) + 1)` |
| портрет | герой рисуется живьём в буфер 160×160 (`0x425DB4`) и блитится по `0x4622D4` / `0x4622D8` |
| две стрелки | спрайты `0x1FC`…`0x1FF` по `0x4622B4` / `0x4622C4` |

Раскладка строк: характеристики с y = 130, навыки с y = 345, шаг 20.
Имя выравнивается ПРАВЫМ краем по x = 870, значение — по x = 920, «+» стоит
на x = 950, «−» на x = 970.

**Цвет значения — не украшение.** Если счётчик прибавок этой строки нулевой,
значение печатается обычной палитрой (`0x5EE348`); если игрок сюда что-то
добавил — другой (`0x5F744A`). То есть добавленное видно сразу.

## 2. Счётчики прибавок

Два массива: `0x8442D8` — шесть байт на характеристики, `0x8442E0` —
двадцать на навыки. В них лежит, сколько очков игрок добавил ИМЕННО НА ЭТОМ
ЭКРАНЕ. Обнуляет их выбор архетипа (`0x4387CC`), и только по ним разрешён
откат: «−» не даёт опуститься ниже того, с чем герой пришёл.

Это же объясняет находку реестра про вечный респек: в порте счётчики
привязаны к игровой панели персонажа и не сбрасываются никогда, тогда как в
движке они живут только на экране создания.

## 3. Кнопки (обработчик `0x438A00`)

| Код | Действие |
|---|---|
| 6…11 | «+» характеристики `i = код − 6` |
| 12…17 | «−» характеристики `i = код − 12` |
| 18…37 | «+» навыка `i = код − 18` |
| 38…57 | «−» навыка `i = код − 38` |

**«+» характеристики.** `0x4131FC` возвращает цену или ноль:

```
если +0x4A != 0            → нельзя (замок прокачки)
если +0x48 < 2             → нельзя (не хватает свободного опыта)
если база +0xC0+i < 150    → цена 2
иначе                      → нельзя (потолок 150)
```

При удаче: база `+0xC0+i` и текущая `+0xCC+i` растут на единицу, свободный
опыт уменьшается на цену, счётчик прибавок растёт.

**«−» характеристики.** Только если счётчик не ноль: база и текущая падают
на единицу, свободный опыт возвращается **на 2**, счётчик уменьшается, и
следом зовётся каскадный пересчёт навыков (см. ниже).

**«+» навыка.** `0x413268` возвращает 1 или 0:

```
если +0x4A != 0        → нельзя
если +0x48 == 0        → нельзя
если навык >= 100      → нельзя
иначе считается ПРЕДЕЛ по характеристикам (своя формула на каждый навык),
предел зажимается сотней, и поднять можно, только пока навык МЕНЬШЕ предела
```

Цена навыка — единица. Формулы пределов уже перенесены в порт (пункт 31
реестра), здесь их трогать не нужно.

**«−» навыка.** Только если счётчик не ноль: навык падает на единицу,
свободный опыт возвращается на 1, счётчик уменьшается.

## 4. Неочевидное: каскадный возврат (`0x437C48`)

Понижение характеристики опускает пределы навыков, и движок сам возвращает
всё, что перестало помещаться:

```
для каждого из двадцати навыков:
    пока счётчик прибавок этого навыка не ноль:
        вернуть 1 опыта, опустить навык на единицу
        если теперь навык снова МОЖНО поднять (0x413268 != 0):
            откатить этот шаг обратно и перейти к следующему навыку
        иначе:
            уменьшить счётчик и повторить
```

То есть игрок не может «занять» ловкость под стрельбу, а потом отобрать её
обратно, оставив навык: лишние очки вернутся в свободный опыт сами. Правило
неочевидное, и выдумать его вместо переноса нельзя.

## 5. Выбор архетипа (`0x4387CC`)

Стрелки переключают героя. Выбор — это выбор МИРА: движок открывает
`GAME.<номер>`, читает запись юнита 0 прямо в героя, обнуляет оба массива
счётчиков, чистит десять байт снаряжения `+0x58`, ставит направление 6 и
байт `+0x19` в четвёрку. Стартовая карта у каждого мира своя — это уже
перенесено и работает.

## 6. Что уже есть в порте

- шесть героев с их записями, картами и клетками (`hero.starts` в паке);
- пределы навыков, цена и потолок характеристики, вместимость отряда,
  предел веса — всё по канону;
- счётчики `raisedCharacteristics` / `raisedSkills` в `progress.js` — но
  висят на игровой панели, где их быть не должно.

## 7. Чего не хватает и что надо достать

1. **Координаты и спрайты экрана.** Числа выше сняты из кода, но в пак они
   не выгружаются. Нужен разбор `NEWHERO.RES` (фон и картинки героев) и
   вывод таблиц `0x461D44`/`0x461D48`, `0x4622B4`…`0x4622D8` в пак.
2. **Массив имён `0x46144C`.** Скорее всего это те же имена, что уже едут в
   `interface.character.labels`; надо сверить порядок, а не полагаться на
   совпадение.
3. **Спрайты «+» и «−»** (`0x4525B0`…`0x4525B6`) и вторая палитра для
   подсветки добавленного (`0x5F744A`).
4. **Кто печатает «Свободный опыт»** — подпись `0x46141C` в таблице подписей
   идёт до записи 34; проверить её индекс.

## 8. Порядок работы

**Шаг 1 — правила. СДЕЛАНО 2026-08-08.** Все три уже были в порте и сверены
построчно: цена 2 и потолок 150 у характеристики, цена 1 и предел у навыка,
каскадный возврат. `trimOvergrownSkills` совпадает с `0x437C48` дословно —
возврат опыта, шаг вниз, проверка «снова можно поднять», откат последнего
шага и выход к следующему навыку.

Проверено живьём: подняли Обучаемость с 10 до 22 (предел навыка стал 15),
вложили 15 очков в навык, затем отобрали характеристику до 16 — предел упал
до 14, навык сам срезался до 14, а опыт вернулся с 161 до 174. Навык встал
ровно на новый предел, как и требует канон.

**Шаг 2 — счётчики на место. СДЕЛАНО 2026-08-08.** «−» убран с игрового
экрана персонажа: там его в движке нет вовсе (рендер `0x42A8F4` печатает
только «+», обработчик `0x421690` знает лишь ветки поднятия). Счётчики
прибавок теперь растут ТОЛЬКО под признаком `creation`, то есть на экране
создания; поднятое в игре окончательно. Добавлен `creationReset` — аналог
обнуления в `0x4387CC`.

Проверено живьём: поднятие в игре счётчик не растит, на экране создания
растит, откат возвращает ровно 2 опыта и ниже принесённого не пускает.
Регрессию стережёт `CreationScreenContractTest` — он падает, если «−»
вернётся на игровую панель или счётчик начнёт расти вне экрана создания.

**Шаг 3 — экран без родных картинок. СДЕЛАНО 2026-08-08.** Живёт в
`knyaz2/web/static/creation.js` и открывается В ИГРЕ, а не в меню: в движке
его тоже рисует игровой рендер (`0x430DF4`), и только там доступны
настоящие правила прокачки — переносить арифметику в меню значило бы её
удвоить. Меню по «Новой игре» передаёт `create: true`, игра показывает
экран поверх сцены, «Играть» уводит на стартовую карту выбранного мира.

Раскладка канонная: имя правым краем по x = 870, значение по 920, «+» на
950, «−» на 970; характеристики с y = 130, навыки с y = 345, шаг 20;
свободный опыт на 74, вес на 270, отряд на 290. Добавленное на этом экране
печатается другим цветом, как движок печатает другой палитрой.

Проверено живьём через путь игрока: экран открылся на герое мира 1
(«2 из 6», свободный опыт 25, Харизма 15). «+» у Харизмы: опыт 25 → 23
(цена два), Харизма 15 → 16, появился «−». «−»: всё вернулось к 25 и 15,
знак исчез — ниже принесённого не пускает. Стрелка «▶»: «3 из 6»,
«начинает на карте 23», опыт снова 25, счётчики обнулены — как `0x4387CC`.

**Шаг 4 — родные картинки.** Разобрать `NEWHERO.RES`, выгрузить фон,
картинки шести героев и спрайты кнопок, поставить экран на них.

Шаги 1 и 2 полезны сами по себе и не ждут шага 4: без них экран будет
красивым, но с выдуманной арифметикой, а это ровно то, чего мы избегаем.
