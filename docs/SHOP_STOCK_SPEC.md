# Наполнение лавок: разбор FUN_0041896C

Дата разбора: 2026-08-09. Повод — отчёт первого бета-тестера (Александр С.):
«Все НПС торгаши пусты… у купца всегда функция рандомного товара, но она тоже
привязана к уровню развития персонажа».

Тезис подтверждён. Здесь записано всё, что вычитано из дизассемблера, и явно
отмечено, что ещё НЕ разобрано. Числа брать отсюда, а не выводить заново.

## Где это живёт

* **`FUN_0041896C(поселение)`** — сам генератор;
* зовётся из **`FUN_0043DF48`** — загрузчика карты, последней строкой перед
  выходом. То есть прилавки набиваются **при каждом входе на карту**, а не
  однажды при старте игры.

В игровых файлах прилавки пусты — это нормально: `village()` из `GAME.N`
отдаёт `goods = {2: [], 3: [], 4: []}`. Наполняет их только загрузчик.

## Три прилавка, а не один

Из `FUN_0043346C` (открытие торговли), ветка по должности собеседника:

| должность | смещение | мест |
|---|---|---|
| 2 (купец)   | `+0x3E0` | 22 (0x16) |
| 3 (знахарь) | `+0x40E` | 32 (0x20) |
| 4 (кузнец)  | `+0x44E` | 39 (0x27) |

Наш `village.js` моделирует только третий (`+0x44E`, мастерская) — тот, что
наполняется работой кузнеца. Двух других у нас нет вовсе.

## Что читает генератор

* `local_1c = герой[+0xF3]`, **потолок 13** — уровень игрока. Снято
  дизассемблером, VA `0x00418A11`, сомнений нет:

  ```asm
  00418a11  mov  edx, dword ptr [0x84951c]   ; запись игрока
  00418a19  mov  al,  byte ptr [edx + 0xf3]  ; уровень
  00418a22  cmp  dword ptr [ebp - 0xc], 0xd
  00418a26  jle  0x418a2f
  00418a28  mov  dword ptr [ebp - 0xc], 0xd  ; выше 13 не поднимается
  ```

  Это именно потолок уровня. Дальше он везде участвует как `уровень/5`,
  `уровень/4`, `уровень/3`, `уровень/2`;
* `iVar5 = DAT_0071E584[поселение[+2] * 0x100] >> 0x18` — культура деревни;
  через неё выбирается «школа» вещей.

Запись предмета (0x10 байт, арена `0x6F956C`, выделяется `FUN_0043B6D8`):

| смещение | что |
|---|---|
| `+0x00` | вид: 0 оружие, 1 метательное, 2 броня, 3 шлем, 4 щит, 6 ожерелье, 7 браслет, 8 кольцо, 9 зелье, 0x0B напиток, 0x0C пачка |
| `+0x03` | класс |
| `+0x04`, `+0x08` | прочность (float), обе копии из таблицы `0x45DAF8` |
| `+0x0E` | слово прибавок |

## Разобранная часть

### Купец, `+0x3E0`

```
n = rand() % 3 + 1                     # 1…3 позиции
для места 0 и 1:
    если n и место пусто:
        запись: вид 9, класс 0x53      # пустая банка
        n -= 1
```

### Знахарь, `+0x40E`, места 0…2 — украшения

Шанс на место: `rand() % 100 > 0x46`, то есть **29 %**.

```
бросок = rand() % 30
бросок < 10  -> вид 8 (кольцо),   база класса 0x42 (66)
бросок < 20  -> вид 7 (браслет),  база класса 0x3F (63)
иначе        -> вид 6 (ожерелье), база класса 0x3C (60)

класс = база + (уровень/5 < 2 ? 0 : rand() % (уровень/5))
слово прибавок = (rand() % (уровень/8 * 2 + 2) + 1) << ((rand() % 4) * 3)
```

### Знахарь, места 3…4 — напитки

Шанс `rand() % 100 > 0x32` — **49 %**. Вид `0x0B`, класс `rand() % 0x1B + 0x1E`
(30…56). Это НЕ монеты: класс 30 в паке — «Вино», и `potions.wine.class`
равен тридцати.

### Знахарь, места 5…7 — оружие по культуре

Шанс `rand() % 100 > 0x1E` — **69 %**.

```
школа = FUN_00416E80(культура)
класс = FUN_00416F48(школа, уровень)
вид 0; прочность = таблица_0x45DAF8[класс], и в +0x04, и в +0x08
с вероятностью rand() % 0x65 < 10 (10 %):
    слово прибавок = (rand() % (уровень/2) + 1) << ((rand() % 5) * 3)
```

Помощники разобраны целиком:

```
FUN_00416E80(культура):          # выбор школы 0…2
    культура == 0 -> rand() % 2 + 1
    культура == 2 -> rand() % 2
    иначе         -> rand() % 2 == 0 ? 0 : 2

FUN_00416F48(школа, уровень):    # класс вещи, три равновероятные ветви
    бросок = rand() % 3
    делитель = [5, 8, 8][бросок]
    база     = [0x65, 0x68, 0x6A][бросок]
    класс = rand() % (уровень/делитель + 1) + школа * 0x22 + база + (rand() % 2) * 7
```

## Разобрано полностью (2026-08-09, вторым заходом)

Дизассемблер снял то, что Ghidra печатала неразборчиво.

**Четыре группы подряд**, граница `[ebp-8]` наращивается, место пропускается,
если занято:

| группа | места | граница | порог `rand()%100 >` | шанс | что |
|---|---|---|---|---|---|
| 1 | 0–2 | `= 3`  (0x418A36) | `0x46` (0x418A76) | 29 % | украшения |
| 2 | 3–4 | `+= 2` (0x418C62) | `0x32` (0x418C9F) | 49 % | напитки |
| 3 | 5–7 | `+= 3` (0x418D27) | `0x1E` (0x418D64) | 69 % | оружие по культуре |
| 4 | 8–13 | `+= 6` (0x418E78) | `0x32` (0x418EB5) | 49 % | снаряжение |

Загадочное `0xd < local_28` оказалось просто последним местом четвёртой
группы — никакого скрытого гейта нет.

**Группа 4** — обычный цикл, по одной вещи на место, вид выбирает `rand()%3`:

```
0 -> вид 2 (броня), база 0x78, шаг rand() % (уровень/4 + 1)
1 -> вид 4 (щит),   база 0x7C, шаг rand() % (уровень/3 + 1)
2 -> вид 3 (шлем),  база 0x81, шаг rand() % (уровень/3 + 1)
класс = ((культура + 1) % 3) * 0x22 + база + шаг
```

**`FUN_00416F48(школа, уровень)`** — три равновероятные ветви:

| `rand()%3` | делитель уровня | база |
|---|---|---|
| 0 | `/5 + 1` | `0x65` |
| 1 | `/8 + 1` | `0x68` |
| 2 | `/8 + 1` | `0x6A` |

К любой прибавляется `школа * 0x22`, и с вероятностью ½ ещё `7`.

**Прилавок кузнеца генератор не трогает вовсе.** Обращений к `+0x3E0` — два,
к `+0x40E` — двадцать шесть, к `+0x44E` — ноль. Третий наполняет мастерская
(`FUN_00417BD8`), и она у нас уже перенесена.

**Поправка:** вид `0x0B` в местах 3–4 — это НЕ монеты. В паке класс 30 вида 11
называется «Вино», а `potions.wine.class` равен 30. Знахарь торгует напитками.

## Что осталось неразобранным

Одно: чем `FUN_0043B6D8` ограничивает арену записей предметов. Когда она
кончается, генератор возвращает ноль и бросает наполнение на полпути. У нас
такого предела нет вовсе — записи рождаются по требованию, — так что на
поведение это влияет только в крайнем случае, до которого игра, похоже, не
доходит.

## Перенесено

`knyaz2/web/static/shops.js`, зовётся из `app.js` рядом с `buildingsSetup()` —
там же, где вызов стоит в `0x43DF48`. Ссылки на вещи экземплярные
(`actorNewItemRef`), прочность и слово прибавок ложатся в `bagStrength` и
`bagEnchant` того же юнита, откуда их берёт экран торговли.

Проверено на живой карте 33 за первый уровень: должность 2 получила две
пустых банки, должность 3 — ожерелье, топор и кожаный доспех, одна вещь с
чарами. Товар копится между заходами: занятое место генератор пропускает.

Тесты — `ShopStockContractTest` в `tests/test_items_contract.py`: границы
групп 3/2/3/6 и пороги 0x46/0x32/0x1E/0x32, потолок уровня 13, прилавок
кузнеца не трогается, и отдельная сверка — что все названные генератором
классы есть в паке и совпадают по видам.
