# План интеграции звука в браузерную версию

Основание — docs/AUDIO_AUDIT.md: механика аудиосистемы оригинала вскрыта
герметично (каждый вызов сопоставлен, каждый слот объяснён). Принцип тот же,
что во всём порте: **повторяем движок, а не сочиняем** — формулы, пороги,
шансы и уровни загрузки берём из exe; расширения (неиспользуемые дубли,
лодка/дух) — только отдельным флагом.

## Решения

1. **Кодек — Opus** (libopus в ffmpeg из imageio_ffmpeg есть, проверено):
   - эффекты: моно 48 kbps (пласт целиком 26 МБ WAV → ~4 МБ);
   - музыка: стерео 96 kbps (59.7 МБ → ~4.3 МБ);
   - голоса: моно 32 kbps (447.5 МБ → ~43 МБ на диске; по сети — только
     нужные реплики, медиана ~27 КБ).
   WAV в паке больше не держим (кроме дев-режима). Safari < 17 не цель;
   если понадобится — второй прогон в AAC тем же скриптом.
2. **Три уровня загрузки — как в движке** (0x43C228 / 0x43DF48 / 0x42D13C):
   - старт страницы: UI 0–19 + отклики 32–79 + четвёрка героя 700+ ≈ 0.3 МБ;
   - вход на карту: амбиент карты + восьмёрки местных зверей + трек карты
     ≈ 0.6 МБ, **очередью по одному fetch за тик** (та же механика);
   - по требованию: реплика диалога в момент фразы, музыка при смене.
3. **Кэш-промах = молчание**, как в оригинале (0x42D660 требует слот в
   кэше). В дев-панели — счётчик промахов, чтобы видеть их числами.
4. **Правила — из exe в пак, не хардкодом в клиенте**: `sounds.py` отдаёт
   `rules()` (формулы слотов, шансы, пороги, питчи), билдер кладёт их в
   `assets/audio.json`, клиент читает. Контракт-тест сверяет константы с
   konung2.exe (в духе test_lighting_contract.py).
5. **Канон по умолчанию**: немые события (0, 11) остаются немыми, спец-звуки
   лодки/духа не звучат, дубли голосов молчат. Всё это включается флагом
   `audio.fixes` в паке — отдельным решением, не тайком.

## Целевые числа (проверяемые)

| метрика | значение |
|---|---|
| старт страницы (звук) | ≤ 0.4 МБ |
| вход на карту 19 (амбиент+звери+музыка) | ≤ 0.8 МБ |
| реплика диалога | ~20–35 КБ, старт ≤ 150 мс на локальном сервере |
| одновременных буферов | ≤ 45 (лимит движка) |
| громкость | gain = 10^(vol100/2000), отсечка vol100 < −4000 |
| пан | pan = (col − (левая_колонка+5))·62.5 / 10000 |
| питч эффектов | rate ∈ {19050, 22050, 25050}/22050 |

### 1. Кодек голосов: `konung2/voices.py`
Таблица 6000×8, смещения абсолютные; `pcm/duration/save_wav`, перечень
занятых, связка с QUESTS (поле `voice` фразы — уже в quests.py).
Проверка: 1245 записей, конец последней = размер файла, сверка с
докладом аудита; тест в tests/.

### 2. Канон в `konung2/sounds.py`
Константы и формулы из аудита: диапазоны слотов, `creature_slots(kind)`,
`ambient_slots(map)`, `response_slot(actor)`, `go_slot(actor)`,
`special_slot(record)`, попадания по типам брони {None:7,0:7,1:15,5:3,*:9},
замахи {0xD:16,0xF:4,*:10}, позиционка (2048, −10000, 62.5, центр+5),
шансы (амбиент rand%100>98; стойка 40 %, ходьба 24 %; приветствия каждые
1024 тика; отклик rand%3, «пошёл» rand%2), питчи `_VOICES`, лимит 45,
синглтоны. Плюс `rules()` для пака.
Проверка: **tests/test_audio_contract.py читает konung2.exe** и падает при
расхождении каждой константы с местом в коде (адреса из аудита).

### 3. Экспорт в пак (builder)
- `assets/sfx/NNN.opus` — все занятые немузыкальные слоты;
- `assets/audio/track_NN.opus` — музыка (11 петель);
- `assets/voices/NNNN.opus` — реплики, **инкрементально** (пропуск по хэшу
  исходного PCM в manifest-таблице `voices.json`; полная перегонка 447 МБ —
  только первый раз);
- `assets/audio.json` — rules() + опись слотов (длительность, канальность);
- в `map.json`: `audio.ambient = {day:[…], night:[…], cave:bool}`,
  `audio.preload=[амбиент+звери]`, `map_track` (есть);
- в дереве диалогов — поле `voice` узла (правка `Dialogs.tree()`).
Проверка: `knyaz2-content verify`; длительность каждого opus в ±2 % от
PCM-исходника (декодом, числами); размеры пласта — в целевых числах.

### 4. Ядро клиента: `sound.js`
AudioContext + разблокировка жестом (паттерн из menu.js); кэш
slot→AudioBuffer; три уровня загрузки; `playEffect(slot, {vol100, pan100,
loop, pitchable})` с формулами из audio.json; позиционка `positional(row,
col)` от камеры (якорь клетки уже в grid/geometry); лимит 45; синглтоны
музыка/голос юнита/реплика; бинарная громкость музыки; приглушение музыки
на время роликов (когда появятся).
Проверка: страница `sound_lab` (дев-каталог: слоты по группам, кнопки) +
selfcheck-правила: отсечка −40 дБ, лимит, формула громкости в трёх точках
против эталона движка.

### 5. События мира
- ui.js/inventory: клики 6, подтверждение 18, взять 17, надеть 0/1/2,
  level-up 14 (progress); окно 11 — немое (канон);
- menu.js: клик пункта 6 (наведение немое);
- units/actor: замах по оружию, звери 80/82/83/84 с шансами, состояние 4 —
  под флагом fixes;
- projectiles/combat: попадание 9/…, промах и стрела в землю 12, по броне
  цели 7/15/3/9;
- warband/orders: отклик выбора (голос-канал), «пошёл» 700-серия;
- scene/world: амбиент-планировщик 1 %/тик, день/ночь по игровому времени
  (порог заката — гейт 8100), пещеры по таблице карт; без позиционки;
- приветствия спутников раз в 1024 тика (VOICES 5500+).
Проверка: selfcheck-сценарий «прогулка по Чёрному Бору» — счётчики
сыгранных слотов по группам за N тиков в ожидаемых пределах; вручную —
sound_lab и игра.

### 6. Голоса диалогов
dialog.js: при входе в узел с `voice` — глушим предыдущую реплику, качаем
`assets/voices/NNNN.opus`, играем на канале реплик с питчем говорящего
(формат по `unit+0xF2` из audio.json/_VOICES).
Проверка: разговор с жителем в Чёрном Бору — реплика слышна, повторный
вход глушит предыдущую; промах файла не роняет диалог.

### 7. Чистовая: селфчек, веса, документация
