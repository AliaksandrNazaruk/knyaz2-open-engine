# Спутники: приём в отряд, уход и «останься здесь»

Разобрано по декомпиляту `engine/decompiled/functions/` и проверено на данных
`GAME.0` и собранном паке. Составлено 2026-08-11 по жалобе: «прошу спутника
остаться — он не остаётся; слот под нового не освобождается».

Ответ короткий: **в каноне это есть и работает не так, как ждёт игрок.**
Спутник не «ждёт», а насовсем переходит в поселение — становится его жителем.
Никакого «стоять и ждать в чистом поле» движок не умеет вовсе.

---

## 1. Где что лежит

| что | адрес | поля |
|---|---|---|
| отряды | `0x71E56C`, шаг `0x100`, 200 записей | `+0x00` u16 первый юнит, `+0x08` u16 карта, `+0x19` вместимость по Харизме, `+0x1A` сколько мест выделено в массиве юнитов, `+0x1C` сколько бойцов сейчас |
| юниты | `0x7B3C08`, шаг `0x100`, 2000 записей | `+0x01` = 0xFF при переезде, `+0x12`/`+0x14` строка/столбец, `+0x16` приказ, `+0x19` бит 0x40 «занят работой», `+0x1B` сторона = номер отряда, `+0xCC` Харизма, `+0xE6` восемь байт рабочих мест |
| поселения | `0x83D408`, шаг `0x4A1` | `+0x02` номер отряда деревни, `+0x3D0` пять слов должностей |
| панель девяти | `0x840B94`, 9 указателей | `0x840BB4` — девятый слот |
| указатели | `0x84950C` отряд игрока, `0x84951C` вожак, `0x849524` собеседник, `0x849538` поселение текущей карты | |

Юниты отряда лежат в массиве **подряд**: `юнит = 0x7B3C08 + (первый + i)*0x100`.
Поэтому отряд не может вырасти за отведённый ему кусок — это и есть `+0x1A`.

**Приказ `+0x16`:** младшая половина — вид приказа, старшая — биты. Бит `0x10`
означает «держаться за вожаком»: свободный юнит с ним зовёт догон
(`0x4111E8` → `0x41209C`), отстав на десять клеток. Выдача нового приказа
(`0x416574`) пишет `новый_вид | (старое & 0xF0)`, то есть **бит «за вожаком»
переживает любой приказ** — увести спутника «постоять в стороне» нельзя, он
вернётся.

## 2. Приём в отряд

**Гейт — условие 7 (`0x434CD0`).** Ровно так:

    вместимость = min(9, (Харизма вожака (+0xCC) >> 4) + 1)
    отряд+0x19 = вместимость          // движок её ЗАПИСЫВАЕТ, а не только считает
    вернуть: отряд+0x1C < отряд+0x19

Харизма берётся ТЕКУЩАЯ (с прибавками надетого), потолок девять. Значит при
Харизме 0…15 в отряде только вожак, при 16…31 — вожак и один, и так далее;
девять набирается с Харизмы 128.

**Действие 36 «взять в отряд» (`0x433070`).** По шагам:

1. `собеседник+0x1A &= 0xF8` — гаснут младшие три бита породы.
2. `собеседник+0x1D = 0x41B3B8(собеседник)` — пересчёт признака.
3. Запись собеседника (все 256 байт) копируется в **конец отряда игрока**:
   слот `(первый + число бойцов) * 0x100`, счётчик `+0x1C` растёт на единицу.
4. Новичку правится: `+0x1B` = сторона вожака, `+0x16` = **0x10 «за вожаком»**,
   `+0x01` = 0xFF, восемь рабочих байт `+0xE6` забиваются 0xFF (жителем деревни
   он быть перестаёт).
5. Клетка карты перештамповывается на его новый номер.
6. Из ПРЕЖНЕГО отряда он вычёркивается: счётчик того отряда −1, хвост массива
   сдвигается `memmove`, клетки оставшихся перештамповываются.
7. Если прежний отряд — деревенский (`+0x1E` бит 0x80) и поселение есть,
   правятся пять должностей (`поселение+0x3D0`): его номер обнуляется, номера
   старше — на единицу меньше. **Уходя в отряд, должностной освобождает
   должность.**

Своей проверки вместимости у 36 НЕТ — гейтом служит условие 7 в самом
разговоре. Реплики приёма («Мне нужны новые воины. Отныне ты будешь сражаться
вместе со мной») есть у старосты, воеводы, знахаря, кузнеца и купца.

## 3. «Останься здесь» — действие 43 (`0x4338B0`)

Это и есть та самая просьба. В данных она подписана дословно (карта 13, Ярун,
диалог 139, узел «Слушаю тебя!»):

> Останься здесь, пока я не хочу рисковать тобой. → делает 43(0)

**Что делает `0x4338B0`:**

1. Нет поселения на карте (`[0x849538] == 0`) → **вернуть 0, ничего не менять.**
2. Отряд деревни полон (`отряд+0x1C == отряд+0x1A`) → **вернуть 0.**
3. `цель+0x19 &= 0xBF` — снимается бит 0x40 «занят работой».
4. Запись цели (256 байт) копируется в **конец отряда деревни**, его счётчик
   `+0x1C` растёт на единицу.
5. Переехавшему правится: `+0x1B` = номер отряда деревни, **`+0x16` = 0 —
   приказ обнуляется целиком, вместе с битом «за вожаком»**, `+0x01` = 0xFF.
6. Клетка перештамповывается на новый номер.
7. **Из отряда игрока вычёркивается:** счётчик `+0x1C` −1, хвост массива
   сдвигается `memmove` на 0x100 назад.
8. **Панель девяти чинится** (`0x840B94`): ушедший выбрасывается со сдвигом
   хвоста, девятый слот обнуляется, у оставшихся указателей выше него
   вычитается 0x100; если первый слот опустел — туда становится вожак.
9. Клетки всех оставшихся бойцов перештамповываются.
10. `0x420644` пересобирает выбор, панель и пояс (`0x4308E0`, `0x43096C`).

Итог ровно тот, которого ждёт игрок: **спутник стоит на месте (приказа нет),
он больше не в отряде, слот освободился, и условие 7 снова пропускает нового —
Харизма считается от числа бойцов `+0x1C`, которое уменьшилось.**

Отличие от ожидания одно: он не «ждёт», а становится жителем деревни. Забрать
его обратно можно тем же действием 36 через разговор.

### А если деревни на карте нет — куда он денется?

**Такого случая не бывает: без поселения реплики просто нет.** Проверено по
байтам `QUESTS.RES`, а не по паку. Узлов с действием 43 в файле ровно шесть, и
у каждого стоит **условие 28 с аргументом 0**:

    узел 41:   действие=5   условие=13  → условия: обработчик 28(0)
    узел 248:  действие=110 условие=150 → обработчик 28(0)
    узел 457, 660, 873, 1080 — то же самое

А условие 28 (`0x4354A8`) начинается вовсе не с того, чем его подписывали:

```c
if (_DAT_00849538 == 0) return 0;                       // ДЕРЕВНИ НА КАРТЕ НЕТ
if (param_1 == 0) return 1;                             // есть — и этого хватит
if ((*(byte *)(_DAT_00849538 + 0x49c) & 0x15) == 0) return 1;   // не в тревоге
return 0;
```

То есть `28(0)` читается как **«на этой карте есть поселение»**. Отбор
вариантов делает `0x436478`: у каждого ответа своё поле условия (`+4` записи
узла), и `if (условие == -1 || FUN_00436664(условие) != 0)` решает, показывать
ли строку. Условие не прошло — ответа в списке нет.

Поселение к карте привязано жёстко: при входе (`0x43DF48`, строки 209-218)
движок обнуляет `[0x849538]`, перебирает двенадцать записей поселений
(`0x83D408`, шаг `0x4A1`) и берёт ту, у которой байт `+3` равен номеру текущей
карты. Не нашлось — указатель остаётся нулём, условие 28 отдаёт ложь, и
«Останься здесь» игроку не предлагают вовсе. Мёртвой кнопки в игре нет.

Единственная дыра, где движок всё же промолчит, — **полная деревня**: условие
28 её не проверяет, а `0x4338B0` на `+0x1C == +0x1A` вернёт ноль. Отказ
действия движок не показывает никак (`0x435F44` возврат просто отбрасывает).
В Борье свободных мест три, так что упереться в это можно.

**Наш порт условие 28 уже считает верно** (`dialog.js`, обработчик 28: первым
делом `if (!village) return false`). Значит после переноса действия 43 реплика
сама собой окажется там, где ей место.

### Два ограничения, которые обязаны быть и у нас

- **Только на карте с поселением.** В глуши реплики просто нет смысла: 43
  вернёт ложь.
- **Только пока у деревни есть свободное место.** Числа из `GAME.0`
  (`+0x1C`/`+0x1A` отряда деревни): карта 19 — 9/20, карта 33 Борье — 14/17,
  карта 13 — 8/24, карта 37 — 14/20, карта 21 — 11/17, карта 20 — 12/21,
  карта 18 — 16/24, карта 23 — 13/17, карта 25 — 16/24, карта 39 — 10/17.
  То есть запас у деревень заложен намеренно, но он не бесконечен: в Борье
  свободных мест всего три.

## 4. Соседние действия того же семейства

- **74 «поставить собеседника на должность» (`0x435D4C`).** Если место
  свободно — внутри зовёт то же `0x4338B0`, а затем последнему бойцу отряда
  деревни пишет клетку рабочего места и саму должность (`+0xE6`). Реплики:
  «ты будешь старостой», «останешься здесь воеводой», «займись кузницей»,
  «готовь лечебные смеси». **У нас это единственное, что уже реализовано.**
- **46 «удалить юнита из мира» (`0x433E30`).** Клетка чистится, из отряда
  игрока вычёркивается, должности освобождаются и сдвигаются. Это не «остаться»,
  а исчезнуть совсем.
- **44 «увести отряд собеседника с карты» (`0x433C30`).** Отряду пишется
  карта 0 — уходит весь отряд, к спутникам отношения не имеет.

## 5. Как разговор со своим вообще начинается

Ctrl (`[0x8495AC]` не ноль) плюс щелчок по юниту своей стороны (`+0x1B` равны):
вожаку пишется цель `+0x10` = номер юнита и приказ `+0x16 = 0x22` — «подойти и
заговорить» (`0x421690`, ветки на строках 279-288 и 349-355). Дойдя, движок
открывает разговор, и там уже условия выбирают узел: своему показывают
«Слушаю тебя!» со списком просьб, чужому — обычное приветствие.

## 6. Всё дерево разговора со спутником

Снято прямо с `QUESTS.RES`. Меню спутника — шесть одинаковых по составу копий
(узлы **40, 247, 456, 659, 872, 1079**), по одной на мир: тексты и голоса свои
(«Слушаю тебя!», «Да, мой командир!», «Чем я могу быть тебе полезна?»), набор
вариантов — до строчки один и тот же. Двенадцать вариантов, девять последствий.

При показе меню выполняется действие «поставить бит 1 флагов собеседника»
(`+0xF7`) — метка «с этим уже говорили».

| # | Реплика игрока | Условия | Действия |
|---|---|---|---|
| 1 | Останься здесь, пока я не хочу рисковать тобой | `28(0)` есть поселение | `43` стать жителем |
| 2 | Ничего, пошли дальше | — | закрыть |
| 3 | Я хочу посоветоваться с тобой | `16(15)` текущий Интеллект ≥ 15 | ветка советов |
| 4 | Наше оружие поизносилось, займись ремонтом | **нет условий** | `65` починить снаряжение отряда |
| 5 | В отряде есть раненые | `18(180)` И `33(0)` | `55` лечит отряд + `67` метка |
| 6 | Ты истекаешь кровью | `18(180)` И НЕ `12(50)` | `56` игрок лечит его + `67` |
| 7 | Попробую залечить твои раны | `18(180)` И НЕ `12(100)` И `12(50)` | `56` + `67` |
| 8 | …ты будешь старостой | `28(1)` И НЕ `29(0)` | `74(0)` |
| 9 | Останешься здесь воеводой | `28(1)` И `4(4)` И НЕ `29(4)` | `74(4)` |
| 10 | Лавка в запустении, поработай в ней | `28(1)` И `4(2)` И НЕ `29(2)` | `74(2)` |
| 11 | Некому ковать оружие, займёшься этим | `28(1)` И `4(3)` И НЕ `29(3)` | `74(3)` |
| 12 | Готовь лечебные смеси в избе знахаря | `28(1)` И `4(1)` И НЕ `29(1)` | `74(1)` |

Что стоит за каждым числом:

- **`28(0)` / `28(1)`** — `0x4354A8`. Ноль: «поселение на карте есть». Единица:
  ещё и «оно спокойно» — биты `0x15` байта `+0x49C` пусты.
- **`4(N)`** — `0x434AF0`, **«постройка на месте N ЕСТЬ»**: ненулевое состояние
  ИЛИ ненулевой счётчик. Не «свободно», как было подписано у нас. Поэтому
  воеводу нельзя поставить без казармы, кузнеца — без кузницы и так далее.
  У старосты (`74(0)`) такого условия нет: ему дом не нужен.
- **`29(N)`** — `0x435500`, должность занята (пять слов с `+0x3D0`). Стоит с
  отрицанием: назначают только на свободную.
- **`18(180)`** — `0x434FFC`: `abs(время_суток/15 − метка собеседника +0x4C)`
  не меньше 180. Метку ставит `67` (`0x435A2C`). Это выдержка между лечениями:
  подлечиться у спутника нельзя дважды подряд.
- **`12(N)`** — `0x434E64`: `N*16` не больше здоровья собеседника (полное 1600,
  то есть аргумент — проценты). Отсюда две реплики про лечение: «истекаешь
  кровью» при здоровье ниже 50, «залечу раны» при 50…99.
- **`33(0)`** — `0x4356B8`: у кого-то в отряде здоровье меньше 1600.
- **`16(15)`** — `0x434F50`: ТЕКУЩИЙ Интеллект вожака не меньше 15. Дурак
  советоваться не станет.

Последствия:

- **`65` починить снаряжение отряда** (`0x4358BC`) — каждая вещь надетого и
  мешка всех живых бойцов проходит точило `0x432DE0` от лица собеседника, то
  есть по ЕГО Кузнечному делу. Бесплатно и без всяких условий — деревенский
  кузнец за то же берёт деньги.
- **`55` собеседник лечит отряд** (`0x434630`) — каждому живому бойцу здоровье
  поднимается до `Знахарство собеседника * 16`, если это больше нынешнего; за
  каждого вылеченного навык растёт на единицу (потолок 100). У деревенского
  знахаря та же услуга стоит 500 монет (`55` + `60(-50)`), у спутника даром.
- **`56` игрок лечит собеседника** (`0x43473C`) — здоровье спутника до
  `Знахарство ВОЖАКА * 16`, растёт навык игрока.
- **`74(N)` должность** (`0x435D4C`) — внутри зовёт `0x4338B0` (то же, что 43),
  затем последнему бойцу отряда деревни пишет клетку рабочего места должности
  и саму должность (`+0xE6`).
- **Ветка советов** — чистый текст: шесть вопросов, каждый под своим квестовым
  битом (32 Белун, 70 дом Радагаста, 75 ярл, 86 Старый Сом, 50 волшебные
  камни), плюс безусловный «как выполнить миссию Титанов». Никаких действий,
  только речь; возврат в тот же узел.

### Изгнание — отдельная ветка, только у сюжетных спутников

Общее меню прогнать спутника не умеет. У именных есть своя реплика:

    «Твои услуги мне больше не нужны. Уходи от меня навсегда.»
        52 затемнить экран → 46(7) удалить юнита из мира → 51(100) дать опыт
        → 66 просветлить экран

и мягкий вариант у спасённой пленницы: `52 → 46(0) → 66` без опыта. То есть
изгнанный НЕ становится жителем — он исчезает с карты совсем, в отличие от
«Останься здесь».

### Приём в отряд — 65 обращений в разных обёртках

Одно и то же действие `36`, разные реплики: свободный наёмник («Я отдохнул и
готов идти за тобой» → «Хорошо, пошли»), деревенские знахарь, кузнец, купец,
воевода и староста («Мне нужны новые воины. Отныне ты будешь сражаться вместе
со мной»), сюжетные («Я пойду с тобой и отомщу за смерть моего деда»). Есть и
составные: `51(250)` + `36` — верность за награду; `52` + `36` + `69(8)` + `66`
— взять в отряд и тут же увести по переходу.

### Чего в разговоре со спутником НЕТ

- **Опознания.** Обработчик `58` («опознать всё у игрока», растит навык
  Идентификации за каждую вещь) встречается четырежды и только у бродячего
  мага: «Я идентифицирую любые магические предметы всего за 250 монет».
  Спутник вещи не опознаёт.
- **Стройки.** `40` («заложить постройку», 56 обращений) — исключительно у
  старосты, в меню «Жду твоих приказов». Спутнику не строят, спутника ставят
  на должность.
- **Волхования как такового.** Обработчика магии в таблице нет вовсе.
  Единственное «волшебство» в разговорах — исцеление оборотня:
  `52` + `59(731)` смена облика + `56` лечение + `66` + `45(91)` забрать
  предмет + `51(250)` опыт. Это одна сюжетная сцена, а не услуга.
- **Обучения и раздачи характеристик.** `49/53/68/73` (Ловкость, Харизма,
  Сила, Выносливость) — только у Старого Сома, по 50 за просьбу, и у бродячих
  музыкантов (`53(-1)`).

## 7. Что есть у нас и чего не хватает

Наша модель отряда другая, но равносильная: постоянный список —
`hero.party.members` (переживает смену карты, `spawnCompanion` поднимает бойцов
на новой карте), признак на карте — `unit.ally`. Панель девяти выводится из
этого же списка, отдельного массива указателей нет.

**Уже верно:**

- условие 7 — вместимость `min(9, (Харизма>>4)+1)` от текущей Харизмы
  (`dialog.js`, обработчик 7);
- действие 36 — приём в отряд с `ally`, стороной, приказом 0x10 и очисткой
  рабочих мест;
- действие 74 — назначение на должность, и оно уже зовёт `partyRelease(unit)`.

**Не хватает ровно одного: обработчика 43.** Его в таблице `HANDLERS` нет
вовсе, поэтому вариант «Останься здесь, пока я не хочу рисковать тобой» молча
падает в `dialog.pending` — реплика произносится, и не происходит ничего.
Отсюда и жалоба целиком.

### Сделано 2026-08-11

1. **Обработчик 43 добавлен** (`dialog.js`): нет поселения — ложь; отряд
   деревни полон — ложь; иначе `partyRelease`, `ally = false`, сторона
   деревни, `orderByte = 0` (вместе с битом «за вожаком»), снят признак
   «занят», `deselect` вместо движковой починки панели девяти.
2. **Запас деревни приехал в пак.** `konung2/gamefile.py::village` отдаёт
   `squad_places` (отряд `+0x1A`) и `squad_people` (`+0x1C`), взятые из
   записи отряда деревни в `GAME.x`. Без нового пака поле пустое, и гейт
   просто не срабатывает — старый пак от этого не ломается.
3. **74 переписан по движковому порядку:** проверка свободной должности →
   `HANDLERS[43](0)` → и только при его успехе запись должности. Полная
   деревня теперь отменяет назначение целиком, как в `0x435D4C`. Заодно
   рабочий байт получает НОМЕР ДОЛЖНОСТИ, а не пустоту.
4. **Сохранение.** В блок поселения добавлены `officials` и `squadPeople`:
   без них должность и оставленный житель откатывались загрузкой.
5. **Контрактные тесты** — `CtrlTalkContractTest`: гейты 43, движковый
   порядок в 74, и числа запаса сверяются с `GAME.0` (Борье 14 из 17).
   Прогон: 405 passed, 1457 subtests.

Остальные одиннадцать вариантов меню были на месте и раньше: в `HANDLERS`
есть `65`, `55`, `56`, `67`, `74`, `46`, а условия `4`, `12`, `16`, `18`,
`28`, `29`, `33` считаются по канону — в частности `4` уже отвечает
«постройка есть», хотя конспект `quests.py` называл её наоборот (подпись
исправлена там же).

### Осталось

- **Житель не переживает уход с карты.** `mapstate.js` помнит только мёртвых,
  кучи и отряды; смена стороны у живого юнита не сохраняется, а постоянный
  список отряда (`hero.party.members`) его больше не держит. Пока спутника
  оставляют в той деревне, откуда он родом, при возврате он поднимется из
  пака своим же жителем и разницы не видно. Оставленный в ЧУЖОЙ деревне
  пропадёт. Чинится тем же, чем и пропавшая стройка: памятью карты, которая
  хранит не только смерти.
- **Проверить в игре, что меню спутника открывается тем самым узлом.** Весь
  список из двенадцати строк висит на шести узлах `QUESTS.RES`; если наш
  выбор ветки уводит в другой узел, часть строк не покажется.
