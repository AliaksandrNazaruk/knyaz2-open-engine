# План трансляции «Велиславна выживает» (Дом2-агент)

Дата: 2026-08-15. Статус: Ф0 сделана (static/agent.js, knyaz2.agent.selfcheck()
7/7, живые прогоны: подбор Лопаты и разговор с Мстиславом целиком через ручки);
из Ф1 сделан фоновый драйвер такта (Worker-пульс в app.js: 12.75 такта/с в
скрытой вкладке при каноне 12.8 — обычный setInterval Chrome душит до 1/мин).
Остальное Ф1 (timeScale, стоп-кадр, кап отрыва) и Ф2—Ф4 — впереди.

## Идея одним абзацем

Агент (быстрая модель через постоянную сессию CLI/SDK) играет героем в боевой
вкладке. Скучные отрезки — дорога, ожидание, длинные диалоги — симуляция
прокручивает ускоренно; на решениях модели мир замирает. Зритель смотрит
отдельным клиентом-плеером ленту состояний со сдвигом до 10 минут, всегда в
1x, плавно и без пауз «модель думает». Отставание — это заработанный на
скучных местах запас; экшн его тратит, дорога копит.

## Архитектура

    боевая вкладка (симуляция + agent.js)
        │  кадры ленты: игровое время, позы, события, мысли
        ▼
    broadcast-сервер (кольцевой буфер 10–15 мин, каркас presence.py)
        │  реплей с отступом, темп по игровому времени
        ▼
    watch.html (наш же клиент в режиме плеера: рендер из ленты,
                управление отключено, камера и звук — зрителю)

Сервер миром не владеет (как presence.py — тупой ретранслятор с памятью);
истина всегда в боевой вкладке.

## Правило времени («стабильный заработок»)

- Одна точка времени: `app.js: animationFrame(now)` — ЕДИНСТВЕННЫЙ вход
  реального времени (seconds → clockAdvance, dt → все *Tick). Виртуальные
  часы ставятся ровно сюда: `virtual += realDt * scale`, дальше по коду идёт
  только virtual. Ничего больше трогать не надо — проверено чтением цикла.
- Политика скоростей (живёт в agent.js, НЕ в ядре):
  - модель думает → scale 0 (стоп-кадр, диф не тратится);
  - приказ «идти далеко» / пустой лес → scale 4–8 (заработок дифа);
  - бой, диалог, торговля → scale 1 (события пишутся в честном темпе);
  - отрыв от хвоста ленты ≥ капа (10 мин) → scale 0, ждём зрителя.
- CATCHUP_LIMIT=4 такта/кадр в clock.js НЕ поднимать (фазы `&0xF` дороже):
  турбо достигается частым вызовом animationFrame с виртуальным шагом
  (setInterval-драйвер), а не большим долгом на один кадр.
- Тот же setInterval-драйвер лечит замеренную беду: фоновая вкладка на rAF
  тикает ~1 кадр/с (мир в ~30 раз медленнее). Боевой вкладке рендер не нужен —
  при scale>1 рисование пропускается, звук боевой вкладки выключен.

## Фазы

### Ф0. Ручки агента — agent.js (маленькая, всё уже разведано)
Файл `static/agent.js`, экспорт в `window.knyaz2.agent`:
- снапшот (перенос отлаженного в консоли `agentSnapshot`): режим
  (local|worldmap|dialog|dead|menu — сейчас размазан по `worldMap.onMap/open`,
  `dialog.unit`, `hero.alive`), герой, юниты с дистанциями, лут по именам
  (`world.map.items['class:N']`), выходы;
- исполнитель (`agentExec`): approach/talk (orderAt по .x/.y цели), move,
  choose (реплика по индексу через dialogChoose), pickup, wait;
- недостающие экспорты: `lootTake`/`lootNear` (loot.js — есть, наружу не
  отдан; подбор сейчас агенту НЕДОСТУПЕН — панель персонажа канвасная),
  `dialogChoose`/`dialogClose` (dialog.js);
- журнал событий (кольцо с меткой clock.ticks): приказ выполнен/сорван,
  диалог начался/реплика/закончился, урон/смерть, подбор, смена карты.
  Журнал = будильник модели И источник событийных кадров ленты.

### Ф1. Виртуальное время (средняя, аккуратность в одной функции)
- `clock.js`/`app.js`: виртуальный аккумулятор в animationFrame; ручки
  `knyaz2.time = { scale, pause(), resume() }`;
- setInterval-драйвер при document.hidden или scale>1;
- пропуск рендера при турбо (dirty-ветку глушить, рисовать раз в N сек);
- тест: при scale=8 тиков ровно в 8 раз больше за то же реальное время,
  clockPhaseHits не теряет фазы (сверить счётчики стройки/работы).

### Ф2. Лента состояний (средняя, каркас есть)
- Писатель в боевой вкладке: кадр ~7–13 Гц игрового времени
  {t: clock.ticks, герой/юниты: x,y,направление,поза,hp, события из Ф0,
  мысль модели (say), реплика диалога, daylight.time}; раз в ~30 игровых
  секунд — полный кадр-синхро (лут на земле, двери), между ними дельты;
- `broadcast.py` по образцу presence.py (те же кадры RFC 6455, тот же стиль):
  роль publisher (одна), кольцевой буфер на 10–15 мин игрового времени,
  роль viewer: подключение с отступом, отдача в темпе игрового t;
  оценка веса: сотни байт/кадр × 10 Гц ≈ единицы КБ/с — мелочь;
- сервер отдаёт «в буфере от…до» — плеер выбирает отступ и держит запас.

### Ф3. Зрительский плеер watch.html (самая большая)
- Наш клиент в режиме replay: карта из content pack как обычно, но
  локальные heroTick/unitsTick/combatTick/clockAdvance ВЫКЛ — позиции и позы
  применяются из ленты с интерполяцией (шаг 0.78 с — линейной хватит);
- диалоги: реплики из ленты через обычный диалоговый UI + озвучка
  (voice-номера в данных есть), темп чтения зрительский;
- смена карты по событию map_change → обычный путь загрузки;
- управление закрыто: input.js не подключать; зрителю — камера (колесо,
  перетаскивание) и звук: это безопасно и живо;
- плавность при голодной ленте (модель зависла дольше запаса): плеер сам
  тормозит 1x→0.5x→пауза с оверлеем «Велиславна размышляет…» и последними
  мыслями (say) — пауза становится частью шоу, а не багом;
- субтитры say + плашка последних событий.

### Ф4. Петля агента и Дом2-механика (параллельно Ф2–Ф3)
- постоянная сессия модели вместо `claude -p` на каждый ход (замерено:
  ~9 с на холостой запуск процесса против ~1–2 с ответа Haiku);
  лестница: рефлексы кодом → Haiku тактика → Sonnet стратегия по триггерам
  (2–3 провала подряд, новое событие, высокие ставки) + общий дневник;
- смерть: СДЕЛАНО (static/respawn.js, knyaz2.respawn, selfcheck 7/7 + E2E):
  якорный сейв в деревне, деньги и сумка переезжают с погибшего, надетое
  пропадает, уровень из якоря; воскрешение через слот «Продолжить» (savePut)
  и перезагрузку — своей ветки восстановления мира нет;
- позже: чат зрителей влияет с задержкой догона (диф делает подсказки
  «в прошлое» бесполезными — применять голосования в моменты нулевого отрыва).

## Порядок и что даёт каждый шаг

1. Ф0 — агент полноценно играет (лут! диалоги по индексу! события).
2. Ф1 — стоп-кадр на решения + турбо: модель перестаёт ждать и тупить.
   Уже здесь можно гонять «серии» без зрителей и копить дневник.
3. Ф2+Ф3 — зрители. 4. Ф4 — постоянная труппа моделей.

## Риски

- Расхождение сцены плеера с боевой (лут/двери) — лечится кадрами-синхро;
- скрытые потребители реального времени мимо animationFrame (аудио-фейды,
  CSS-анимации) — при турбо не критично (рендер выключен), проверить на Ф1;
- clockAdvance сбрасывает долг при разрыве >1 с — драйвер обязан звать кадр
  чаще раза в секунду даже на паузе (scale=0 — звать с dt=0);
- сохранения: автосейв при турбо не должен писать чаще (гейт по игровому t).
