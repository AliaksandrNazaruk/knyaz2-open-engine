# Механика атаки: законы оригинального движка

Собрано с разобранного `konung2.exe`. Каждое утверждение помечено адресом
функции, из которой оно снято. Отсебятины здесь нет: где код не даёт ответа,
стоит пометка **[ОТКРЫТО]**, а не догадка.

Дата сбора: 2026-08-10. Корпус: `engine/decompiled/functions`, 724 функции.

## 0. Как читать этот документ

Ghidra врёт предсказуемо, и в тексте ниже чтения приведены к настоящим:

| в декомпиляции | на самом деле |
|---|---|
| `*(int *)(p + 0x14) >> 0x18` | байт `p+0x17` |
| `*(int *)(p + 0x1a) >> 0x18` | байт `p+0x1D` |
| `*(int *)(p + 0x4c) >> 0x10` | слово `p+0x4E` |
| `*(int *)(&DAT_00xxxxxx + i) >> 0x18` | байт таблицы со смещением `+3` |

Поле `hp` = `+0x4E s16`, 1600 = 100 % — это уже установлено в `FORMATS.md`
и сходится с тем, что вычитает резолвер удара.

## 2. Вход в ближний бой — VA 0x416B50

```
если НЕ тварь (+0x1A & 0x40 == 0):
    +0x19 |= 0x04                       поднять боевую стойку
    +0xEE = 0                           ПЕРЕКЛЮЧИТЬСЯ НА РУКУ
    предмет = +0x56
    если предмета нет ИЛИ группа(предмет) < 0x0D:
        если +0xD3 == 0            -> блок 5
        иначе:
            второй = +0x5E
            если второго нет ИЛИ вид(второй) == 0  -> блок 9
            иначе                                   -> блок 5
    иначе                                            -> блок 8
    поставить блок (0x416740)
    если 4 - скорость(+0x1D) < 2: +0xFD = 1
    иначе:                        +0xFD = 1 + rand() % (4 - скорость)
иначе (тварь):
    поставить блок 5, +0xFD = 1
```

**Главное здесь — строка `+0xEE = 0`.** Движок при входе в ближний удар
СБРАСЫВАЕТ режим стрельбы. Юнит с луком, к которому подошли вплотную,
переходит на руку сам; отдельной проверки «а не далеко ли» тут нет вовсе.

## 3. Вход в стрельбу — VA 0x416AC8

```
если +0x1A == 0x53:  поставить блок 5      (особый случай, [ОТКРЫТО] что за порода)
иначе:
    +0x19 |= 0x04
    +0xEE = 1                              РЕЖИМ СТРЕЛЬБЫ
    если группа(+0x58) == 0x15: блок 10    боевой самострел
    иначе:                      блок 4     лук
```

## 4. Можно ли вообще стрелять — VA 0x414AF8

```
если НЕ тварь:
    если расстояние(0x43B670) < 3 клеток -> вернуть -1     В УПОР НЕ СТРЕЛЯЮТ
    дальность = [0x45DAFE + класс(+0x58)*0x20] >> 16
иначе:
    дальность = 0x28 (40 клеток)
шагать от стрелка к цели по восемь подшагов на клетку, не дальше `дальность`:
    дошли до клетки цели            -> 1   можно
    клетка с битом 0x40 на пути     -> 0   нельзя (стена/постройка)
не дошли за `дальность` шагов        -> 0
```

Бит `0x40` берётся из карты проходимости `0x5662BC`, слово на клетку,
байт `+1`.

## 5. Момент удара внутри анимации — VA 0x412480

Возвращает, каким гнездом бьём на ЭТОМ кадре:

```
тварь (+0x1A & 0x40):
    кадр(+0x1C) == [0x459F71 + порода(+0xFC)]>>24  -> 0
    иначе -> -1
блок 9 (удар двумя руками):
    кадр == (DAT_0045FE98 & 0x70) >> 4   -> 0    основная рука
    кадр == (DAT_0045FE98 & 0x0F)        -> 4    ВТОРАЯ рука
    иначе -> -1
остальные блоки:
    кадр == −([0x45FE8D + блок(+0x17)] >> 24)  -> 0
    иначе -> -1
```

**[ОТКРЫТО]** минус в последней строке — либо настоящая семантика (кадр
считается с конца), либо потерянный Ghidra знак. Проверять по сырому асму.

Отсюда же следует канон: **блок 9 бьёт ДВАЖДЫ за анимацию**, на двух разных
кадрах, и второй удар идёт гнездом 4 (вторая рука).

## 6. Разрешение ближнего удара — VA 0x41C194

Аргументы: `(жертва, атакующий, сила_удара, гнездо)`. Возврат — код исхода.

```
0. если _DAT_00849620 != 0 И жертва == _DAT_0084951C -> -2      [ОТКРЫТО] что за режим
1. ПАРИРОВАНИЕ  (снято дизассемблером, 0x41C1CE…0x41C230)
   пересчитать характеристики жертвы (0x41C494)
   если [0x459F94 + напр_атакующего + напр_жертвы*8] != 0:
        порог = ROUND( ловкость_жертвы(+0xCD) * 0.5 )       const @0x450160
        если rand() % 101 <= порог -> вернуть -2
   Таблица 8x8 -> удар СО СПИНЫ не парируется вовсе.
2. СМЕРТЕЛЬНЫЙ УДАР  (0x41C268…0x41C2AC)
   навык = атакующий+0xD4
   если навык != 0 И (навык / 10) >= rand() % 100  -> код 1 (смерть), МИНУЯ урон,
   броню, отраву и износ
3. УРОН  (0x41C244…0x41C2E1) — формула снята командами, целиком
   броня = 0x41A414(жертва)
   сырое = сила*0.7 - броня            const @0x450168, во float
   если сырое <= 0: сырое = 0          (fcompp/jbe, 0x41C255…0x41C261)
   урон = ROUND( (( сырое + сила*0.3 ) / стойкость_жертвы(+0xD1) + 1) * 16 )
                        const @0x450170 = 0.3      @0x450178 = 16.0
   если урон < hp(+0x4E):
        hp -= урон                     sub word ptr [жертва+0x4E]
        пересчитать (0x41C494)
        код = -1 если урон < 0x30, иначе 0
   иначе код = 1 (смерть)
4. ОТРАВА
   жертва+0x52 += _DAT_00849704        (отрава оружия, её кладёт 0x41A7D0)
5. ИЗНОС БРОНИ ЖЕРТВЫ, гнёзда 2…4
   доля = min(1.0, сила_удара / броня_жертвы)     если броня 0 -> доля = 1.0
   прочность -= доля * [0x45DAF4 + класс*0x20] * _DAT_00450180
   прочность <= 0 -> класс = −1, гнездо очищено
6. ИЗНОС ОРУЖИЯ АТАКУЮЩЕГО, гнездо из аргумента
   боезапас [0x6F9578] -= 1, если не ноль
   прочность -= сила_удара * _DAT_00450188
   прочность <= 0 -> класс = 0xFF, гнездо очищено
```

### Коды исхода и что делает вызывающий — VA 0x413894

| код | значение | что делает вызывающий |
|---|---|---|
| `1` | смерть | `0x41B044(жертва)` награда, `0x416A00(жертва)` смерть, `0x413110(атакующий, награда/4)`, `0x416E24` |
| `0` | обычный удар | `0x416740(жертва, 2)` — **реакция «вздрогнуть»** |
| `-1` | слабый удар (урон < 0x30) | ничего: урон нанесён, жертва не прервана |
| `-2` | промах или парирование | ничего |

## 7. Разрешение выстрела — VA 0x41BF54

Аргументы: `(жертва, сила, точность)`. Снято дизассемблером целиком.

```
0. пересчитать характеристики жертвы (0x41C494) — ДО всего, в отличие от ближнего
1. гейт _DAT_00849620 / _DAT_0084951C -> -2
2. ТОЧНОСТЬ (0x41BF8E):
   если rand() % 101 > точность -> -2 (промах)
3. ПАРИРОВАНИЕ СТРЕЛЫ (0x41BFB2…0x41BFF4):
   порог = ловкость_жертвы(+0xCD) * 0.1        const @0x450138
   сравнение идёт В ПЛАВАЮЩЕЙ ТОЧКЕ, БЕЗ округления (fstp qword / fcomp qword)
   если rand() % 101 <= порог -> -2
   Таблицы направлений здесь НЕТ: стрела парируется с любой стороны.
4. УРОН (0x41C008…0x41C05C) — формула ТА ЖЕ, что в ближнем бою:
   сырое = max(0, сила*0.7 - броня)            const @0x450140
   урон  = ROUND( (( сырое + сила*0.3 ) / стойкость(+0xD1) + 1) * 16 )
                          @0x450148 = 0.3        @0x450150 = 16.0
   те же пороги: урон < hp -> вычесть и код (-1 если < 0x30, иначе 0);
   иначе код 1 (смерть)
5. ОТРАВА: жертва+0x52 += _DAT_00849704
6. ИЗНОС БРОНИ гнёзда 2…4, множитель 0.001 @0x450158
```

Три отличия выстрела от удара рукой:

1. **Проверки «смертельного удара» нет вовсе** — навык `+0xD4` в выстрел не входит.
2. **Точность проверяется внутри резолвера**, а не снаружи, как у ближнего
   (там это делает 0x41A9C8).
3. **Порог парирования не округляется.** У ближнего стоит `ROUND(ловкость×0.5)`,
   у стрелы — сравнение с `ловкость×0.1` как есть, в double.

Константы урона у выстрела лежат по другим адресам (`0x450140/48/50`), но
**значения в них те же**: 0.7, 0.3, 16.0. То есть формула урона одна на оба
вида боя, в exe просто две копии чисел.

## 8. Сила и точность удара — VA 0x41A9C8

```
FUN_0041A9C8(жертва, атакующий, гнездо):
    точность = 0x41ADD8(атакующий, 0, гнездо)
    если точность < rand() % 101 -> 0        промах, сила нулевая
    иначе -> 0x41A7D0(атакующий, порода_жертвы(+0x1A), гнездо)
```

### Точность — VA 0x41ADD8

```
тварь: ROUND(ST0)                                  [ОТКРЫТО]
человек:
    пересчитать (0x41C494)
    если +0xEE == 1 И есть метательное(+0x58) И param_2 != 0:
        точность = ROUND( 0x41B4CC(юнит,1) * (param_2 * _DAT_00450094)
                          / [0x45DB00 + класс*0x20] )
    иначе:
        точность = 0x41B4CC(юнит, гнездо)
    если +0x4A != 0: точность += +0xF8
    если +0x46 != 0: точность = (+0xFA & 4) ? точность + (+0x44) : (+0x44)
    зажать в [5, 0x5F]                            минимум 5, максимум 95
```

### Базовый навык по оружию — VA 0x41B4CC

| гнездо | предмет | навык |
|---|---|---|
| 1 (метательное) | нет | `+0xDC` |
| | группа 0x15 (боевой самострел) | `+0xDB` |
| | иначе | `+0xDC` |
| 0 (основная рука) | нет | `+0xD2` |
| | не оружие (`0x45DB0A == 0`) | `+0xD2` |
| | группа < 0x0D, подвид 0xA6 | `+0xD5` |
| | группа < 0x0D, подвид 0x9A | `+0xD6` |
| | группа < 0x0D, иначе | `+0xD7` |
| | группа >= 0x0D, подвид 0xA6 | `+0xD8` |
| | группа >= 0x0D, подвид 0x9A | `+0xD9` |
| | группа >= 0x0D, иначе | `+0xDA` |
| вторая рука | по тем же правилам, но | результат × `+0xD3` / 100 |

**Вторая рука бьёт с точностью, умноженной на навык «бой двумя руками».**

### Сила удара — VA 0x41A7D0

```
человек, предмет в гнезде отсутствует:
    _DAT_00849704 = 0                       отравы нет
    сила = ROUND(ST0 от +0xD0)              сила голыми руками   [ОТКРЫТО]
человек, предмет есть:
    _DAT_00849704 = [0x6F9576 + предмет*0x10] >> 16      отрава оружия
    если особый вид < 0 ИЛИ порода_жертвы != [0x4624FC + вид*0x20]:
        сила = [0x45DAF4 + класс*0x20]              обычный урон класса
    иначе:
        сила = [0x4624F8 + вид*0x20]                урон ПРОТИВ ЭТОЙ ПОРОДЫ
    сила += ROUND(ST0)                                            [ОТКРЫТО]
тварь:
    _DAT_00849704 = +0xF6                   отрава породы
    сила = ROUND(ST0)                                             [ОТКРЫТО]
затем для всех:
    если +0x44 != 0: сила = (+0xFA & 2) ? сила + (+0x42) : (+0x42)
    если сила < 0: сила = 0
```

**Таблица `0x4624F8` — оружие против конкретной породы.** Это отдельный
канон: у предмета есть «вид», и если порода жертвы совпала с
`[0x4624FC + вид*0x20]`, берётся особый урон вместо обычного.

### Броня жертвы — VA 0x41A414

```
пересчитать (0x41C494)
броня = +0xF4
для гнёзд +0x5A и +0x5C:  броня += [0x45DAF4 + класс*0x20]
для гнезда +0x5E: если вид предмета == 4 (щит): броня += то же
если +0x42 != 0: броня = (+0xFA & 1) ? броня + (+0x40) : (+0x40)
если броня < 0: броня = 0
```

**Щит считается бронёй только если его вид равен 4.**

## 9. Пересчёт характеристик — VA 0x41C494

Зовётся перед каждым расчётом и после каждого урона. Обнуляет накопители
`0x841CA4` (6 штук) и `0x8442F4`, затем проходит **два набора гнёзд**:
`+0x56…+0x5E` и `+0xB4…+0xBC`, и для каждого целого предмета
(`[0x6F957B] & 0x80 == 0`) разбирает битовые поля `[0x6F957A]`:

| маска | сдвиг | таблица | куда копится |
|---|---|---|---|
| `0x7000` | 12 | `0x45D524` | `0x841CBC` -> `+0x42` броня |
| `0x0E00` | 9 | `0x45D584` | `0x841CC0` -> `+0x44` точность |
| `0x01C0` | 6 | `0x45D5E4` | `0x841CA8` |
| `0x0038` | 3 | `0x45D644` | `0x841CB4` |
| `0x0007` | 0 | `0x45D6A4` | `0x841CB8` |

Затем:

* здоровье: `0x841CC8 *= 16`; если ноль — берётся `+0x4E`, иначе прибавка
  либо заменяет, либо складывается (`DAT_008442FD`), **потолок 0x640 = 1600**;
* шесть характеристик: `+0xCC…+0xD1` = база `+0xC0…+0xC5` плюс накопитель,
  отрицательные зажимаются в ноль;
* `+0xD1` никогда не остаётся нулём — если вышел ноль, ставится 1;
* `+0xFA` собирает три бита «прибавка складывается, а не заменяет».

## 10. Что осталось не разобранным

**ЗАКРЫТО дизассемблером 2026-08-10:** формула урона, порог парирования,
все девять констант, поле здоровья (`sub word ptr [жертва+0x4E]` не оставляет
сомнений: урон вычитается из `+0x4E`, а сравнивается с ним же через
`[+0x4C] >> 16`).

Осталось:

1. **Минус** в `0x412480` при вычислении ударного кадра.
2. **`_DAT_00849620` / `_DAT_0084951C`** — гейт в начале обоих резолверов.
   Из асма видно: если `[0x849620] != 0` И жертва == `[0x84951C]` (запись
   игрока), удар отменяется с кодом −2. Похоже на «бессмертие/пауза», но
   чем взводится `0x849620` — не прослежено.
3. **`+0x1A == 0x53`** в `0x416AC8` — что за порода бьёт в упор блоком 5.

Формула урона выстрела **закрыта** дизассемблером `0x41BF54` (раздел 7):
она совпадает с ближней до последней константы.

## 11. ЧАСТЬ II. Приоритеты, агро, дальности, погоня

### 11.1. Порядок решений внутри такта — VA 0x413894 и 0x4111E8

Рассудок юнита (`0x4111E8`) зовётся из главного такта **только при нулевой
младшей половине байта приказа** `+0x16`. Есть приказ — юнит его и делает,
ничего не выбирая. Это и есть верхний приоритет.

Внутри рассудка порядок такой:

```
0. ОТСЕВ: юнит с битом +0x1A & 0x80 или в блоке смерти (3, 11, 12) не думает вовсе.

ветка A — юнит НЕ помечен битом +0x19 & 0x40 («вольный»):
   1. свой отряд — отряд игрока (_DAT_0084950C)?
        а) 0x4107EC — есть ли враг ВПЛОТНУЮ -> начать ближний удар
        б) отряд в войне (+0x1D == 1) -> приказ 0x21
        в) 0x410684 — сюжетный подход «подойди и заговори»
        г) бит +0x16 & 0x10 -> 0x41209C
   2. чужой отряд, отряд в войне (+0x1D == 1):
        порода 'T'/'U' -> 0x4126A8 (движение по прямоугольнику отряда)
        иначе: поднять боевую стойку (+0x19 |= 4) и обнажить оружие,
               а если она уже поднята — приказ 0x21
   3. чужой отряд, войны нет, но стойка боевая -> СНЯТЬ стойку (+0x19 ^= 4),
      поставить блок 0x10 (мирная стойка)
   4. иначе: 0x410684, затем работа:
        `+0xE3 >> 24 < 0` (нет наряда) -> держаться прямоугольника отряда
        (0x4126A8), а если уже внутри — просто стоять
        иначе -> 0x412C0C, выбор работы

ветка B — юнит помечен +0x19 & 0x40:
   1. 0x4107EC — враг вплотную
   2. отряд в войне: если режим стрельбы (+0xEE == 1) ИЛИ нет бита +0x19 & 0x20,
      то 0x411F28 — ИСКАТЬ ЦЕЛЬ ДЛЯ ВЫСТРЕЛА
   3. иначе 0x410684
```

Отсюда закон: **ближний бой вплотную сильнее всего остального**, потом война
отряда, потом сюжет, и только потом работа.

### 11.2. Агро отряда: война объявляется ПО ТЕРРИТОРИИ — VA 0x415B20

У отряда есть прямоугольник (строки `+0x0C…+0x10`, столбцы `+0x14…+0x16`) и
байт реакций `+0x1F`:

| бит `+0x1F` | на кого реагирует |
|---|---|
| `0x01` | на отряд ИГРОКА |
| `0x08` | вместе с `0x01`: только если игрок уже воюет |
| `0x04` | на любые другие отряды того же мира с битом `0x04` |
| `0x80` | на отряд поселения (`_DAT_00849538`) |

Проход отряда (раз в 16 мировых тактов, `0x41C944`):

```
если отряд НЕ в войне:
    перебрать чужие живые юниты; первый, чья КЛЕТКА попала в прямоугольник,
    -> объявить войну его отряду (0x4159DC)
если отряд в войне (+0x1D):
    проверить, остался ли хоть один контакт: для каждой пары «наш × их»
    0x410784 — |Δx| < 0x348 И |Δy| < 0x348 в мировых пикселях
    контактов нет -> война снята, ВСЕ юниты отряда сброшены в покой (0x416E24)
```

**0x348 = 840 пикселей** по каждой оси — это и есть радиус, на котором война
держится. Больше — и отряд успокаивается.

Объявление войны (`0x4159DC`):

```
требуется +0x1F & 0x4F != 0
+0x1F |= (реакции вражеского отряда) & 0x4F      война заразна
+0x06 = номер врага, +0x1D = 1
если отряд не игрока и у него бит +0x1E & 0x80 (поселение):
    поднять тревогу в поселении: +0x49C |= 0x15 (если враг — игрок) иначе |= 5
ВСЕ юниты отряда сбрасываются в покой (0x416E24), чтобы передумать
```

### 11.3. Агро юнита в ближнем бою: ТОЛЬКО СОСЕДНИЕ КЛЕТКИ — VA 0x4107EC

```
для восьми направлений (0x441344 даёт соседнюю клетку):
    занявший = карта[0x5662BC + клетка] & 0xFFF
    пропустить пустую (0) и 0xFFF
    занявший должен быть жив и из ДРУГОГО отряда (+0x1B)
    (а) его приказ (+0x1E & 0xF) == 1 И его цель == мы
        -> ВЫБРАТЬ НЕМЕДЛЕННО, перебор прекращается
    (б) иначе, если его отряд в войне (0x71E589) И воюет ИМЕННО с нашим
        -> запомнить кандидатом, перебор продолжается
выбранный: +0x10 = номер, +0x13/+0x15 = его клетка, +0x16 = 1, путь очищен,
затем 0x416B50 — начать ближний удар
```

Три закона отсюда:

1. **Ближняя цель ищется только среди восьми соседей.** Никакого «увидел за
   десять клеток и побежал» на этом уровне нет.
2. **Тот, кто уже бьёт нас, имеет безусловный приоритет** — он выбирается
   сразу, остальные направления даже не смотрятся.
3. Из остальных побеждает **последний найденный**, а не ближайший: перебор
   идёт по направлениям и перезаписывает кандидата.

### 11.4. Агро стрелка: ПЕРВЫЙ ПО СПИСКУ, а не ближайший — VA 0x411F28

```
требуется: метательное в +0x58 != 0 И +0x50 != 0 (боезапас)
взять вражеский отряд по +0x1B, пройти его список юнитов ПО ПОРЯДКУ:
    юнит жив?
    0x414AF8(стрелок, его строка, его столбец, его номер) > 0?
        -> цель +0x10, клетка +0x13/+0x15, приказ +0x16 = 1,
           0x416AC8 — анимация выстрела, ВЫЙТИ
```

Перебор прекращается на первом, по кому выстрел проходит. **Ни расстояние, ни
здоровье, ни опасность цели не учитываются.**

### 11.5. Дальности — сводка

| что | значение | откуда |
|---|---|---|
| ближний бой | ровно 1 клетка (только соседи) | 0x4107EC |
| минимум для выстрела | **3 клетки**, ближе — отказ | 0x414AF8 |
| максимум для выстрела | `[0x45DAFE + класс*0x20] >> 16` | 0x414AF8 |
| максимум для твари | **0x28 = 40 клеток** | 0x414AF8 |
| трассировка | 8 подшагов на клетку, стоп на бите `0x40` | 0x414AF8 |
| радиус удержания войны | **0x348 = 840 пикселей** по каждой оси | 0x410784 |
| прямоугольник отряда | `+0x0C…+0x16` в клетках | 0x415B20 |

### 11.6. Погоня и движение — VA 0x416574

```
FUN_00416574(юнит, строка, столбец, вид_приказа):
    +0x13/+0x15 = цель, +0x16 = вид (младшая половина)
    путь очищается (+0x01 = 0xFF)
    СВОЯ занятость снимается с карты, зовётся поиск пути 0x441441,
    занятость возвращается            <- иначе юнит спотыкается о самого себя
    путь не найден:
        вид == 1 (бой) И 0x4107EC нашёл врага вплотную -> 1
        иначе -> сброс в покой (0x416E24), вернуть 0
    путь найден:
        вид == 1 (бой) И скорость >= 0 И не тварь -> ПОДНЯТЬ БИТ БЕГА +0x19 |= 0x80
        вид == 2 -> отрезать последний шаг пути
        блок хода выбирается двумя битами +0x19:
            бег 0x80 | стойка 0x04 -> блок
             нет   |  нет          -> 0x11  мирный шаг
             нет   |  есть         -> 0x01  боевой шаг
             есть  |  нет          -> 0x13  мирный бег
             есть  |  есть         -> 0x07  боевой бег
```

**Погоня за врагом всегда бегом** — бит бега поднимается безусловно для
приказа вида 1. Тот же выбор блока по двум битам повторяет `0x416C84`.

### 11.7. Как ближний бой начинается на самом деле — VA 0x416740 → 0x415090

Отдельной команды «атакуй» у движка нет. Юнит идёт В САМУ КЛЕТКУ цели, и на
попытке шагнуть в неё срабатывает:

```
0x416740, ветка перехода в следующую клетку:
    клетка свободна -> просто переехать
    клетка занята   -> 0x415090(юнит, строка, столбец):
        приказ юнита должен быть вида 1
        занявший != 0xFFF, жив
        занявший из ДРУГОГО отряда И он ровно наша цель (+0x0E)
        -> вернуть его номер
    номер получен -> +0x10 = он, +0x13/+0x15 = его клетка, путь оборван,
       FUN_00416B50 — УДАР
    номер не получен -> приказ снят (+0x16 &= 0xF0), путь оборван
```

То есть «догнал и ударил» — это одно и то же движение: шаг в занятую клетку
превращается в удар, а если занявший не наша цель, приказ просто снимается.

### 11.8. Защита — что именно защищает

| механизм | где | закон |
|---|---|---|
| парирование ближнего | 0x41C194 | таблица 8×8 `0x459F94` по паре направлений; **со спины не парируется** |
| парирование стрелы | 0x41BF54 | без таблицы направлений, порог `+0xCD × const 0x450138` |
| броня | 0x41A414 | `+0xF4` + классы предметов в `+0x5A`, `+0x5C`, и `+0x5E` только если его вид == 4 (щит) |
| прибавка брони | 0x41A414 | `+0x40` при `+0x42 != 0`; бит `+0xFA & 1` решает, складывается или ЗАМЕНЯЕТ |
| порог прерывания | 0x41C194 | урон < `0x30` — жертва не вздрагивает |
| износ брони | 0x41C194 | доля `сила/броня`, потолок 1.0; прочность до нуля — предмет ломается |

**Щит не даёт брони, если его вид не равен 4.** И броня, и точность, и сила
могут не складываться с прибавкой, а быть ею заменены — это решают три бита
в `+0xFA`, которые выставляет пересчёт `0x41C494`.

## 9б. ОКРУГЛЕНИЕ: в бою движок УСЕКАЕТ, а не округляет

`FUN_00442BF0` — не «округление», как показывает Ghidra, а подмена режима
сопроцессора:

```
00442bf2  fnstcw [esp]                 сохранить контрольное слово
00442bf9  mov byte ptr [esp+1], 0x1F   старший байт CW = 0x1F
00442bfe  fldcw  [esp]
00442c01  frndint                      округлить по этому режиму
00442c03  fldcw  [esp+4]               вернуть как было
```

`0x1F` в старшем байте — это `PC = 11` (расширенная точность) и **`RC = 11`,
режим «к нулю»**. `frndint` в нём отсекает дробную часть. После него значение
уже целое, и следующий `fistp` ничего не меняет.

Отсюда правило, различающее два случая:

| как в движке | что это |
|---|---|
| просто `fistp` | к ближайшему, ровно половина — к ЧЁТНОМУ (`round.js`) |
| `call 0x442BF0` → `fistp` | **усечение к нулю** |

Места боя, проверенные дизассемблером:

| расчёт | адрес | режим |
|---|---|---|
| порог парирования ближнего | 0x41C209 | усечение |
| урон ближнего боя | 0x41C2DC | усечение |
| урон выстрела | 0x41C057 | усечение |
| порог парирования стрелы | 0x41BFC9 | **не округляется вовсе**, сравнение в double |
| сила удара, все три ветки | 0x41A82D, 0x41A930, 0x41A96F | усечение |
| точность зверя | 0x41AE16 | усечение |
| точность со штрафом за дальность | 0x41AEA7 | усечение |
| «смертельный удар», навык/10 | 0x41C29F | `idiv`, целочисленное |
| навык второй руки, ×навык/100 | 0x41B4CC | целочисленное |

## 9в. Формулы, вскрытые дизассемблером сверх резолверов

**Слагаемое силы — VA 0x41A7D0.** Три ветки, одна форма:

```
слагаемое = ТРУНК( характеристика * K * здоровье(+0x4E) * 0.0625 )
```

| ветка | K | адрес константы |
|---|---|---|
| без оружия | **0.04** | 0x450054 |
| с оружием | **0.04** | 0x450064 |
| тварь | **0.02** | 0x450074 |

Множитель `0.0625 = 1/16` одинаков во всех трёх (0x45005C, 0x45006C, 0x45007C).
**Сила удара зависит от ТЕКУЩЕГО здоровья бьющего** — раненый бьёт слабее.

**Точность зверя — VA 0x41ADFB:**

```
точность = ТРУНК( 100 - (100 - ловкость * 0.5) * 0.5 )
```
константы 0x450084 = 0.5, 0x45008C = 100.0.

**Штраф точности за дальность — VA 0x41AE7F:**

```
точность = ТРУНК( навык(0x41B4CC) - расстояние * 0.3 / дальность_класса )
```
константа 0x450094 = 0.3, дальность берётся из поля `+0x10` класса предмета.

## 11а. Сверка порта с канонной формулой

`knyaz2/web/static/combat.js`:

```js
const ARMOUR_PART = 0.7; const DIRECT_PART = 0.3; const DAMAGE_SCALE = 16;
const PARRY_SCALE = 0.1;
const raw = Math.max(0, strength * ARMOUR_PART - armour) + strength * DIRECT_PART;
const damage = Math.round((raw / Math.max(1, defenderStats.toughness) + 1) * DAMAGE_SCALE);
```

Команда в команду совпадает с `0x41C244…0x41C2E1`, и все четыре константы
равны прочитанным из дампа. **Формула урона и порог парирования в порту
каноничны.** Единственное отличие — `Math.max(1, toughness)`: движок делит на
`+0xD1` без защиты от нуля, но нуля там и не бывает, потому что `0x41C494`
сам подставляет единицу, если пересчёт дал ноль.

Отсюда важное следствие для спора о реакции на удар: **19 урона голым кулаком
— это канонное число**, а не наша ошибка масштаба. Порог прерывания `0x30`
безоружным героем недостижим по устройству оригинала.

### Где порт округляет не тем способом

Все пять мест сверены дизассемблером (раздел 9б): движок там усекает, порт —
округляет. Расхождение до единицы в каждом.

| файл, строка | сейчас | по движку |
|---|---|---|
| `combat.js:95` точность зверя | `Math.round` | `Math.trunc` |
| `combat.js:138` штраф за дальность | `Math.round` | `Math.trunc` |
| `combat.js:306` слагаемое силы | `roundHalfEven` | `Math.trunc` |
| `combat.js:458` порог парирования ближнего | `roundHalfEven` | `Math.trunc` |
| `combat.js:481` урон | `Math.round` | `Math.trunc` |

`roundHalfEven` сам по себе не ошибка — он верен там, где движок делает голый
`fistp` (цены, зелья, сроки работ). Ошибка в том, что в бою перед `fistp`
стоит `call 0x442BF0`, и режим там другой.

Проверить стоит и обратное: не стоит ли `Math.trunc` там, где движок как раз
округляет к чётному. В бою таких мест не найдено, за пределами боя не смотрел.

## 11б. Что внесено в порт 2026-08-10

**Сброс режима стрельбы при сближении** (`units.js`, ветка выбора цели). По
`0x416B50`: движок, начиная ближний удар, пишет `+0xEE = 0` безусловно. Порог
взят тот же, что запрещает выстрел, — `ranged_min_cells`.

Замер на карте 23, Асбад с охотничьим самострелом, герой вплотную, десять
секунд мировых тактов:

| | до правки | после |
|---|---|---|
| позы | `walk` 26, `stand` 274 | `stand` 111, **`attack_shield` 189** |
| разных картинок на холсте | — | **48** |
| здоровье героя | 361 → 361 | **361 → 85** |

**Пять округлений** переведены на `Math.trunc` (строки 95, 138, 306, 458, 481
в `combat.js`), импорт `roundHalfEven` оттуда убран — в бою он больше не
нужен. Тесты: 401 passed.

**Радиус обзора убран совсем.** Поле `unit.sight` и условие
`distance <= unit.sight` удалены из `units.js`: в движке такого предела нет
ни в одной из разобранных функций. Основание:

* `0x410010` — юнит воюющего отряда идёт к цели **без всякого предела
  расстояния**; единственный гейт наверху — отряд должен быть в войне
  (`[0x71E589] == 1`), иначе `0x416E24` сбрасывает юнита в покой;
* `0x41F234` — цель это ближайший живой враг, счётчик стартует с `0x7FFFFFFF`,
  верхней границы нет;
* начало и конец боя решает отряд: зона (`0x415B20`) и 840 пикселей
  (`0x410784`) — обе половины в порту уже были.

Проверено на карте 23:

| проверка | результат |
|---|---|
| мирно, 10 секунд | 0 отрядов в войне, все 20 юнитов `stand`, герой цел |
| герой ударил стражника | 1 отряд в войне, у одного юнита появилась цель, пошёл к герою |
| погоня дальше прежних 10 клеток | 16 → 11 клеток за пять секунд — работает |
| выход из боя | при идущих мировых тактах отряд выходит, юнит возвращается в `stand` |

**Пересчёт маршрута погони — повод канонный, частота под бюджетом.** Движок
(`0x410010`) правит курс каждому преследователю каждый мировой такт: ставит
путь и тут же гасит младшую половину байта приказа, поэтому рассудок
отрабатывает снова через 78 мс. Буквально это не переносится: замер на карте
23 (сетка 7556 клеток) — один поиск волной 2.4…3.4 мс, сорок врагов дали бы
512 поисков в секунду, полторы секунды счёта на секунду игры. У авторов игры
волна была дешевле и считалась у игрока, у нас это же ляжет на общий сервер.

Сделано три вещи, ни одна не трогает канон:

1. **Повод** — цель сменила клетку (`unit.chaseAt` помнит, на какую строился
   путь), а не «прежний путь кончился».
2. **Бюджет** — `REPLAN_PER_TICK = 2` поиска на МИРОВОЙ такт (не на кадр
   браузера, иначе на 144 Гц цена втрое). Кому не хватило — идёт по прежнему
   маршруту и пробует на следующем такте. Застрявший (пути нет вовсе) бюджет
   не тратит: он стоит, ему важнее.
3. **Обрезка хвоста вместо поиска** — если новая клетка цели уже лежит на
   нашем маршруте, путь просто укорачивается. Проход по направлениям стоит
   пятнадцать сложений против 2.4 мс волной.
4. **Активная зона** — за 840 пикселей (`KEEP_RANGE`, тот же порог, которым
   `0x410784` держит войну) курс не обновляется вовсе: отряд там и так
   вот-вот выйдет из боя.

**Сверка трёх политик на одном сценарии.** Карта 23, чистая загрузка перед
каждым прогоном, война поднимается ударом, герой ходит проходом 400 пикселей
туда и обратно — клетка цели меняется всё время, но погоня не рвётся.
Шестьдесят секунд игры, 1800 итераций:

| политика | обновлений маршрута | `unitsTick` мс/с | худший кадр | отставание маршрута |
|---|---|---|---|---|
| **A — повод по клетке + бюджет + обрезка + зона** | 29 (0.48/с) | **13.0** | **23.1 мс** | 0.61 клетки |
| B — то же, но без обрезки и без зоны | 26 (0.43/с) | 21.3 | 55.4 мс | 0.64 клетки |
| C — прежнее: только когда путь кончился | 13 (0.22/с) | 17.5 | 46.7 мс | 0.57 клетки |

Итог неочевидный и потому важный: **A обновляет маршрут вдвое чаще C, но
стоит дешевле** — 13.0 против 17.5 мс на секунду игры, и худший кадр вдвое
короче. Разгадка в обрезке хвоста: у A большая часть обновлений не стоит
поиска вовсе, это укорачивание уже готового пути. B показывает ту же политику
без обрезки — и сразу становится самой дорогой из трёх.

Отставание маршрута от цели во всех трёх около полуклетки: на таком проходе
прежняя политика не успевала отстать сильно. Разница в отставании вылезает на
длинной погоне, где C уводит юнита в точку, покинутую десять секунд назад.

Оговорка о замере: в сценарии один преследователь (отряд Асбада одиночный),
поэтому числа показывают цену политики, а не нагрузку от толпы. Оценка для
сорока врагов — расчётная: бюджет не даёт больше двух поисков за такт
независимо от их числа.

Главное свойство для сервера: **цена не растёт с толпой.** Сорок врагов или
пять — поисков всё равно не больше двух за такт, просто каждый обновляет курс
реже. Крутится одной константой.

**Соседство — не «расстояние единица».** Самая дорогая находка дня, и её
никакие тесты не ловили. Сетка изометрическая, строки идут вполовину, поэтому
сосед с СЕВЕРА отличается на ДВЕ строки: `heroNeighbor(9,27, 2)` даёт (7,27).
Мерка движка `0x43B670` (наш `cellRange`) для этой пары честно возвращает
двойку — она меряет клетки, а не соседство.

Ближний бой стоял на `distance <= actorReach`, то есть на этой мерке. Значит
юнит, вставший строго севернее или южнее цели, удара не начинал (2 > 1) и
шагнуть в занятую клетку не мог — и замирал НАВСЕГДА. Стоящие слева-справа
(разница по столбцам единица) дрались нормально, поэтому со стороны это
выглядело как «некоторые враги застыли и не дерутся».

Движок так не считает вовсе: ближнюю цель он берёт ПЕРЕБОРОМ ВОСЬМИ
НАПРАВЛЕНИЙ (`0x4107EC` зовёт `0x441344` на каждое), а дальность в клетках
нужна ему только для стрельбы (`0x414AF8`). Введён `withinReach`: рукой —
по соседству, метательным — по дальности. Тем же лечится и герой.

Замер на карте 3, один преследователь, 30 секунд игры:

| | до | после |
|---|---|---|
| застывших с целью | **1 из 1** | **0** |
| тактов в позе атаки | 0 | **252** |
| здоровье героя | 1254 | **0** — юнит его убил |

**Герой сам доходит до врага.** `combatTick` вёл его в точку за 52 пикселя до
цели с обоснованием «в саму клетку врага маршрут не строится в принципе». Это
неверно: планировщик занятую клетку принимает, если ему передать занявшего, а
`heroOrderTo` уже кладёт туда `hero.orderTarget`. Так же ходит движок: приказ
`0x61` пишет номер цели в `+0x10`, `0x416574` строит путь В КЛЕТКУ ЦЕЛИ,
`0x441441` сверяет занявшего с этим полем, а шаг в занятую клетку `0x415090`
переводит в удар `0x416B50`.

Замер на карте 23, герой (121,39), Асбад (121,36):

| | до правки | после |
|---|---|---|
| путь после приказа | **0 шагов** | **10 шагов** |
| сближение | стоит на месте | 7 клеток → 1 за 4 секунды |
| урон цели за 20 секунд | 0 | 1565 → 1137 хп |

**Тем же заходом исправлены три подхода в `orderAt`**: разговор со своим по
Ctrl, обыск лежачего и разговор с чужим. Все три вели героя в точку
`цель.y + 40` — на сорок пикселей ниже собеседника, — и она бывает
непроходимой. В движке все они идут тем же приказом с номером цели
(`+0x16 = 0x22`, VA 0x421690:280), то есть В КЛЕТКУ. Остановка выходит сама
собой: шаг в занятую клетку разбирает `0x415090`, и для приказа не боевого
вида он возвращает ноль — приказ снимается, юнит встаёт рядом.

Замер разговора, карта 23:

| | до правки | после |
|---|---|---|
| путь после приказа | **0** | **10 шагов** |
| подход | стоит | 7 клеток → 1 |
| остановка | — | вплотную, поза `stand` |
| диалог | не начинался | **начался** |

Оговорка о методике: первый прогон показал, будто отряд не выходит из боя на
1119 пикселях. Это была ошибка замера — `clockAdvance(seconds)` принимает
АБСОЛЮТНЫЕ секунды, а харнесс передавал `dt`, отчего `clock.elapsed` оставался
нулём и отрядный такт (раз в 16 мировых тактов) не отрабатывал ни разу.
С верным вызовом бой снимается штатно.

## 12. Немедленное следствие для порта

`0x416B50` пишет `+0xEE = 0` при входе в ближний удар. В порту
(`knyaz2/web/static/units.js`) `rangedMode` не сбрасывается никогда, поэтому
юнит с метательным оружием, к которому подошли вплотную, попадает в мёртвую
зону: стрелять нельзя (ближе трёх клеток, VA 0x414AF8), а на руку он не
переходит. Замер на карте 23: Асбад с охотничьим самострелом стоит вплотную
к герою десять секунд, `canStrike` возвращает false, поз атаки нет ни одной.

Ещё три расхождения, которые видны из части II. Они НЕ проверены на порту —
это список к проверке, а не приговор:

1. **Радиуса обзора в движке не найдено вовсе.** Ближняя цель берётся из
   восьми соседних клеток (0x4107EC), война отряда объявляется попаданием
   чужого юнита в ПРЯМОУГОЛЬНИК отряда (0x415B20), удержание войны считается
   расстоянием 840 пикселей (0x410784). Поля «сколько клеток вижу» ни в одной
   из разобранных функций не встретилось. В порту же условие боя стоит на
   `distance <= unit.sight`. **Проверено: это наша выдумка.** В
   `knyaz2/content/builder.py` поле `sight_cells` зашито числом `10`
   (строки 742, 2389, 2435) и из данных игры не читается ни разу. То есть
   порт ввёл радиус обзора, которого у движка нет, и бой у нас начинается по
   правилу, которого в оригинале не существует.
2. **Стрелок выбирает первого по списку отряда, а не ближайшего** (0x411F28).
3. **Ближний бой начинается шагом в занятую клетку**, а не отдельным решением
   «атаковать» (0x416740 → 0x415090 → 0x416B50).

## 13. Открытые вопросы части II

1. `+0x50` — что за поле, без которого стрелок не ищет цель (боезапас?).
2. `+0x19 & 0x40` — по этому биту рассудок расходится на две большие ветки;
   что он значит, из прочитанного не видно.
3. `+0x19 & 0x20` — участвует в разрешении на стрельбу.
4. Породы `'T'`, `'U'` (0x54, 0x55) в рассудке и `0x53` в 0x416AC8.
5. Не читаны: `0x4126A8` (движение по прямоугольнику), `0x41209C`,
   `0x410684` (сюжетный подход), `0x412FF4`, `0x4292B0`, `0x416CF0`,
   `0x429B2C` (постановка кадров), `0x41B044` и `0x413110` (награда и опыт).
6. Таблица работ отряда `0x71E56C + …` — разобрана только та часть, что
   участвует в выборе наряда (0x412C0C).
