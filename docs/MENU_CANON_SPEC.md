# Меню, новая игра и создание героя: спецификация по оригиналу

Снято с `konung2.exe` (декомпилят `engine/decompiled/functions/*.c` и прямой
дизассемблер). Каждое утверждение сопровождается адресом. Ничего не
додумано: где данных не хватает, это сказано явным пунктом «не выяснено».

Спецификация писалась после того, как первая попытка сделать эти экраны «по
смыслу» дала неработающий результат. Всё, что раньше было сделано на глаз,
считается недействительным и заменяется описанным здесь.

## 1. Состояния экрана

Экран игры выбирается числом `0x849574`. Диспетчер — `switch` в главном
цикле (`0x438A00`, строка 149 декомпилята). Известные состояния:

| Значение | Экран | Разбор ввода | Отрисовка |
|---:|---|---|---|
| 0 | игра | `0x437FF8` | мировой такт: `0x41FDD0`, `0x413894`, `0x415948`, `0x41C944`, `0x436A44` |
| 1 | меню | таблица `0x46155C` | `0x430CA4` |
| 2 | создание героя | таблица `0x461D44` → `0x4388E4` | `0x430DF4` |
| 4 | загрузить игру | таблица `0x462304` | `0x43259C(0)` |
| 5 | сохранить игру | таблица `0x462304` | `0x43259C(1)` |
| 6 | настройки | — | `0x4326A8` |
| 7 | переход между экранами | — | — |
| 8, 10 | не выяснено | — | — |

Попадание мыши считает `0x43B5F8(x, y, таблица)`: массив прямоугольников
`{x1, y1, x2, y2}` по четыре int, конец — `-1` в первом поле; возвращается
НОМЕР прямоугольника или `-1`. Номер и есть код действия.

## 2. Клавиша ESC

`0x438A00`, ветка кода `0x1B`, `switch` по состоянию:

- **состояние 0 (игра):** сперва `FUN_0042944c(1)` — отмена переноса вещи.
  Затем, если открыт какой-то экран (`0x8495F0` не ноль), закрывается ОН и
  игра продолжается; и только если не открыто ничего — состояние 7 и уход в
  меню.
- **состояние 1 (меню):** возврат в игру (состояние 0) с перезагрузкой
  интерфейса `0x43026C`, `0x4308E0`, `0x42958C`. Если `0x8495C8 == -1` —
  вместо этого состояние 10 и `0x422CCC`.
- **состояния 2, 4, 5, 6:** возврат в меню (состояние 7 с признаком, откуда
  пришли: `0x8496B8` = 0, 2, 5, 6 соответственно).

## 3. Меню (состояние 1)

Шесть пунктов, прямоугольники из `0x46155C`:

| № | Прямоугольник | Пункт | Что делает |
|---:|---|---|---|
| 0 | x 358…660, y 228…255 | Продолжить игру | состояние 0, перезагрузка интерфейса |
| 1 | x 358…670, y 278…305 | Сохранить игру | состояние 5, `0x430394`, `0x43259C(1)` |
| 2 | x 358…660, y 328…355 | Загрузить игру | состояние 4, `0x430394`, `0x43259C(0)` |
| 3 | x 368…650, y 378…405 | Новая игра | состояние 2, см. ниже |
| 4 | x 378…640, y 428…455 | Настройки | состояние 6, `0x4326A8` |
| 5 | x 390…630, y 478…505 | не выяснено (вероятно выход) | — |

**Первые два пункта гасятся, пока игра не идёт:**
`if ((_DAT_008495C8 == 0) && (номер < 2)) номер = -1;` — то есть «Продолжить»
и «Сохранить» недоступны до начала игры. Это канон, а не наше удобство.

Щелчок по пункту озвучивается `FUN_0042d660(6, 0, 0, 0)` — слот звука 6.

## 4. «Новая игра» (пункт 3)

Последовательность из `0x438A00`, case 3:

1. `0x43012C()` — подготовка экрана.
2. Байт героя `+0x3F` ← 2.
3. **`0x4387CC(2)`** — загрузка архетипа номер ДВА (см. § 5). То есть экран
   создания открывается не на нулевом герое, а на втором.
4. Байт `+0xEE` ← 0 (режим оружия — ближний бой).
5. Слоты снаряжения: `+0x16` ← 5, `+0x5A` ← 4, `+0x17` ← 1, `+0x5E` ← 8,
   `+0x18` ← 5.
6. `0x416740(герой, 0)` — поза «стойка».
7. Записи предметов `0x6F957C`…`0x6F961F` заполняются парами
   «вид, класс»: (2, 0xBE), (2, 0xBD), (0, 0x68), (1, 0x73), (0, 0x65),
   (3, 0x83), (3, 0xC7), (3, 0xA5), (1, 0x76), (0, 0x6A), (0, 0x6C).
   Это витрина снаряжения экрана создания.
8. `0x430DF4(0)` — отрисовка экрана создания.
9. `0x42D13C(0x1D)` — музыка, трек 29.

## 5. Загрузка архетипа (`0x4387CC(номер)`)

```
имя файла = "GAME." + номер
открыть; FUN_00443211(файл, 0x46322, 0);        // к массиву юнитов
FUN_00442fdc(файл, 0x84951C, 0x100);            // ЗАПИСЬ ГЕРОЯ целиком
закрыть
FUN_00442c10(0x8442D8, 0, 6);                   // счётчики характеристик
FUN_00442c10(0x8442E0, 0, 0x14);                // счётчики навыков
FUN_00442c10(0x84951C + 0x58, 0, 10);           // десять байт гнёзд
байт +0x18 ← 6                                  // направление
байт +0x19 ← 4
```

Архетип — это МИР: `GAME.0`…`GAME.5`. Стартовая карта каждого мира лежит в
записи отряда игрока (`+0x08` таблицы отрядов): 0 → 33, 1 → 19, 2 → 23,
3 → 37, 4 → 45, 5 → 1.

## 6. Экран создания героя (состояние 2)

Отрисовка `0x430DF4(нажатая_стрелка)`, ввод — таблица `0x461D44`, обработка
номера — `0x4388E4(номер)`.

### 6.1. Прямоугольники и коды

Всего в таблице **91 прямоугольник**:

| Коды | Прямоугольники | Смысл |
|---|---|---|
| 0…5 | шесть портретов: x 104…183, 266…346, 429…509; y 109…200 и 244…335 | выбор архетипа |
| 6…11 | x 930…960, y 131…248 шагом 20 | «+» характеристики |
| 12…17 | x 965…990, y 131…248 шагом 20 | «−» характеристики |
| 18…37 | x 930…960, y 346…743 шагом 20 | «+» навыка |
| 38…57 (0x26…0x39) | x 965…990, y 346…743 шагом 20 | «−» навыка |
| 86 (0x56) | x 806…999, y 74…93 | область свободного опыта, назначение не выяснено |
| **87 (0x57)** | x 100…243, y 699…717 | **«Играть»**: состояние ← 8, экран перерисовывается с нажатой кнопкой (`0x430DF4(1)`) |
| **88 (0x58)** | x 380…520, y 699…717 | **«Отмена»**: состояние ← 7 с признаком 2 (назад в меню), `0x430DF4(-1)` |

Порядок портретов в таблице: 0 — левый нижний, 1 — левый верхний,
2 — средний нижний, 3 — средний верхний, 4 — правый нижний, 5 — правый
верхний.

**Выбор героя — щелчок по портрету, не стрелки.** Каждый случай зовёт
`0x4387CC(N)`, ставит те же слоты снаряжения, `0x416740(герой, 0)`,
`0x430DF4(0)` и `0x431548(N)`.

### 6.2. Что нарисовано (`0x430DF4`)

| Элемент | Источник |
|---|---|
| фон на весь экран | спрайт `0x6B35C0` |
| картинка выбранного героя | `0x6B35C8 + вид*8`, позиция — первые два поля прямоугольника `0x461D44 + вид*0x10`; вид = байт героя `+0xFC` |
| «Свободный опыт» | подпись `0x46141C`, значение — слово `+0x48` |
| шесть характеристик | имена `0x46144C` (шаг 8), значения — БАЗОВЫЕ байты `+0xC0+i`, y с 130 шагом 20 |
| двадцать навыков | продолжение того же массива имён, значения `+0xD2+i`, y с 345 шагом 20 |
| «Максимальный вес» | подпись `0x46154C`, значение `((+0xD1)*1000/3 + 20000) * 0.001`, формат `%4.1f`, y 270 |
| «Максимальный отряд» | подпись `0x461554`, значение `min(9, (+0xCC >> 4) + 1)`, y 290 |
| портрет героя | герой рисуется в буфер 160×160 (`0x425DB4`) и блитится в точку `0x4622D4` / `0x4622D8` = **(547, 75)** |
| две кнопки | «Играть» в (100, 699), «Отмена» в (380, 699); спрайты `0x1FE`/`0x1FF` и `0x1FC`/`0x1FD` — отжатый и нажатый |
| описание героя | `0x431548(номер)` печатает строку `0x462CDC[номер]` с переносом по ширине (`0x42FCAC`, x от `0x4622E4` до `0x4622EC`, y `0x4622E8`) |

**Это КНОПКИ, а не стрелки.** Параметр `0x430DF4` показывает, какая из двух
нажата: 1 — «Играть», −1 — «Отмена», 0 — обе отжаты. Переключение архетипа
идёт щелчком по портрету, стрелок на экране нет вовсе.

### 6.2.1. Имена и описания шестерых

Строки лежат в `0x462CDC` (шесть указателей). Это не «Герой 1…6», а
названные персонажи со своей историей:

| Мир | Карта | Кто |
|---:|---:|---|
| 0 | 33 Борье | **Ратибор**, князь деревни Борье, старший из потомков Титанов |
| 1 | 19 Чёрный Бор | **Велиславна**, княгиня, последняя из рода князей Чёрного Бора |
| 2 | 23 | **Эйнар**, викинг охраны торгового корабля |
| 3 | 37 | **Хельга**, знахарка Нижнего лагеря викингов |
| 4 | 45 | **Александр**, византиец, ученик волхва |
| 5 | 1 | **Анастасия**, византийка, лучница стражи Летающего Острова |

Отсюда же видно, что **Ратибор начинает в Борье, а не в Чёрном Бору** —
Чёрный Бор принадлежит Велиславне.

Выравнивание: имя правым краем по x = 870, значение по x = 920, «+» по 950,
«−» по 970.

**Цвет значения:** обычная палитра `0x5EE348`, если счётчик прибавок этой
строки нулевой; палитра `0x5F744A`, если игрок сюда добавил.

### 6.3. Правила прибавок

- «+» характеристики: `0x4131FC` возвращает цену 2, если замок прокачки
  `+0x4A` нулевой, свободного опыта не меньше двух и база `+0xC0+i` меньше
  150. Растут база и текущая, опыт тратится, счётчик `0x8442D8[i]` растёт.
- «−» характеристики: только пока счётчик не ноль. База и текущая падают,
  возвращается 2 опыта, счётчик уменьшается, затем `0x437C48`.
- «+» навыка: `0x413268` возвращает 1, если замок нулевой, опыт не ноль,
  навык меньше 100 и меньше предела, считаемого от характеристик.
- «−» навыка: только пока счётчик не ноль; навык падает, возвращается 1.
- **`0x437C48` — каскадный возврат.** После понижения характеристики для
  каждого из двадцати навыков: пока счётчик не ноль, вернуть 1 опыта и
  опустить навык; как только навык снова можно поднять — откатить последний
  шаг и перейти к следующему навыку.

## 6.5. NEWHERO.RES — РАЗОБРАН

Формат сходится до последнего байта файла (1 671 328):

```
блок:  u32 размер                 = 4 + 2*h + сумма длин строк
       u16 w, u16 h
       u16 длины_строк[h]
       RLE:  байт 0        конец строки
             байт & 0x80   пропуск (байт & 0x7F) прозрачных пикселей
             иначе         серия из n пикселей, следом 2*n байт X1R5G5B5
```

**Пиксели шестнадцатибитные, а не индексы палитры** — потому палитры в файле
и нет. Доказательство арифметикой: строка фона занимает 2058 байт, это ровно
1024 пикселя по два байта плюс девять управляющих (серии не длиннее 127)
плюс завершающий ноль. Декодирование всех одиннадцати блоков даёт точную
объявленную ширину в каждой строке, ноль расхождений.

Состав файла:

| Блок | Размер | Что |
|---:|---|---|
| 0 | 1024×768 | фон экрана создания (указатель `0x6B35C0`) |
| 1…6 | 76×87 | шесть портретов героев (`0x6B35C8 + вид*8`) |
| 7, 8 | 94×13 | пара картинок, отжатая и нажатая |
| 9, 10 | 55×12 | вторая такая же пара |

Разбор лежит в `konung2/res.py`: `newhero_blocks()` и `newhero_sprite(номер)`.
Проверка содержимого числами: фон непрозрачен на 100%, 1839 уникальных
цветов, связность соседних пикселей 87.8% — это изображение, а не шум;
портреты — по 1100 цветов при связности 42…45%.

Прямоугольники портретов на экране (80×92) чуть больше самих картинок
(76×87) — картинка ставится в левый верхний угол прямоугольника из
`0x461D44`.

### 6.6. Не выяснено

- Что происходит в состоянии 8, куда уводит «Играть».
- Назначение области с кодом 86 (полоса свободного опыта).
- Назначение блоков 7…10 файла: кнопки экрана рисуются спрайтами INTERF.RES
  (`0x6B2618`, индексы 0x1FC…0x1FF), поэтому эти четыре картинки — что-то
  иное. Размеры 94×13 и 55×12 не совпадают с прямоугольниками кнопок
  (144×19 и 141×19).

## 7. Сохранить и загрузить (состояния 5 и 4)

Один экран на оба режима: `0x43259C(1)` — запись, `0x43259C(0)` — чтение.
Прямоугольники мест — `0x462304`, **их десять**: x 305…725, y с 208 шагом 37.

Имя файла собирается в буфер `0x844154` из шаблона `0x4616D4[текущая_карта]`
и строки `0x45930C`; в него подставляются поля структуры `0x8A7A70`
(смещения +4, +8, +0x0C и +0x10) — то есть подпись места содержит данные
сохранения, а не только номер.

## 8. Настройки (состояние 6)

`0x4326A8`. Перед входом текущие значения складываются в запасной блок
`0x8A7A7C`…`0x8A7A9C` (одиннадцать полей из `0x849598`, `0x84959C`,
`0x8495B4`, `0x8495DC`, `0x8495E4`, `0x84953C`, `0x849540`, `0x8495F8`,
`0x849604`, `0x849614`, `0x84958C`) — то есть «Отмена» возвращает их
обратно. Состав самих настроек **не выяснен**: нужен разбор `0x4326A8`.

Известно только, что `0x84958C` — множитель опыта: начисление умножает
опыт на `значение + 2`, а стартовые деньги — на 5 при значении 2 и на 10
при 4.

## 9. Что из этого уже перенесено неверно

1. **Экран создания собран HTML-накладкой поверх живой сцены.** В движке это
   отдельное состояние экрана с собственным фоном; сцена под ним не видна.
   Накладку надо убрать.
2. **Выбор героя сделан стрелками и карточками.** В оригинале — щелчок по
   одному из шести портретов, разложенных в два ряда по три.
3. **Мест сохранения шесть.** В оригинале десять.
4. **«Новая игра» открывается на герое мира 0.** В оригинале — на втором
   (`0x4387CC(2)`).
5. **Выбранный герой не переживает перезагрузку страницы:** заказ новой игры
   потребляется при старте, и обновление возвращает героя мира 0. В движке
   архетип лежит в самой записи героя (байт `+0xFC`) и потому сохраняется.
6. **Экран создания не гасит игру:** мировой такт под накладкой продолжает
   идти, юниты ходят, портрет в панели меняется на ходу.
