### 0.2. `class_kinds` против контрактного теста

`tests/test_items_contract.py::ClassKindsContractTest::test_kinds_agree_across_worlds_and_cover_jewels`

`konung2/gamefile.py::class_kinds` перестала отбрасывать записи с видом 0, тест
их по-прежнему отбрасывает (`if ... record[0] in (0, 0xFF): continue`).
Расхождение — ровно 43 класса: 101–112, 114, 134–148, 168–182, 208.

**Права здесь функция, а не тест.** Записи с видом 0 — настоящие вещи:

    idx 146  00 ffff 86 0000 8041 0000 8041 0000 0000   класс 134, крепость 16.0/16.0
    idx 148  00 ffff d0 0000 be42 0000 be42 0a00 0000   класс 208, крепость 95.0/95.0, отрава 10

Байт +0 = 0 — это вид «оружие» (0…4 снаряжение), пустая запись метится 0xFF
(движок так и чистит слот: `(&DAT_006f956c)[iVar2] = -1`). Байт +2 = 0xFF —
«не намазано маслом», как и у чистых стрел. Полностью нулевых записей в таблице
нет ни в одном из шести миров.

То есть до правки порт не знал ВООБЩЕ НИ ОДНОГО класса оружия, и всё, что
гейтится видом 0 (точило по B10, двуручность, выбор анимации удара), работало на
пустом множестве. Правка верная — устарел тест: убрать `0` из его фильтра,
оставив только `0xFF`.

## 2. Поправки к находкам

- **B15, смещение слота.** В находке щитовое гнездо названо `+0x5E`. В
  `0x41A414` читается `*(int *)(param_1 + 0x5e) >> 0x10`, то есть u16 по
  **+0x60**; три слота — это +0x5C, +0x5E, +0x60. На суть (третий слот гейтится
  видом 4) не влияет, но это ровно тот сдвиг на 2, который числится в реестре
  под № 51 — при переносе править по адресам, а не по подписям в комментариях.
- **B29 недооценена.** Находка говорит про условие 6 (462 вызова). Комментарий
  самого порта считает 1457 вызовов из 2143 — то есть неразобрано **две трети**
  всех условий диалогов, и все они трактуются как выполненные.
- **B16, сверх находки.** В той же ветке `0x41FDD0` движок бросает `rand() % 100
  < 0x15` и только при удаче ставит постройке состояние 3 (пожар). В порте
  зажигательная стрела поджигает детерминированно — смежное расхождение, в
  реестре не числится.
