# Скорость движения: разбор движка

Дата разбора: 2026-08-10. Повод — оба бета-тестера: «скорость не меняется от
выносливости и ловкости», «скорость не меняется при перегрузе, в оригинале
только ходишь», «бег и ходьба одинаковые».

Здесь записано снятое с кода. Две мои прежние модели были неверны и обе сняты
— об этом в конце.

## Формула

**Клетка проходится за `база_блока − скорость` мировых тактов.** Такт 78 мс
(`_DAT_0084962C`).

Цепочка по байтам записи юнита:

| функция | что делает |
|---|---|
| `FUN_00416C84` | по битам `+0x19` выбирает блок хода: `0x80` бег, `0x04` боевая стойка |
| `FUN_00429B2C` (VA 0x429B3E) | `юнит[0xFD] = DAT_0045FE90[блок] − юнит[0x1D]` |
| `FUN_0041611C` (VA 0x41612B) | каждый такт `inc byte ptr [eax + 0xFB]` |
| `FUN_00413894` | `if (юнит[0xFD] <= юнит[0xFB])` → обнулить `+0xFB` и перейти в следующую клетку |

Байты: `+0xFD` походка (она же число тактов на клетку), `+0xFB` счётчик
подшагов, `+0x1D` скорость, `+0xFE` число кадров блока, `+0x1C` номер кадра.

### Таблица баз — `DAT_0045FE90`

```
00 0B 00 00 00 FB 00 05 F9 D9 00 00 00 00 00 00 00 0A 00 04 ...
```

| блок | что это | база |
|---|---|---|
| `0x01` | ходьба боевая | 11 |
| `0x07` | бег боевой | 5 |
| `0x11` | ходьба мирная | 10 |
| `0x13` | бег мирный | 4 |

У всех неходовых блоков база 0 — и `FUN_0041611C` по условию `база < 1`
вообще не двигает экранную точку.

### Скорость — `FUN_0041B3B8`

```c
raw = (юнит[0xD1] + юнит[0xCD]) / 50;          // Выносливость + Ловкость
если raw == 0                    -> 0
если raw < 4:
    предел = юнит[0xD1] * 1000 / 3 + 20000;    // тот же, что у переноса вещей
    ноша   = FUN_0041B218(юнит);
    если предел * 0x55 < ноша * 100  -> raw -= 2;   // свыше 85 %
    иначе если предел * 0x3C < ноша * 100 -> raw -= 1;  // свыше 60 %
итог зажимается в 0…2
```

Особая ветка: у твари не нашей стороны с отрицательным `+0x1A` скорость
берётся прямо из этого байта. У нас не перенесена — порода лежит в отдельном
поле.

### Сколько это в миллисекундах

| режим | скорость 0 | 1 | 2 |
|---|---|---|---|
| ходьба мирная | 780 мс | 702 | 624 |
| бег мирный | 312 мс | 234 | **156** |
| ходьба боевая | 858 мс | 780 | 702 |
| бег боевой | 390 мс | 312 | 234 |

Порог первой прибавки — сумма Выносливости и Ловкости в 50, второй — в 100.
У Ратибора на старте 21 и 10, поэтому скорость 0, и тестер не зря не видел
разницы от характеристик: до порога ему далеко.

## Независимая проверка

Таблицы подшагов `0x459AD4` (X) и `0x459D14` (Y) индексируются САМОЙ походкой
— VA 0x416157, `shl eax, 5` по байту `+0xFD` плюс направление × 4. Размер
`0x459D14 − 0x459AD4 = 0x240` — восемнадцать походок по восемь направлений.

Смещение, умноженное на походку, даёт ровно переход в соседнюю клетку —
(±58, 0), (±29, ±16), (0, ±32) — и так для всех восемнадцати. То есть таблица
буквально «клетка, делённая на число тактов», и это подтверждает смысл
`+0xFD` вторым, независимым способом.

## Перегруз запрещает бег совсем

`FUN_0042F22C`, обработка двойного щелчка (0x203), ставит бит бега всей
дружине, но каждому — с проверкой:

```c
iVar3 = FUN_00415040(юнит);                     // свой и живой
if (iVar3 != 0 &&
    (bVar1 = юнит[0xD1],
     iVar3 = FUN_0041B218(юнит),
     iVar3 <= (int)(((uint)bVar1 * 1000) / 3 + 20000)))
    юнит[0x19] |= 0x80;
```

Одиночный щелчок по миру (ветка 0x401 той же функции) бит СНИМАЕТ, тоже у
всей дружины: `юнит[0x19] &= 0x7F`.

## Новый приказ перетаймливает ход немедленно

`FUN_00416574`, найдя путь, выбирает блок по битам `+0x19` и зовёт
`FUN_00416740`, а та:

```c
if ((база[текущий] < 1) || (текущий != новый)) FUN_00429B2C(юнит, новый);
юнит[0xFB] = '\0';
FUN_0043B974(+0x36, +0x3E, +0x12, +0x14);       // якорь на клетку юнита
```

Поэтому двойной щелчок даёт бег с первой же клетки, а не после того, как
доиграет начатая клетка ходьбы.

## Известный изъян оригинала и наше отступление

Сброс `+0xFB` и якорь — БЕЗУСЛОВНЫЕ, а раздача приказов `FUN_004240BC` шлёт
приказ каждому выбранному на каждый щелчок, ничего не сверяя с текущей целью.
Хвост `FUN_00416740` у идущего юнита (`база[текущий] > 0` и в очереди есть
направление) вдобавок сразу сдвигает `+0x12/+0x14` в соседнюю клетку. Отсюда
спам щелчками гонит персонажа скачками быстрее такта.

**Отступаем намеренно**: берём условие, которое у самого движка стоит строкой
выше — пересчёт походки сделан только при смене блока, — и распространяем его
на сброс с якорем. Повторные щелчки в ту же точку блок не меняют, скачков
нет; двойной щелчок меняет `0x11` на `0x13`, и бег включается сразу.

**Второе отступление — спам держит бег.** Браузер на пару щелчков шлёт
`click, click, dblclick`, и одиночные гасят бег между двойными; в движке то же
чередование — ветка 0x401 снимает бит, 0x203 ставит. Поэтому спам и в
оригинале, и у нас удерживал ХОДЬБУ. Сделали иначе: повтор приказа в ту же
клетку бег не гасит, щелчок по другой точке возвращает ходьбу.

Подшаги мы рисуем плавно, а не скачками: движок за такт прыгает на
«клетка / походка» (на бегу со скоростью 2 это два прыжка по полклетки),
браузер же рисует чаще такта. Длительность и средняя скорость совпадают.

## Две снятые модели

1. **«Клетка за номер походки тактов», походка = `1 + случайное(0…3−скорость)`.**
   Походку я взял верно, но её ИСТОЧНИК выдумал: жребий там для блоков
   простоя (`FUN_00413894`, приказ 10), а не для хода. Темп скакал от клетки
   к клетке — на это тестер и пожаловался.
2. **«Клетка = число кадров блока × такт».** Кадры (`+0xFE`) крутят спрайты,
   и когда кончаются, блок заводится заново — на клетку они не влияют. Модель
   давала бегу 702 мс вместо 156…312, то есть ровно канонную ходьбу, отсюда
   «бег как ходьба». Эта версия была залита на сервер без спроса — снята.

## Замер на сборке

Карта 33 (Борье), Ратибор, скорость 0, путь в 10 клеток:

| режим | клетка | путь |
|---|---|---|
| ходьба | 785 мс (канон 780) | 7.85 с |
| бег | 319 мс (канон 312) | 3.19 с |

Задержка бега после двойного щелчка — 10…22 мс. Спам щелчками (43 щелчка за
2 с) переходов не добавляет: 3 на ходьбе и 7 на бегу, столько же, сколько
без спама.

Спам настоящими событиями канвы (`click, click, dblclick`, 21 щелчок за
2.6 с): бег держится 95 % времени, 289 мс на клетку — беговой темп и не
быстрее него.
