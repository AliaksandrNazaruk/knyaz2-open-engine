# Аудит аудиосистемы Князя 2

Полная перепись того, как оригинал хранит, грузит и играет звук. Снято с
декомпилята (`engine/decompiled/`) и перепроверено по данным установки;
каждый пункт с адресом — прочитан в коде, каждый пункт с числами — измерен
скриптом по файлам. Дата: 2026-08-08.

## 1. Носители

| файл | размер | содержимое |
|---|---|---|
| SOUNDS.RES | 69 422 616 | 494 слота: эффекты, музыка, голоса юнитов, амбиент |
| KONUNG2\voices.res | 469 316 818 | 1245 реплик озвучки диалогов, ~177 минут речи |
| KONUNG2\_VOICES | 200 | текст, CSV «голос,поправка частоты» — питчи голосов |
| QUESTS.RES (поле фразы +0) | — | номер реплики voices.res для каждой озвученной фразы |
| VIDEO\*.avi | 63 МБ | ролики со своими звуковыми дорожками (вне этой системы) |

Оба контейнера — таблица `{u32 off; u32 size}` с нулевого смещения:
SOUNDS.RES — 1000 записей (8000 Б), смещения **от конца таблицы** (движок
прибавляет 8000); voices.res — 6000 записей (48000 Б), смещения
**абсолютные** (движок сикает без поправки — VA 0x42D9FC). Проверено:
у voices.res минимальное смещение занятых = 48000, конец последней записи =
размер файла, 0 дыр, 0 перекрытий.

## 2. Форматы PCM

Все данные — сырой PCM s16le без заголовков. Форматов ТРИ, по пути
воспроизведения (WAVEFORMATEX заполняются в 0x42CE0C и 0x42A43C):

| путь | формат | адрес формата | кто играет |
|---|---|---|---|
| эффекты | моно 22050 (+варианты 19050 и 25050) | 0x8A77F8 (три подряд) | 0x42D660 |
| музыка (слоты 20–30) | **стерео 44100** | 0x8A7A10 | 0x42D13C |
| голоса (voices.res и слоты 32–79, 700–723) | моно 22050 **+ поправка по номеру голоса** | 0x8A7830[] | 0x42D9FC, 0x42D308 |

- Вариация питча эффектов: 0x42D660 берёт случайный из трёх форматов
  (22050/19050/25050, то есть ±13.6 %) — для слотов ≥ 32 и для 3, 5, 12,
  13, 15; прочие UI-слоты (< 32) всегда 22050. Слоты ≥ 700 — тоже всегда
  базовый.
- `_VOICES`: 21 строка «голос,дельта» (дельты −1500…+2500). При старте
  0x42A43C строит для каждой дельты WAVEFORMATEX 22050+дельта и пишет индекс
  в таблицу `0x8A7344[голос]`. Номер голоса — байт `unit+0xF2`; для реплик
  диалога текущий говорящий кладётся в `0x849658` (0x4369A0).

## 3. Раскладка SOUNDS.RES (494 занятых слота, 86.0 МБ)

| слоты | шт | объём | что это |
|---|---|---|---|
| 0–19 | 17 | 0.5 МБ | UI и общие эффекты (предзагрузка при старте) |
| 20–30 | 11 | 59.7 МБ | музыкальные петли 26–46 с, стерео 44100 |
| 32–79 | 30 | 0.7 МБ | голосовые отклики: 6 актёров × 8 (заняты +2,+4…+7) |
| 80–255 | 71 | 3.1 МБ | звуки зверей: `вид*8 + {80,82,83,84}` (+ спец `запись*8+49`) |
| 256–686 | 341 | 21.0 МБ | **амбиент карт: `(карта−1)*8 + 256 + n`, по 8 на карту, карты 6–54** |
| 700–723 | 24 | 0.9 МБ | «Эй, есть разговор!»: `база(700/702) + актёр*4 + rand%2` |

Звери (0x429B2C, слот от вида зверя = байт `unit+0xFC`):
`+80` смерть (блок 5), `+82` атака (блоки 3/0xB/0xC), `+83` стойка и ходьба
(блок 0 с шансом 4 % — в коде «rand%100 ≤ 95 → тишина», блок 1 с шансом
24 %), `+84` бег (блок 2, всегда).
Занятость слотов 80–255 ≡ {0,2,3,4} mod 8 — сходится с формулой.

Спец-звук зверя (0x413894:343): при входе в состояние-набор 4 (кадр 1,
позиционно) слот `(unit+0x1A & 0x7F)*8 − 463` = **`запись_OBJECTS*8 + 49`**
(байт `+0x1A` зверя = `0x40 | номер записи динамики`; связка вид↔запись
обычно `запись = вид+1`, но не всегда — виды 13 и 20 сидят на записях 16 и
17). Записаны только два таких звука — ровно под эту формулу: слот 121
(запись 9 — **лодка с гребцом**, 1.0 c; 13 из 21 стартовых стоят прямо на
клетках воды) и слот 169 (запись 15 — **исчезающий дух**, VANISHING_BODY,
1.8 c). Но сетка предзагрузки грузит `запись*8+80…87`, то есть слот
`запись*8+49` попадает в кэш только как «восьмёрка записи−4» — а на
стартовых расстановках всех шести миров записи 5 (для лодок) и 11 (для
духов; они вообще стоят только в резерве, «карта 105») на нужных картах
нет. **Оба спец-звука в оригинале фактически никогда не слышны** —
кэш-промах глушит их молча.

Люди при замахе (та же 0x429B2C, ветка HEROES): слот по типу оружия из
класса предмета (таблица 0x45DB08): тип 0xD → слот 16, тип 0xF → слот 4,
иначе слот 10.

Попадания по человеку (0x412570): промах или блок → слот 12; иначе по
типу брони в гнезде (таблица классов 0x45DB08 +0x10): пусто/тип 0 → 7
(по телу), тип 1 → 15, тип 5 → 3, прочие → 9. Питч-вариации у UI-слотов
включены ровно для {3, 5, 12, 13, 15} — это и есть звуки попаданий.

Level-up (0x413110, gainExperience): слот 14, только для юнитов стороны
игрока, без позиционирования.

## 4. voices.res и связка с диалогами

- Записи 1–1215 — реплики диалогов. Поле +0 записи фразы QUESTS.RES
  (`0x642790 + фраза*8`) — номер реплики; 0 = фраза не озвучена.
  **Перекрёстная проверка: 1215 уникальных номеров озвучки в QUESTS ↔ все
  1215 есть в voices.res, висячих записей нет.**
- Записи 5500–5529 — 30 приветствий: `5500 + актёр*5 + rand%5`
  (актёр = байт `unit+0xFC`). Играются спутником раз в 1024 тика
  (0x438A00:199), если в отряде > 1 юнита И **нет открытого экрана**
  (`[0x8495F0] == 0`, строка 170) — иначе приветствие перебивало бы
  реплику разговора: канал у них общий (0x849670). У амбиента этого
  гейта НЕТ — сверчки поют и при открытом окне разговора.
- Реплика диалога играется в 0x436478 при входе в узел разговора; питч —
  формат текущего говорящего (`0x8A7344[0x849658]`).
- Медиана реплики 6.7 с, максимум 49 с. Формат: моно (проверено тестом
  чередования каналов на трёх записях), 22050 ± дельта голоса.

## 5. Механика воспроизведения (DirectSound)

- Микшер: до **45 одновременных буферов** (0x2D, массив 0x8A7744,
  счётчик 0x8A7A50); отыгравшие вычищаются перед каждым новым звуком.
- Синглтоны: 1 канал музыки (0x8A79D0), 1 канал голоса юнита (хэндл
  0x84963C), 1 канал реплики диалога (0x849670). Новый голос глушит
  предыдущий (0x42EAF0 в начале 0x42D9FC).
- Музыка: единственный зацикленный буфер (Play с DSBPLAY_LOOPING);
  громкость **бинарная** — 0x42D0E8 ставит 0 или −10000 (настройка
  «музыка» вкл/выкл, 0x8495E4). Смена трека: если номер не изменился —
  ничего (0x42D13C, ранний выход).
- Эффект: `0x42D660(слот, громкость, пан, луп)`; звук тише **−4000**
  (−40 дБ) не заводится вовсе.

### Позиционный звук (снято дизасмом, константы из exe)

- Громкость (0x43BC74): клетка → мировые пиксели якоря (0x43B974), затем
  `dist = round(sqrt(dx² + dy²))` до **центра экрана** (камера + (442, 354));
  `громкость = −10000·dist/2048` (сотые дБ), дальше 2048 px — тишина.
- Пан (0x43BC20): `пан = round((col − (левая_колонка_0x849680 + 5)) · 62.5)`
  (константы 10000.0 и 0.00625 по адресам 0x45933A/0x459342).

## 6. Память и стриминг — «оптимизация оригинала»

Арена звуков ~3.5 МБ (0x43C228). Три уровня:

1. **Вечная предзагрузка** (старт игры и каждая загрузка сейва, 0x43D898):
   слоты 0–19 (UI), 32–79 (отклики юнитов), `700 + актёр_героя*4 … +3`
   (голос текущего героя). Итого меньше 1.5 МБ.
2. **Стриминг звуков карты**: загрузчик карты (0x43DF48) ставит в очередь
   0x843C64 два набора: занятые амбиент-слоты `(карта−1)*8+256+n` И звуки
   зверей `запись*8+80…87` для каждой записи динамики, встреченной среди
   юнитов карты (флаги local_1b8; записи 14 и 15 добавляются принудительно
   отдельной веткой). Главный цикл (0x438A00:246) догружает **по одному
   слоту за тик** (0x43F07C) в переиспользуемую часть арены (курсор
   0x849558 сбрасывается на каждой карте). Ни одного фриза — очередь
   расползается на секунды, а до догрузки звук просто молчит.
3. **Прямо с диска в буфер**: музыка (целиком при старте трека) и реплики
   диалога (seek + read в момент воспроизведения). Кэша нет — и не нужен.

Гейт всех эффектов и голосов: настройка «звук» 0x849614; кэш-промах
(слот не догружен) просто молчит — 0x42D660 требует `0x840D04[слот] != 0`.

### Амбиент: день, ночь и пещеры

Раз в тик с шансом 1 % (rand%100 > 98, герой жив, режим 0):

- обычная карта, день: слоты **+0…+4** (rand%5);
- обычная карта, после заката (гейт ночного света 0x8495CC, тик ≥ 8100):
  слоты **+5…+7** (rand%3+5);
- карта с фиксированным светом (0x8495A4 = запись таблицы 0x4617B0,
  пещеры и «всегда светящиеся» карты): все 8 без деления.

У 47 из 52 карт есть свой набор (обычно 7–8 слотов, 331 слот суммарно,
489.9 c звука). Это самый большой пласт эффектов игры.

### Стартовое меню (0x438A00 case 1)

Хит-тест пунктов — по таблице прямоугольников **0x46155C** (0x43B5F8);
без запущенной игры пункты < 2 («Продолжить», «Сохранить») неактивны —
«Загрузить» РАБОТАЕТ. Наведение немое, отрисовка золотой плиты — и только
клик кнопкой играет **слот 6**, тот же универсальный щелчок. Музыка меню —
трек 29 (case 3 и case 7, только когда игры нет).

### «Эй, есть разговор!» — серия 700…723 (уточнено 2026-08-08)

Первая трактовка «отклик на приказ „пошёл“» была неверной: блок 700-х
живёт в **case 2** обработчика приказов 0x410A08 — «подойти и заговорить».
Пока игрок ИДЁТ к собеседнику (|Δстрок| ≥ 7 или |Δколонок| ≥ 4), из
одинарного голосового канала играется `база + актёр_идущего*4 + rand%2`;
вплотную разговор открывается сразу и молча (0x4369A0). База — по ТИПУ
собеседника: байт `0x45FE90[тип]` ненулевой (типы 1, 5, 7, 8, 9, 17, 19)
даёт 702, иначе 700. Сетка 700…723 закрывается целиком: 6 актёров × 2 базы
× 2 варианта — **дублей в этой серии нет**, и вечная предзагрузка героя
(0x43D898, четыре слота `700+актёр*4`) как раз покрывает обе его базы.
Приказ «идти» в движке не озвучивается вовсе. Проигрыватель откликов
0x42D308 и этот путь НЕ проходят через случайную питч-тройку эффектов —
частота только базовая или личная (по номеру диалога, _VOICES).

### Восьмёрки 32–79 целиком: голоса людей (закрыто 2026-08-08)

Дорожки +2/+4 — НЕ дубли и НЕ вырезанный контент: это штатные **крики
смерти и боли**, которые зовёт та же 0x429B2C — её ветку людей я сперва
прочитал с середины. Полный switch по номеру НАБОРА анимации человека:

| набор | событие | слот |
|---|---|---|
| 0, 6, 0x10, 0x12 | стойка/простой, шанс 4 % | `актёр*8+35` — ПУСТ (кряхтенье вырезано) |
| 1, 0x11 | ходьба, ТОЛЬКО герой | 13 — ПУСТ (шаги вырезаны) |
| 2 | реакция на удар | **`актёр*8+36` — крик боли** |
| 3, 0xB, 0xC | три смерти | **`актёр*8+34` — крик смерти** |
| 4 | выстрел | класс слоя 0x15 (самострел) → **1**, иначе → **5** (лук) |
| 8 | замах | по типу оружия: 0xD → 16, 0xF → 4, иначе 10 |

Отсюда же закрываются последние «сироты»: слот 5 — выстрел лука, слот 1 —
взвод самострела (он же «надеть предмет» из 0x41E280), слот 13 — пустые
шаги героя (потому он и в питч-списке). Настоящих сирот осталось два:
8 и 19. Урок: карта вызовов по `call`-адресам не связывает ВЫЧИСЛЕНИЕ
слота с вызовом — switch стоял сотней строк выше, и одна функция давала
семь разных событий.
