# Контейнеры: бочки, сундуки и прочая обстановка интерьера

Снято с декомпилята 12.08.2026. Заменяет черновой `CONTAINERS_PORT_PLAN.md`:
тот строился на догадке «у сундука должна быть ссылка на список вещей», а на
деле связь обратная — это **куча знает, в каком гнезде обстановки лежит**.

Всё, что ниже, проверено по коду и по данным; числа снимались с игры.

---

## Коротко

Сундук — это не объект и не постройка. Это **гнездо обстановки**: спрайт с
экранной точкой внутри дома. А содержимое — обычная куча из той же таблицы
`0x7AD7E4`, что и добро на земле. Связывает их пара байтов в записи кучи:

    +0x09  place  — номер ЗОНЫ (0xFF = куча лежит на полу, а не в гнезде)
    +0x0A  slot   — номер ГНЕЗДА внутри зоны

Загрузчик карты по этой паре вписывает номер кучи в само гнездо, и дальше
гнездо ведёт себя как контейнер: по нему можно щёлкнуть.

---

## 1. Откуда берётся обстановка

Блок `0x3D384` файла `.KN2`, размер `0x1680`: **30 зон по 16 гнёзд, гнездо 12
байт**. Загрузчик читает его целиком (`VA 0x43DF48:92`):

    FUN_00442fdc(файл, &DAT_006ae458, 0x1680)

Формат гнезда — тот же, что у записей раннего прохода оверлеев (`0x31600`,
`T_DYNAMIC` текстового проекта), и разбирает их движок ОДНИМ И ТЕМ ЖЕ кодом
(`0x43DF48:158-172`):

    +0x00  u16  спрайт GRAPH.RES
    +0x02  u16  ноль в файле — РЕЗЕРВ, сюда движок пишет номер кучи
    +0x04  u16  палитра (в файле есть, но движок её ПЕРЕЗАПИСЫВАЕТ)
    +0x06  u16  старшая половина палитры (в файле 0, изредка 1)
    +0x08  u16  экранный x
    +0x0A  u16  экранный y

Разбор загрузчика:

    for (зона = 0; зона < 30; зона++) {
        n = 0;
        for (гнездо = база + зона*0xC0; n < 15 && *гнездо < 0x80000000; гнездо += 3) {
            гнездо[1] = *(u32 *)(0x6B455C + *гнездо * 8);   // палитра из таблицы спрайтов
            *гнездо   = 0x84954C + *(int *)(0x6B4558 + *гнездо * 8);
            n++;
        }
        *(u8 *)(зона + 0x844304) = n;                       // сколько гнёзд занято
    }

Отсюда три правила:

1. **Занятые гнёзда идут префиксом.** Перебор обрывается на первом пустом
   (`0xFFFFFFFF`), а не пропускает его.
2. **Не больше пятнадцати** гнёзд из шестнадцати доступны — счётчик `n < 15`.
3. **Палитра из файла не годится.** Движок берёт её из таблицы спрайта, ровно
   как у оверлеев (в сборщике это уже учтено: `assets.graph.tile_palette`).

**Данные:** 369 занятых гнёзд на 50 картах, 30 разных спрайтов. Самые частые —
325 (54 раза), 334 (46), 324 (40), 337 (36).

## 2. Кто такая «зона»

Номер зоны — это **номер записи объекта карты**:

    iVar3 = (param_2 - 0x834768) / 0x24;      // VA 0x425AA8:29
    if (прототип[2] != -1) FUN_00424514(холст, iVar3, флаг);

`0x834768` — таблица объектов карты (1000 записей по `0x24`), а `прототип[2]`
— смещение блока СТЕН. То есть обстановка рисуется только у объектов со
стенами, то есть у построек с интерьером, и только у первых тридцати.

## 3. Как рисуется

Проход содержимого постройки, `VA 0x424514:113-131`:

    гнездо = 0x6AE458 + зона * 0xC0;
    для каждого из (0x844304 + зона) гнёзд:
        x = камера_x + u16[гнездо + 8];
        y = камера_y + u16[гнездо + 10];
        рисовать(гнездо[0], гнездо[1] & 0xFFFFFF, x, y);
        если (байт[гнездо + 7] != 0 && курсор попал в спрайт)
            0x84952C = гнездо;              // контейнер под мышью

Место в порядке отрисовки: между главным спрайтом постройки и её стенами.

## 4. Как связывается с кучей

Загрузчик куч, `VA 0x43DF48:344-352`. Для каждой записи кучи:

    если (байт +0x09 == 0xFF)                       // НА ПОЛУ
        клетка[строка][столбец] |= 0x2000;          // «здесь есть куча»
        экранная точка = якорь клетки − половина спрайта;
        записать её в +0x00 и +0x02 записи кучи;
    иначе                                           // В ГНЕЗДЕ
        *(u32 *)(0x6AE458 + slot*0xC + place*0xC0) |= (номер + 1) << 24;

То есть номер кучи плюс один ложится в **старший байт второго слова гнезда** —
в тот самый резерв, который в файле всегда ноль.

**Данные:** 61 куча в гнёздах на 22 картах (мир 0). В Борье их пять.

## 5. Как открывается

Три звена, все проверены:

**Щелчок** (`VA 0x421690:213`):

    если (0x84952C != 0) {
        n = (u32[0x84952C + 4] >> 24) & 0xFF;        // номер кучи + 1
        FUN_0041F518(-n,                             // ЦЕЛЬ ОТРИЦАТЕЛЬНАЯ
                     байт[0x7AD7E4 + (n-1)*0x65 + 5],   // строка кучи
                     байт[0x7AD7E4 + (n-1)*0x65 + 6]);  // столбец кучи
        return;
    }

**Приказ** (`VA 0x41F518`) — тот же, что у кучи на земле:

    выбранный[+0x10] = цель;  [+0x13] = строка;  [+0x15] = столбец;
    выбранный[+0x16] = 0x23;                       // «обыскать по приказу»

**Приход** (`VA 0x4115AC`, случай 3) — и вот здесь развилка:

    если (цель < 1) {
        если (цель < 0)  куча = 0x7AD7E4 + (−1 − цель) * 0x65;   // ПО НОМЕРУ
                         юнит[+0x18] = байт записи кучи +4;      // повернуться
        иначе если (клетка & 0x2000)
                         куча = FUN_004149F8(строка, столбец);   // ПО КЛЕТКЕ
    }

`FUN_004149F8` берёт **только напольные**: в её условии стоит `байт +0x09 ==
0xFF`. Поэтому контейнер по клетке не находится никогда — только по номеру,
только щелчком по самому гнезду.

## Что делать в порте

Порядок — от данных к коду, как обычно.

**1. Выпечка.** Сейчас `builder.py` выбрасывает непольные кучи одной строкой:

    if not pile["on_floor"]:
        continue

Их 61. Надо везти их с `place` и `slot`, и отдельным списком везти обстановку
(30 зон, занятые гнёзда префиксом, спрайт + палитра из таблицы + экранная
точка). Картинка гнезда берётся тем же `assets.terrain_overlay(спрайт)`, что и
у оверлеев, — блоки однотипны.

**2. Отрисовка.** Гнёзда зоны рисуются в проходе содержимого постройки, между
главным спрайтом и стенами. Зона = `record_slot` объекта, и только у объектов
со стенами.

**3. Щелчок.** Попадание по спрайту гнезда с ненулевым номером кучи → приказ
«обыскать» с клеткой кучи; открытие — по прибытии, тем же путём, что уже
работает у напольных куч (см. `CANON_AUDIT.md`, пункт 92).

## Побочная находка

Экранная точка напольной кучи — это **якорь клетки минус половина размера
спрайта** (`0x43DF48:331-341`). Сборщик кладёт голый якорь, без вычета. На
глаз это полспрайта вверх-влево; поправка дешёвая, но к контейнерам отношения
не имеет — отдельным пунктом.
