# Репутация «Продолжения легенды»

Разбор 20–21.08.2026. Повод — жалоба «Угорье, не работает квест с драконом».
Квест оказался цел, а под ним нашлась механика донора, перенесённая наполовину.

## Поправка к первой редакции

Первая редакция этого разбора (20.08, файл назывался `DONOR_GLORY.md`)
утверждала, что механики у нас нет вовсе и что на непереносённых
обработчиках висит 1148 условий и 486 действий. **Это неверно.** Ошибка
была в источнике: я взял из `konung2/donor.py` список `HANDLER_OWN` и
прочёл его как «не перенесено», тогда как он значит совсем другое — «у
канона нет парного обработчика с тем же смыслом». Перенос при этом мог
быть сделан давно, и был.

Честный замер — по фактической таблице `HANDLERS` из `dialog.js`, а не
по спискам донора:

    обработчиков в клиенте            92
    его собственных из них            17  (8, 12, 21, 26, 29, 30, 33, 38,
                                           49, 51, 61, 62, 71, 72, 75, 80, 91)
    условий-обработчиков в паке    11547,  из них непереносённых  0
    действий-обработчиков в паке    6723,  из них непереносённых  0

Все пять обработчиков, на которых держится квест о драконе, — донорские
8, 12, 21, 30 и 49 (наши 136, 140, 149, 158, 177) — в клиенте есть.

И название было неверным: механика зовётся **Репутация**. Так она
подписана в его интерфейсе (строка `0x4527FD`, cp866), следующей строкой
после «Уровень» (`0x4527F5`). Слова «слава» в игре нет.

## Что это

Одно знаковое число на всю игру — глобал `0x0087F410`. В каноне такой
механики НЕТ ВОВСЕ: строки «Репутация» в `konung2.exe` не найдено ни
одной. Ссылок на глобал в машинном коде донора ровно десять, и они
разошлись по восьми функциям — все восемь разобраны:

| VA | что делает |
|---|---|
| `0x0043C4AC` | выбор персонажа: счёт берётся из таблицы `0x00465A28` |
| `0x00418554` | убийство: начисление, см. ниже |
| `0x00436A14` | обработчик 49 (наш 177): `репутация += довод` |
| `0x00438120` | обработчик 8 (наш 136): `довод <= репутация` |
| `0x004258A4` | сохранение: четыре байта вторым полем |
| `0x00425158` | загрузка |
| `0x00433C30` | экран выбора героя: подпись и значение |
| `0x0042D710` | панель персонажа в игре: только когда показан сам игрок |

Последнюю Ghidra потеряла: в её выводе от функции остался один вызов, а
ссылка на глобал не видна вовсе. Нашлась поиском по машинному коду —
`0x0042DF7E`: `mov eax,[0x87F398]` / `cmp eax,[0x87F3A4]` / `jne` /
`push [0x87F410]`, дальше та же печать числа `0x00432E04`, что и на
экране выбора. Печатается по центру (`x = 0x15E − ширина/2`) на `y = 0x23`,
строкой ниже имени юнита.

## Старт у каждого героя свой

Таблица `0x00465A28`, четыре знаковых слова по номеру героя донора:

| герой | его номер | старт |
|---|---|---|
| Иззарк | 0 | −30 |
| Велиславна | 1 | 0 |
| Драгомир | 2 | −100 |
| Гильдис | 3 | +30 |

Порядок подтверждается независимо: у героя 1 движок ставит признак пола
(`+0xEE = 1`), и это Велиславна — единственная женщина из четверых.
Канонным героям ставим ноль: их игра о репутации не знает, и любое другое
число было бы выдумкой.

## За что меняется при убийстве

`0x00418554`, где `param_1` — убийца, `param_2` — жертва:

```c
if (убийца[0x1B] == игрок[0x1B]) {          // убил кто-то нашей стороны
  if (жертва[0xF2] == -1) {                 // разговора нет — безымянный
    if (жертва[0x1A] & 0x40) {
      if (жертва[0xFC] == 0xF)  репутация  = -0x8C;   // −140, ПРИСВАИВАНИЕМ
      if (жертва[0xFC] == 0xE)  репутация += -0x46;   // −70
    }
  } else {                                   // разговор есть — именованный
    репутация += таблица[0x45B0D4 + жертва[0xF2]];    // знаковый байт
  }
}
```

Тела 15 и 14 — **не звери**: пятнадцатое носят знатные мужи (Всеслав,
Глеб, Крок, Орей), четырнадцатое — женщины. То есть вторая ветвь
наказывает за убийство БЕЗЫМЯННОГО знатного и безымянной женщины.

## Таблица цен

Индекс — номер разговора жертвы (`unit+0xF2`), значение — знаковый байт.
Смысл сошёлся сразу у четырнадцати имён, и ни одна цена из него не выпала:

    Королева Нежити                +120     Глеб                    −120
    Чёрный маг                      +50     Всеслав                 −120
    Предводитель Жёлтых собак       +30     Иоанн                   −120
    Торрар                          +20     Жрец Вотана              −50
                                            именованные женщины      −60
                                            Ингви, Мефодий, Федора   −20
                                            рядовой именованный       −5

Обе ветви согласуются между собой, и это независимая проверка чтения:
именованный князь стоит −120, безымянный −140; именованная женщина −60,
безымянная −70. Перепутанные тела или знак эту согласованность сломали бы.

**ЦЕНА ИЩЕТСЯ ПО ПАРЕ «ИГРА + НОМЕР».** Номера разговоров обеих игр лежат
вперемешку (канон 6…151, донор 6…145) и один номер значит в них разных
людей. Канонной жертве цены нет вовсе.

## Осталось неразобранным

Три обработчика донора работают, но чем являются их поля — не установлено.
Все три опираются на `DAT_0087F3A4`, а это, как теперь известно, **запись
игрока**: по ней же читаются облик (`+0xFC`), характеристики (`+0xC0…`) и
свободный опыт (`+0x48`).

* **21** (`0x004384B0`): перебирает пять слов по `0x87F3A4 + 0xB4` и
  сравнивает класс найденной записи предмета с доводом. Пять слотов по
  смещению `+0xB4` в записи игрока — скорее всего украшения (браслеты,
  кольца, ожерелье), но это не проверено.
* **12** (`0x00438210`): `(байт +0xDD) << 4` против слова `+0x4E` с
  порогом `0x5F0`. Слово `+0x4E` — здоровье; что такое `+0xDD`, неясно.
* **30** (`0x00438948`): байт `+0xDF`; у канона это навык «Следопыт», но
  у донора записи местами сдвинуты, и совпадение надо проверять отдельно.

## Бочки — отдельный вывод

Жалоба «не зажигаются бочки» к этому квесту отношения не имеет. У бочек в
ресурсе РОВНО ОДНО состояние:

    ресурс 236, 238, 239, 240, 241, 243:  состояния [0], count=1, group=0

Таблица состояний простого объекта — восемь записей по восемь байт (спрайт
с +0x80, якорь с +0xC0, см. `konung2/res.py`), и у бочки заполнена одна.
Значит картинки горящей бочки НЕТ ВООБЩЕ, и «зажечь» её сменой состояния
нельзя ни у нас, ни в оригинале. Что тестер видел под словом
«зажигаются», надо уточнять у него.

Для сравнения, у деревенской постройки лестница состояний идёт по СОСЕДНИМ
ресурсам (изба 307 — состояния 304…310), и `group` у неё 8 или 13 против
нуля у бочки.
