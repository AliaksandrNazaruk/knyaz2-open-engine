# Новый редактор: на основе старого — поверх нашего ядра

> **25.08:** курс сменился — режим ?editor=1 остаётся «посмотреть
> глазами игрока», а САМ редактор строится отдельным UI (Claude
> Design) поверх JSON API дев-сервера. Концепция и API —
> **docs/EDITOR_SPEC.md**; фазы ниже — история механик, на которых
> API стоит.

Решение 24.08: редактор строим НЕ как отдельную программу со своим
рендером, а как РЕЖИМ нашего браузерного клиента. Ядро уже умеет всё,
что старому редактору давал движок: рисует карту, юнитов, кучи, объекты,
свет и воду, попиксельно ловит клики. Редактору остаётся выбор сущности,
панель свойств и запись в проект.

Старый авторский edit.exe (запущен на Win11 — рецепт в памяти проекта и
в knyaz2-map-editor) остаётся инструментом ЛАНДШАФТА: тайлы .KN2 он
правит в родном формате, и переписывать это ядро незачем, пока наш пак
читает .KN2 как вход. Новый редактор правит ДАННЫЕ НАШЕГО ядра.

## Архитектура (реализована фаза 1)

```
браузер (editor.js)          дев-сервер (server.py)      сборка пака
┌──────────────────┐  POST   ┌──────────────────────┐   ┌────────────────┐
│ режим ?editor=1  │ ───────>│ /editor/unit         │──>│ editor_units   │
│ клик = выбор     │         │ пишет editor_units в │   │ применяется    │
│ панель свойств   │         │ project/maps/N/      │   │ поверх юнитов  │
│ живой предпросмотр│        │ map.json             │   │ (белый список) │
│ F2 = сохранить   │         └──────────────────────┘   └────────────────┘
└──────────────────┘
```

- **Живой предпросмотр бесплатно**: правка меняет юнита прямо в мире —
  ядро само рисует следствия (здоровье, палитра, характеристики).
- **Проект — источник истины**: правки лежат в project/maps/<карта>/
  map.json ключом `editor_units` (человекочитаемый JSON, дифф в git).
- **Белый список сборки** (`EDITOR_UNIT_FIELDS/DICTS` в builder):
  редактор правит данные юнита, не его устройство; словарные поля
  сливаются по ключам, чтобы «здоровье 800» не съедало броню.

## Фазы

1. **Юниты** — СДЕЛАНО: выбор кликом, имя/уровень/деньги/здоровье/
   броня/палитра/шесть характеристик, сохранение F2, донос сборкой.
2. **Кучи и лут** — СДЕЛАНО: клик мимо юнита выбирает кучу (тайники
   редактору видны), панель — деньги, чекбокс «тайник», состав с
   именами из каталога, убрать/добавить вещь по классу; items+details
   всегда летят парой (они параллельны). Новая напольная куча в клетке
   героя — knyaz2.editorNewPile() (id pile_new_*, запись целиком уходит
   в `editor_loot_add`; патчи существующих — `editor_loot`, removed
   удаляет).
3. **Расстановка** — СДЕЛАНО: Ctrl+клик по земле переносит выбранного
   юнита (клетка через heroCellAt, якорь тем же heroAnchor, что и
   спавн; правится и `home` — куда житель возвращается);
   knyaz2.editorCloneUnit() клонирует выбранного в клетку героя (запись
   целиком, id unit_new_* -> `editor_units_add`, мирные умолчания у
   сборки; порода/тело меняются в панели — это и есть «из бестиария»);
   кнопка «убрать юнита с карты» — приговор `removed`.
4. **Объекты и мебель** — СДЕЛАНО: клик по объекту (рамка отрисовки,
   перебор с конца — верхний по порядку рисования) открывает панель
   (палитра, состояние-лестница, убрать с карты), Ctrl+клик переносит —
   позиция и предвычисленная рамка (draw_x/draw_y/sort_y) сдвигаются
   ВМЕСТЕ; knyaz2.editorCloneProp() клонирует объект в точку героя
   (prop_new_* -> `editor_props_add`, кадры копируются как есть). Клик
   по сундуку открывает ЕГО КУЧУ — состав правится панелью фазы 2.
   Слой применяется в _export_map из того же scenario.json.
5. **Тайлы/ландшафт** — СДЕЛАНО (клетки): Alt+клик открывает панель
   клетки — «глушь» (низ 12 бит LO: 0 свободно / 0xFFF стена-вода, по
   VA 0x4414A7), «глухая для стрел» (бит 0x4000), тайл (слово HI).
   Правки пишутся ПРЯМО В GRID.TXT проекта (он и есть источник сетки —
   отдельный слой завёл бы второго хозяина), без dirty-буфера, запись
   идемпотентна (байт-в-байт при откате). Живой предпросмотр —
   world.editorCellWall и набор solid ядра. Сборку менять не пришлось:
   grid.txt она уже читает. Рисование КАРТИНОК тайлов (layer1/2.png) —
   по-прежнему старый edit.exe: он для того и заведён.
6. **Квесты** — СДЕЛАНО (в рамках слоёв): поле «диалог №» в панели
   юнита (dialog_number в белом списке; смена номера ПЕРЕПЕКАЕТ дерево
   при сборке — оно испечено раньше слоя, добавленным говорящим тоже
   печётся своё), и knyaz2.editorCompileQuests() — пересборка
   QUESTS.RES авторским M_QUEST.exe прямо из редактора (POST
   /editor/quests, рабочее место — посылка k2_tools, статистика в
   панель; живой тест держит эталонные 103 токена). Честное
   ограничение: пак читает QUESTS.RES из каталога игры — собранный файл
   модер доносит туда осознанным шагом, ручка заменяет DOS-эпоху
   компиляции, не подменяет поставку.

7. **Тайлы и свет клеток (режимы TILE и LIGHT)** — СДЕЛАНО:
   knyaz2.editorTilesToggle() включает режим кисти. Разгадка формата:
   «два тайла на клетку» = ПАРА ПИКСЕЛЕЙ layer1.png (160 рядов x 80
   клеток земли, x=col*2 нижний / x=col*2+1 верхний), «свет» клетки =
   пиксель layer2.png; ноль — пусто, иначе индекс+1 (ground_cells).
   Палитра тайлов — страницы по 50 (PgUp/PgDn), превью печёт сервер на
   лету из GRAPH.RES (compose_cell) в assets/ground/editor_tile_N.png;
   слои кисти «низ/верх/свет», ЛКМ красит, ПКМ — ластик. Живой
   предпросмотр — подмена ассета клетки (комбинации низ+верх честно
   приедут пересборкой). Интеграционный ритуал пройден: мазок ->
   build --map 33 -> tiles.lower=5 и испечённый ассет в паке; откат
   байт-в-байт (PNG-сериализация идемпотентна).

8. **Вода (режим WATER)** — СДЕЛАНО: knyaz2.editorWaterToggle() —
   кисть по клеткам подложки 256x256 px (ЛКМ заливает, ПКМ осушает,
   счёт «N из 512» как в старом редакторе), панель — переключатель
   Lake/Stream и номер тайла подложки (light_flag). Ручка
   /editor/water правит sparse-records блока `light` в map.json
   проекта (записи только для рядов, отличных от _default). Живой
   предпросмотр — правка world.underlay (рендер уже рисует по нему).
   ДИЗАСМ-РАЗГАДКА ТИПА ВОДЫ (закрыла и баг рендера 12 карт): тип у
   карты ЦЕЛИКОМ — загрузчик (VA 0x43DF48) складывает OR всех 512
   байтов в 0x84961C, и отрисовщик (VA 0x428240) по биту 0x80 зовёт
   стоячую волну Lake (VA 0x43F46E) либо течение Stream со сдвигом
   буфера (VA 0x43F4D9); авторский редактор потому писал во все
   клетки Lake-карт 0x80, Stream-карт — 0x40 (по данным всех карт —
   ни одной смеси). Наш builder судил по ПЕРВОМУ байту и гнал 12
   стоячих карт (болота, озёра, Борье, оазис) течением — исправлен
   на OR. Кисть льёт канонный байт типа карты, переключатель
   конвертирует все клетки разом.

9. **Оверлеи ландшафта (режим SPRITE)** — СДЕЛАНО: клик в «пустоту»
   (после юнитов, куч, мебели и реквизита) выбирает оверлей по рамке
   кадра — берега, кувшинки, камыши из первой 12-байтовой таблицы .KN2
   (движок рисует их в порядке слотов после земли, VA 0x42543D; палитру
   записи сборка подменяет палитрой GRAPH — VA 0x43E4E9, потому панель
   её не правит). Панель: спрайт GRAPH, x, y, убрать; Ctrl+клик —
   перенос; knyaz2.editorCloneOverlay() — клон в точку героя (тот же
   спрайт => кадр испечён => полный предпросмотр; свободный слот
   выбирает сервер). Ручка /editor/sprite правит sparse-records блока
   `dynamic` map.json проекта: поля записи меняются, raw НЕ трогается —
   binrec.pack кладёт поля поверх raw, неизвестные байты целы; новая
   запись — new_record от дефолта 12xFF. Живой предпросмотр — правка
   world.terrainOverlays + groundInvalidate() (экспорт ground.js:
   запечённый слой земли перепекается следующим кадром).

10. **Признаки клеток (полная карта бит)** — СДЕЛАНО: панель клетки
    (Alt+клик) выросла с двух флагов до всей кисти признаков старого
    редактора. ДИЗАСМ (обработчик кнопок редактора FUN_00410F50 —
    кисть DAT_00640AEC, отрисовка нажатости FUN_00412878; запись в
    клетку OR'ом/стирание AND NOT — FUN_004108AB): слово клетки
    (0x5662BC + row*0x280 + col*4) несёт LO 0-11 NoWay (0xFFF глушь;
    в рантайме метка юнита), LO 12 выход с карты (курсор перехода
    0x428B88; ставится зоной, не кнопкой), LO 13 РАНТАЙМ «в клетке
    куча» (0x423360), LO 14 NoFly (стрелы, 0x41FDD0/0x414AF8), LO 15
    Transparency (юнит рисуется поверх отложенным списком, 0x425DB4
    байт+1 & 0x80 — тот самый «& 0x8000», которого grep по u32 не
    видел), HI 0-4 номер объекта 1-30 (списки юнитов по объектам,
    0x428240), HI 5 Inner (интерьер), HI 6 Light (daylit — дневная
    палитра юнита, 0x425DB4 байт+2 & 0x40; наше ядро уже читает его в
    terrain.bright -> daylit_cells пака), HI 7 UpOff — редактор пишет,
    финальный движок НЕ читает нигде. «Тайл (HI)» фазы 5 был ложной
    подписью — HI не тайл, а битовое поле; поле заменено честными
    чекбоксами с подписями кнопок старого редактора.

11. **Новая карта с нуля** — СДЕЛАНО: knyaz2.editorNewMap(N, "Имя") /
    POST /editor/newmap рождает пустой проект project/maps/NN_слаг
    (транслит имени: идентификаторы — латиницей): grid.txt весь
    4FFF:0000 (чистый лист старого редактора — сплошная глушь,
    расчищаемая кистью), чёрные layer1/2.png, map.json с пустыми
    таблицами (дефолты: объекты и оверлеи 0xFF-сентинел, вода нулевая,
    light_flag 0), пустой scenario.json. Сборка находит папку по глобу
    NN_* сама; жителей и выходов у нового номера в GAME.0 нет — пак
    честно даёт пустое население, наполнение кладут фазы 1-3 и кисти
    тайлов/воды. Карта играбельна после пересборки (--map N); номер
    1-254, занятые отбиваются.

12. **Библиотека контента (тулбар, каталог, бестиарий)** — СДЕЛАНО по
    отзыву первого пользователя («кроме перемещения и правки юнитов
    ничего не заметил»): консольные ручки получили ВИДИМЫЙ тулбар в
    панели (юнит+/объект+/куча+/тайлы/вода). «Объект+» — каталог из
    паспорта пака (assets/objects/index.json, 451 канонная пара
    «гнездо+палитра+состояние» с готовыми картинками — щелчок ставит
    в точку героя; добавка = запись T_OBJECTS в map.json проекта,
    сборка печёт слои и рамку как родным; живой предпросмотр — пропс
    из уже испечённых кадров пака, world.objects пересортируется как
    в dialog.js). «Юнит+» — бестиарий, собранный сканом самого пака:
    23 породы (breed|0x40) со связкой тело/имя/масти и ЧЕСТНЫМИ
    числами (statы/характеристики/навыки сняты с живого юнита), превью
    кадром stand с листа тварей; выбор отряда из warbands карты (вражда
    живёт в отряде, не в юните — warband.js) либо «новый вражий отряд»:
    слой editor_warbands_add в scenario.json, сборка подмешивает его
    отрядам ВСЕХ миров, зона агрессии ±20 клеток вокруг героя,
    war_flags 0x01 (нападать на игрока). Канон-фикс по пути: добавка
    в T_DYNAMIC/T_OBJECTS идёт строго ЗА последним занятым слотом —
    движок читает таблицы до первого пустого (0x80000000-сентинел в
    0x43DF48), запись в дырке прятала бы хвост. Клон пропса теперь
    виден сразу (push и в world.objects — недосмотр фазы 4).

Разгадки форматов по ходу (важно для оставшихся фаз): блок 0x3D184,
звавшийся в kn2.py «T_LIGHT», — на деле КАРТА ПОДЛОЖКИ-ВОДЫ 16x32
(«Water N of 512» старого редактора — счёт ненулевых; тип Lake/Stream —
см. фазу 8: OR всех байтов, 0x80 стоит / 0x40 течёт); «16 источников
света» не существует — свет живёт в layer2. Режим SPRITE старого — это
записи T_DYNAMIC (оверлеи GRAPH), в проекте ключ dynamic map.json.

## Что взято у старого редактора

Язык привычек: F2 — сохранить, подсветка несохранённого, статистика в
строке состояния (фаза 2), режимы-вкладки TILE/SPRITE/OBJECT как модель
для наших фаз. Форматы данных берём не у него, а у нашего пака — он
уже проверен сверками против движка на десятках тысяч полей.

## Уроки

- **Слои живут в scenario.json, не в map.json**: сборка читает сценарий
  из source/scenario.json, а map.json — метаданные карты. Первая версия
  ручки писала в map.json, и правки НЕ ДОЕЗЖАЛИ до пака; юнит-тесты
  звали функции напрямую и разрыва не видели. Теперь это держит
  интеграционный прогон: слой в scenario.json -> сборка карты 33 ->
  уровень юнита и клон в паке всех миров (проверено 24.08).

## Ограничения фазы 1 (честно)

- Правки применяются ко ВСЕМ мирам разом (патч по id юнита); по-мировые
  правки — ключом вида `editor_units_by_world` при надобности.
- Дев-сервер пишет в проект только локально: боевой сервер ручки НЕ
  несёт (deploy_web её не выкладывает — файл server.py серверу не нужен,
  там nginx). Редактирование — процесс разработчика.
- Пересборка пака нужна, чтобы правка доехала до пака (кэш выпечки
  делает это быстро); живой предпросмотр работает и до пересборки.
