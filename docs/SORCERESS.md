# Волшебница: свой персонаж из Diablo II

Играбельный герой, чьи кадры взяты из Diablo II LoD 1.14d, с огненным шаром
по правой кнопке. Заведён **отдельной записью рядом с канонными**: выбор
Велиславны остаётся выбором Велиславны, ни один канонный шаблон не переписан.

Документ описывает, что сделано, какими числами это проверено и на какие
грабли наступили по дороге.

## Как играть

Обычный запуск, никаких ключей в адресе:

```bash
python -m knyaz2.web
```

На экране «Новая игра» появилась **десятая** кнопка — «Волшебница», своей
клеткой под сеткой канонных портретов. Дальше как обычно.

* `C` — огонь по цели под курсором; если курсор ни на кого не показывает,
  по ближайшему чужому.
* **Правая кнопка** по миру — огонь в ту сторону, куда указали, как в Diablo:
  летит по вектору и жжёт первого встречного.

## Откуда берутся кадры

Извлечение живёт отдельно, в `C:\Games\d2extract` (свой конвейер MPQ → DCC →
PNG, зависимости — только numpy и Pillow). Оно ничего не знает про «Князя»,
кроме формата на выходе.

```bash
python tools/to_konung.py                       # кадры волшебницы
python tools/to_konung_projectile.py            # огненный шар + взрыв
python tools/to_konung_projectile.py --missile FireCast_for_Sorceress \
    --burst "" --name firecast --keep-anchor    # вспышка в руках
```

Кладут результат в `project/creatures/<имя>/` и `project/projectiles/<имя>/`:
`set.json` с разметкой и `sheet.png` со всеми кадрами. Дальше их подхватывает
обычная сборка пака.

### Соглашения, которые пришлось сводить

**Направления.** У «Князя» они нумеруются `0=W 1=NW 2=N 3=NE 4=E 5=SE 6=S
7=SW` — это снято с таблицы шагов движка `DIRECTION_STEPS`. У Diablo нумерация
начинается с юга и идёт туда же, по часовой, но **кадры в файле лежат
перемешанными**. Игровое направление `k` — это кадр
`[4,8,0,9,5,10,1,11,6,12,2,13,7,14,3,15][k]`; проверено численно, сортировка
шестнадцати кадров по углу вектора «правая рука минус левая» даёт ровно эту
последовательность. Итог: направление «Князя» `j` берётся из диабловского
`(j + 2) mod 8`.

**Якорь.** У персонажа кадр привязан к точке под ногами — так в обеих играх,
и смещения переносятся как есть. У **снаряда** привязка тоже к земле, и это
важно: огненный шар нарисован уже поднятым на 54 точки над своей точкой, то
есть по плечо. Поэтому снаряд пускается **по земле**, а высоту даёт сам кадр.

**Масштаб** совпал сам: человек в «Князе» около 85 точек ростом, волшебница
около 68. Пересчёта нет.

## Формат своих наборов

### Существо — `project/creatures/<имя>/set.json`

```json
{ "name": "sorceress", "title": "Волшебница", "body": 200, "palette": "0",
  "sheet": "sheet.png",
  "poses": { "stand": [ [ {"x":0,"y":0,"width":28,"height":68,
                           "offset_x":-14,"offset_y":-64,
                           "shadow": { … }}, … ], …восемь направлений… ], … },
  "playable": { "name": "Волшебница", "story": "…", "world": 0, "breed": 64,
                "characteristics": {"Ловкость": 30, "Выносливость": 30} } }
```

Поз девятнадцать: шесть тварных (`stand`, `walk`, `hit`, `death_1`, `rise`,
`attack`) и словарь героя (`idle`, `run`, `attack_one_hand`,
`attack_two_hand`, `attack_shield`, `death_2/3`, `corpse_1/2/3`, `shoot_bow`,
`shoot_crossbow`, `cast`). Клиент ищет позу по имени в наборе **раньше**, чем
в кадрах `HEROES.RES`, поэтому один набор служит и твари, и герою. Чего в
наборе нет — откатывается к `stand`; из-за этого `run` обязателен, иначе герой
бежит стоя.

Больше восемнадцати кадров в направлении класть нельзя: столько держит
таблица анимаций движка. Смерть у Diablo длиннее, её прореживаем.

Тени у нас свои: у диабловского персонажа отдельного спрайта тени нет, а
клиент её ждёт. Строится преобразованием силуэта, числа сняты с 23 канонных
стоячих кадров — сдвиг 0.7 на пиксель высоты, сжатие 0.45, низ по низу тела.

Блок `playable` делает набор **персонажем на экране выбора**. Подробности —
ниже, в разделе про десятый слот.

### Снаряд — `project/projectiles/<имя>/set.json`

```json
{ "name": "fireball", "sheet": "sheet.png",
  "directions": [ [ {…кадр…}, … ], …восемь… ],
  "burst": [ {…кадр…}, … ],
  "trans": "1", "table": "Missiles.txt", "blend": "additive" }
```

`blend` не выдуман: конвертер читает столбец `Trans` из таблицы самой игры. У
`FireBall` там `1` — «прозрачность по яркости», то есть сложение; у оверлея
вспышки `3`. Что означает тройка, документации нет, сложение для неё — наше
решение, и оно снимает чёрную кайму.

## Что добавлено в движок

Правило было одно: **добавлять, а не переписывать**. Все правки в общем коде
устроены так, что у канонных данных нужного поля нет вовсе и поведение не
меняется.

### Сборка (`knyaz2/content/builder.py`)

| что | где |
|---|---|
| `_custom_creatures` | подшивает свои наборы к канонным, сдвигая номера листов; занять канонное тело нельзя — сборка остановится |
| `_custom_hero_choices` | добавляет персонажа на экран выбора следующим слотом |
| `_custom_projectiles` | свои снаряды в `shared.projectiles` |
| `_png_size` | размер листа из IHDR, без графических библиотек |

Свои наборы подшиваются **после** канонных и мимо паспорта кадров — тот
считается по `OBJECTS.RES`, нашего набора там нет, поэтому кэш выпечки
продолжает работать.

### Клиент

| файл | что |
|---|---|
| `actor.js` | `actorPoseKnown` — есть ли поза именно в наборе, без отката к `stand` |
| `hero.js` | разовое действие может прийти из набора; тварь-игрок ходит блоками человека, а не таблицей зверей |
| `progress.js` | шаблон может нести `breed` |
| `cursors.js` | подпись под курсором ищется по слоту, потом по миру |
| `creation.js` | кнопка персонажам за пределами девяти портретных клеток |
| `app.js`, `save.js` | свой персонаж узнаётся по слоту при старте и в сохранении |
| `app.js` | страховка от прибытия в непроходимую клетку |
| `world.js` | `projectiles` из `shared.json` доезжают до карты |
| `projectiles.js` | свои спрайты снаряда, вспышки, режим сложения, высота полёта, свободный выстрел |
| `combat.js` | `heroCast`, `heroCastAt`, отложенный выпуск `castRelease` |
| `input.js` | клавиша `C` и правая кнопка |
| `units.js` | `cast` в списке разовых поз; список юнитов наружу для свободного снаряда |
| `scene.js` | огонь отдельным проходом поверх сцены |

### Десятый слот на экране выбора

Канонных записей девять (шесть своих героев и три донорских), портретных
клеток в `NEWHERO.RES` тоже девять. Свой персонаж становится десятым: ему
рисуется кнопка следующей строкой той же сетки и подписывается именем, потому
что портрета у него нет.

**Мир он занимает у канонного.** Жители, кучи, деревни и отряды разложены в
паке по мирам (`units_by_world` и соседи), и своего населения у нового слота
взяться неоткуда — поэтому `template.world` остаётся базовым (у волшебницы
нулевым), а для подписи в шаблон кладётся `slot`. По нему же её узнают
загрузчик и сохранение: искать по миру нельзя, там найдётся канонный сосед.

### Скорость — канонной механикой

Движок считает игроку скорость сам, из Ловкости и Выносливости:
`(вынос + ловкость) / 50`, потолок 2 (`carry.js unitSpeed`, VA 0x41B3B8). У
стартовой шестёрки сумма 25–31, то есть скорость 0 и бег 4 такта на клетку.
Волшебнице дано 30/30 — сумма 60, скорость 1, **бег 3 такта**. Никаких
множителей в формулу не добавлено; захотите быстрее — поднимайте
характеристики в `playable`.

### Огонь

Каст не имеет своей боевой математики. Он повторяет форму плевка Кикиморы:
оружие не нужно, дальность константой (`0x28` клеток), а долетевший снаряд
разрешается тем же `strike`, что и стрела, — урон, смерть и опыт считаются
канонно.

* Нажатие ставит намерение `combat.pendingCast`, огонь уходит **на середине
  раскадровки** (кадр 7 из 14). Позу сбили — намерение снято.
* Герой разворачивается к цели, спрайту снаряда направление считается из
  вектора полёта, а не из взгляда стрелка.
* Вспышка в руках зажигается **с началом жеста** и крутится в полтора раза
  быстрее такта.
* Свободный выстрел (правая кнопка) цели не имеет: попадание ищется перебором
  живых чужих на каждом подшаге. Своих не задевает.
* Огонь рисуется **отдельным проходом после слоя суток и юнитов**: он светит,
  затенять его нечем, а вспышка обязана лечь на фигуру. Канонная стрела при
  этом осталась внутри сцены, как в движке.

## Чем проверено

Всё ниже — замеры в живом клиенте, не рассуждения.

| что | как | результат |
|---|---|---|
| рисуется наш набор | сравнение с канонной послойной отрисовкой | 6650 расходящихся пикселей, кадр восстанавливается до бита |
| направления | угол «правая рука минус левая» по 16 кадрам | порядок совпал с таблицей, хранимое 4 = лицом к камере |
| порядок слоёв COF | «ближнее плечо рисуется позже дальнего» | 31 из 32 против 15 из 32 при неверной сцепке |
| перекрытие головы | доля закрытых пикселей | было 3–11 %, стало 0–2 % |
| скорость | `unitCellTicks` из клиента | бег 3 такта, ходьба 8 |
| выпуск огня | запись по 30 мс | кадр 7 из 14 |
| зацикливание позы | та же запись | кадры 0…13 по разу, дальше `stand` |
| вспышка поверх фигуры | огненные точки в рамке спрайта | 78 до каста, 3333 на пике (рамка ~4000) |
| темп вспышки | та же запись | 19.2 кадра в секунду при расчётных 19.2 |
| свободный выстрел | вектор шага | `(0, −4)` при цели строго на север |
| снаряд не бессмертен | жизнь по тактам | 40 → 37, исчезает |
| канон не тронут | сравнение списка стартов | девять записей побайтово те же |

Тесты: `tests/test_custom_creatures.py`, 14 штук — слой наборов, слой
персонажей, скорость из характеристик, отказ занять канонное тело, годность
поставляемого набора. Плюс `tools/check_sorceress.py` — проверка собранного
пака.

## Грабли, на которые наступили

Записаны, чтобы не наступить снова.

1. **Кадры DCC лежат перемешанными по направлениям**, а таблица порядка слоёв
   в COF индексируется **игровым** направлением. Сцепив их напрямую, получаешь
   наплечник поверх головы в половине направлений.
2. **У Волшебницы нет анимации `A2` голыми руками** — есть только COF, слоёв
   нет вовсе. Пустая поза в наборе означает, что клиент не нарисует героя;
   конвертер такие позы выбрасывает.
3. **Шаблон выбранного персонажа ставит облик ПОСЛЕ всего.** Переодевать
   героя своими полями бесполезно — затрёт. Заводить надо своим слотом.
4. **Загрузчик и сохранение ищут персонажа по миру.** Своему миру взяться
   неоткуда, поэтому только по слоту.
5. **Лист снаряда надо класть в предзагрузку.** Рисовальщик молча уходит,
   когда картинки нет, и выглядит это как «эффекта нет вовсе». Заодно
   выяснилось, что канонные стрелы не предзагружались на новой игре.
6. **Поза, которой нет в списке действий, зацикливается.** В разборе конца
   анимации есть особый случай для `rise`; `cast` попал в ту же яму. Теперь
   там именованный список разовых поз набора.
7. **`?map=N` входит без записи прибытия**, а у 24 карт из 52 её нет — герой
   остаётся на координатах прошлой карты и может оказаться в скале.
8. **Огонь в Diablo рисуется сложением.** Обычной альфой у шара вылезает
   чёрная кайма: 38 % его площади — точки яркостью ниже 60.

## Чего нет

* **Экипировки на волшебнице не видно.** Тварь рисуется одним кадром целиком,
  слоёв у неё нет — меч и доспех в руках не появятся. Это цена подхода.
* **Звука у каста нет.** Фаербол не канонное заклинание, своего слота в
  звуковых таблицах у него нет.
* **Ни маны, ни отката** — жать можно хоть каждый кадр.
* **Друида и Убийцы не будет**: `d2exp.mpq` в установке отсутствует, доступны
  пять классов оригинала.
