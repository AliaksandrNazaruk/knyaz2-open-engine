# Глобальная карта: скорость похода и встречи

Дата разбора: 2026-08-10. Повод — отчёт тестера: «по карте мира перемещение
слишком быстрое, в оригинале скорость зависит от уровня навыка Следопыт».

Всё ниже снято с `konung2.exe`. Навык 13 «Следопыт» — байт **+0xDF** записи
юнита (навыки идут подряд с +0xD2, проверено независимо: навык 12
«Приготовление смесей» = +0xDE, его растит варка).

## 1. Скорость похода — `FUN_00421690`, щелчок по карте мира

```c
// расстояние — ЧЕБЫШЕВСКОЕ: большая из двух проекций
iVar4 = abs(dx);
_DAT_008496C0 = (iVar4 < abs(dy)) ? abs(dy) : abs(dx);

// ЛУЧШИЙ СЛЕДОПЫТ В ОТРЯДЕ, а не у игрока
local_18 = 0;
для каждого юнита отряда:
    если local_18 < юнит[+0xDF] -> local_18 = юнит[+0xDF];

_DAT_00849568 = ((100 - local_18) * 0.01 + 1.0) * _DAT_008496C0;
_DAT_00849564 = dx / _DAT_00849568;      // шаг по X за такт
_DAT_00849568 = dy / _DAT_00849568;      // шаг по Y за такт
_DAT_008496C0 = ROUND(...);              // счётчик тактов пути
```

Константа `0.01` — `float` по **0x45049E**.

**Делитель = (100 − навык) · 0.01 + 1.0**, и он же множитель числа тактов:

| Следопыт | делитель | во сколько дольше идти |
|---|---|---|
| 0 | 2.00 | вдвое |
| 25 | 1.75 | |
| 50 | 1.50 | в полтора раза |
| 75 | 1.25 | |
| 100 | 1.00 | предел скорости |

То есть навык ускоряет поход **ровно вдвое** между нулём и сотней, не
больше. Скорость задаётся не длительностью, а ШАГОМ ПО ОСЯМ: `dx/делитель`
и `dy/делитель` за такт. Если двигать отряд постоянным шагом, поход выходит
всегда самым быстрым — это и есть наша ошибка.

**Навык берётся ЛУЧШИЙ ПО ОТРЯДУ.** Перебор идёт по числу юнитов отряда
(`_DAT_0084950C[+0x19]`), начиная с игрока, шагом 0x100.

## 2. Случайные встречи — `FUN_004277F4`, такт глобальной

```c
если ((DAT_0084962C & 0xF) == 0)            // раз в шестнадцать кадров
   && ... условия по клетке ...
   && (rand() % 100 > игрок[+0xDF])          // БРОСОК ПРОТИВ СЛЕДОПЫТА
{
    открыть ENCOUNTS.RES, собрать встречу
}
```

Здесь навык берётся **только у игрока**, а не максимум по отряду — в
отличие от скорости. Работает как защита: бросок из ста должен ПРЕВЫСИТЬ
навык. При Следопыте 100 случайных встреч не бывает вовсе, при нуле они
возможны на каждой проверке.

Период проверки — тот же счётчик кадров и та же маска `& 0xF`, что у отравы
(VA 0x41C944), то есть раз в шестнадцать кадров.

## 3. Чего в разборе нет

* Прочие условия встречи (три сравнения по клетке перед броском) не
  разобраны — сняты только маска периода и сам бросок.
* Как расходуется игровое время в походе и где тикает отрава на глобальной
  (VA 0x4277F4 её тоже трогает) — отдельная работа.

## 4. Что чинить в клиенте

1. Ход по карте мира должен делить шаг на `(100 − лучший Следопыт) · 0.01 + 1`.
2. Расстояние — чебышевское, `max(|dx|, |dy|)`, а не евклидово.
3. Порог случайной встречи — `rand() % 100 > Следопыт игрока`, раз в
   шестнадцать тактов.
