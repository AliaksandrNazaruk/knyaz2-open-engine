# Редактор полного цикла: видение

Дата: 25.08.2026. Отношение к другим документам: EDITOR_SPEC.md — API
и рабочий контракт ТЕКУЩЕГО этапа; этот документ — куда идём: редактор,
которым можно собрать «Князя 2» ЦЕЛИКОМ или новую игру на движке, а не
только подправить существующее.

---

## 1. Игра как данные: полная инвентаризация

Чтобы «создать всю игру», редактор обязан покрыть каждый домен. Опись —
по нашим разборам (FORMATS.md, аудиты) и авторским докам (посылка
k2_tools). Статус: ✔ редактируется сейчас, ◐ читается/частично,
✗ пока только в оригинале.

| Домен | Данные | Статус |
|---|---|---|
| **Ландшафт локации** | тайлы 2 слоя + свет (layer1/2), вода 16×32 Lake/Stream, сетка 256×160 с битами | ✔ фазы 5,7,8,10 |
| **Объекты локации** | T_OBJECTS (здания/реквизит), T_DYNAMIC (декор), T_ZONES (обстановка интерьеров, 30×16 гнёзд) | ✔ объекты/декор; ✗ интерьеры |
| **Фазы строений** | серия из 7 объектов подряд = стадии стройки (дока EDIT: фундамент→готовое, движок сам правит фазы при деревне; частокол ≤100 секций) | ✗ (редактор должен понимать серии) |
| **Население мира** | GAME.0-5: группы (зона расстановки=зона агрессии, тип/нация/враги, лимит), юниты (модель+палитра, 6 параметров, 20+ навыков, снаряжение с прочностью/бонусами, инвентарь, деньги, имя из _N, лицо, диалог, точки поведения день/ночь: стояние/встреча/посещение/тренировка/спарринг) | ◐ draft-слои поверх пака |

Вывод №1: **ядро локаций уже редактируемо**; три великих разрыва до
«полной игры» — **миры/население**, **сюжет-редактор**, **глобальная
карта**. Всё остальное — техника.

## 2. Уроки авторского пайплайна (как игру делали авторы)

Посылка k2_tools содержит ВЕСЬ конвейер 2002-2003 годов:

```
EDIT.EXE  ──────────► N.KN2            (ландшафт+объекты локаций)
GAMERES-тексты ─────► M_UNIT ─► GAME.N (миры: группы, юниты, вещи)
KONUNG2.QST ────────► M_QUEST ► QUESTS.RES (сюжет)
PALETTES.TXT ───────► PALETTES.RES     (палитры!)
```

86 текстовых исходников миров (GAME_0..5.TXT + по файлу на карту) —
авторы расставляли население НЕ редактором, а ТЕКСТОМ: группа → юниты
с навыками и снаряжением построчно. Уроки:

1. **Исходники — текст, бинарь — продукт компиляции.** Дифф, ревью,
   поиск, массовая правка серией — всё бесплатно. Наш проект уже так
   устроен для карт; миры должны стать такими же.
2. **Данные декларативны и самодостаточны**: UNIT.MODEL=0,RUSS —
   модель+палитра по имени; UNIT.NAME=35,0 — индекс имени. Редактор
   полного цикла = красивый фронтенд над такой моделью, а не над
   бинарём.
3. **Лимиты — часть формата** (512 воды, 100 секций частокола, 12
   поселений, резерв мест в деревне под наёмников): валидатор обязан
   их знать.
4. **Автопочинка при загрузке** (движок сам выправляет фазы строений):
   редактор может позволить черновую неточность там, где рантайм
   чинит, но обязан её показывать.

## 3. Уроки официального редактора (язык привычек)

Режимы TILE / SPRITE / OBJECT / CELL + вода + признаки; статистика
карты всегда на экране; листание палитр PgUp/PgDn; TAB — цикл режимов,
Ctrl+буква — прямой выбор; Space — взять элемент под курсором,
стрелки — точное смещение, Ins — дублировать, Del — удалить, Enter —
поставить, F2 — сохранить. Наш UI обязан говорить на этом языке —
он проверен девятью годами карт сообщества.

## 5. Архитектура совершенного редактора

```
┌────────────────────────────────────────────────────────────┐
│  UI (Claude Design): холст+палитры+инспектор+БД+граф+чертежи│
└───────────────┬────────────────────────────────────────────┘
                │ JSON API (v2 сейчас; v3 добавляет миры/сюжет)
┌───────────────▼────────────────────────────────────────────┐
│  Дев-сервер: схемы, валидатор, журнал мутаций (undo),      │
│  каталоги с превью, Build-очередь, Play                     │
└───────────────┬────────────────────────────────────────────┘
                │ читает/пишет
┌───────────────▼────────────────────────────────────────────┐
│  ПРОЕКТ = исходники ВСЕЙ игры (git):                        │
│  project/maps/NN_*      — локации (есть)                    │
│  project/worlds/N/*     — миры: группы/юниты/поселения (НЕТ │
│                           — этап E2, замена бинарям GAME.N) │
│  project/story/*        — диалоги+токены (.QST → JSON-граф) │
│  project/rules,items,…  — правила, вещи, тексты, звук       │
└───────────────┬────────────────────────────────────────────┘
                │ сборка (компилятор, как M_UNIT+M_QUEST+пак)
┌───────────────▼────────────────────────────────────────────┐
│  content_build — пак; опционально экспорт в ОРИГИНАЛЬНЫЕ    │
│  форматы (.KN2 уже умеем; GAME.N/QUESTS.RES — можно)        │
└────────────────────────────────────────────────────────────┘
```

Принципиальные решения:

1. **Undo/redo = журнал мутаций на сервере.** Каждый POST/DELETE
   пишется в журнал (операция + обратная операция); `POST /undo`
   откатывает верх стека. Плюс git проекта как «вечный undo».
2. **Схемы данных публикуются API** (`GET /schema/unit` и т.д.) — UI
   строит формы инспектора автоматически, новые поля не требуют правок
   UI.
3. **Валидатор** (`GET /maps/{n}/validate`): битые ссылки (спрайт/
   диалог/класс вещи/имя), заблокированные выходы, юнит в глуши,
   перелимиты (вода>512, частокол>100), фазы строений не серией,
   группа без зоны. Уровни: ошибка/предупреждение.
4. **Автотайлинг**: по 140 картам собирается матрица допустимых
   соседств пар тайлов → кисть «биом» сама кладёт переходы. Данные
   уже есть — нужен один анализ.
5. **Префабы**: JSON-чертёж (кусок terrain + объекты + юниты
   относительно якоря). Штамп «деревня руссов», «лагерь разбойников».
   Обмен чертежами строкой.
6. **Мир-исходники (E2, ключевой разрыв)**: конвертер GAME.N → 
   project/worlds/N/{groups.json, units.json, villages.json} (модель
   ровно как GAMERES: группа/зона/тип/юниты/точки поведения) + сборка
   scenario из них. После E2 draft-слои editor_* становятся не нужны —
   редактор правит мир напрямую, «весь мир редактируем» без пометок
   поверх бинаря.
7. **Сюжет-граф (E3)**: .QST → JSON-граф (секции=узлы, ответы=рёбра,
   переключатели=условия на рёбрах, токены=переменные, директивы=
   действия) — двусторонний конвертер (граф ↔ .QST, M_QUEST остаётся
   компилятором истины). UI — узловой редактор как в Twine; валидатор
   считает недостижимые секции.
8. **Совместимость с оригиналом — двунаправленная**: проект собирается
   и в наш пак, и (где возможно) назад в форматы игры: .KN2 уже
   пишем; GAME.N поддаётся (формат разобран полностью), QUESTS.RES
   через M_QUEST. Карта, сделанная нашим редактором, может поехать в
   ОРИГИНАЛЬНЫЙ konung2.exe.

## 6. Дорожная карта

| Этап | Содержание | Опора |
|---|---|---|
| **E1 (идёт)** | UI поверх API v2: холст из проекта, палитры, инспектор, Build/Play | SPEC v2 готова, API живо |
| **E1.5** | журнал мутаций → undo/redo; валидатор №1 (ссылки+лимиты); схемы форм; горячие клавиши старого редактора | сервер |
| **E2** | мир-исходники project/worlds + конвертер GAME.N↔JSON + вкладка «Население»: группы с зонами на холсте, юниты формами, точки поведения перетаскиванием | konung2/gamefile.py читает всё |
| **E3** | сюжет-граф: .QST↔JSON, узловой UI, валидатор достижимости; директивы карт подсвечиваются на холсте | M_QUEST живой |
| **E4** | автотайлинг-кисти; префабы/чертежи; интерьеры (T_ZONES) визуально; серии фаз строений | 140 карт как корпус |
| **E5** | глобальная карта (значки, маршруты, встречи ENCOUNTS), базы данных (вещи/породы/имена/тексты), звук-назначение | форматы разобраны |
| **E6** | «новая игра на движке»: пустой проект-шаблон целиком, экспорт в оригинальные форматы, тотальная замена ресурсов (свои тайлы/спрайты через писатели RES) | п.5.8 |

Первый шаг за пределами E1 — **E1.5 + конвертер GAME.N → JSON** (ядро
E2): он превращает «модификатор» в «редактор игры», и вся остальная
дорожка стоит на нём.
