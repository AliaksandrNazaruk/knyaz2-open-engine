# План мода «Новая деревня» для Князь 2: Кровь Титанов

> Этот документ описывает исторический план конкретного мода. Каноническая
> архитектура нового движка находится в `ARCHITECTURE.md`, глобальные этапы —
> в `ROADMAP.md`.

## Что уже известно (см. FORMATS.md)

- Карта = `<N>.KN2`, формат разобран полностью (сетка 160×256, объекты, зоны).
- **Слоты карт 4 и 5 свободны**: в таблице имён локаций exe они пустые,
  файлов 4.KN2/5.KN2 нет, но для слота 5 остался загрузочный экран `PICS\m5.res`
  (вырезанный контент). Движок строит имя файла из номера — если положить
  4.KN2 рядом с остальными, загрузчик его прочитает.
- NPC мира лежат в GAME.0–5 (юниты 2000×256Б) и привязываются к картам
  **группами** (250×17Б: {u16 rt; u8 тип; u8 флаги; u8 карта; u16 члены[6]}).
- Все реплики — в QUESTS.RES. Полный файл = 469000 байт (5 таблиц структуры
  диалогов + блоб строк + состояния); в установке лежал обрезанный (308400,
  только блоб) — в стендах заменён полным из дистрибутива.
- Названия локаций/имена NPC — таблицы указателей в exe (патчится).

## Три пути реализации (от простого к сложному)

### Путь A — «Перестроить существующую локацию» (рекомендуемый старт)
Взять малоиспользуемую боевую карту (например 32 «Местность у лесной просеки»
или 41 «Стоянка разбойников») и превратить её в новую деревню:

1. Скопировать 19.KN2 (Черный Бор) → 32.KN2: получаем готовую деревню
   с частоколом, домами и проходимостью.
2. В GAME.x добавить группу(ы) с map=32 и юнитов-NPC (староста, кузнец…).
3. Переименовать локацию в exe (указатель имени → новая строка).
4. Тексты диалогов — переиспользовать существующие индексы QUESTS.RES
   (деревенские реплики универсальны), новые квесты — дописать строки.

Риски: минимальные — не меняется число карт; переходы уже существуют.

### Путь B — «Задействовать слот 4/5» (полноценная новая деревня)
1. Создать 4.KN2 (за основу взять любую деревню, перерисовать).
2. Прописать имя в таблицу указателей (file 0x4D2D4 + 4*4 → адрес новой
   строки; строку разместить в свободном хвосте DGROUP).
3. Добавить переход на карту 4 с соседней карты: в KN2-секции зон (30×192)
   исходной карты добавить зону перехода (нужен эксперимент — тип зоны
   перехода пока не подтверждён) ЛИБО скрипт-командой `MAP=` в QUESTS.RES.
4. Группы + юниты в GAME.x (map=4).
5. Опционально PICS\m4.res (можно скопировать m5.res).

Риски: движок может где-то держать жёсткий список «деревень» (управление,
дань). Требуется тестовая итерация: скопировать 19.KN2 → 4.KN2 «как есть»,
телепортироваться и проверить, работает ли управление деревней.

### Путь C — «Мод через сейв» (быстрые эксперименты)
KONUNG2.SA0 содержит те же структуры (юниты с 0x4B2CC, предметы с 0x115C).
Редактируя сейв, можно мгновенно проверять гипотезы (телепорт героя на
карту N — поле карты юнита №0, добавление NPC) без правки GAME.x.
Редактор-референс: github.com/Benzeliden/konung-2-save-editor.

## Открытые вопросы (проверить экспериментом)

1. Как активируется управление деревней — по номеру карты (hardcode) или
   по наличию юнита-старосты? → тест: копия деревни на карте 32.
2. Формат зоны перехода между картами (секция 8 KN2, 30×192) — какая
   подзапись = выход, куда пишется целевая карта. → сравнить парные карты.
3. Чит `MAP=` — как вводится (консоль в игре?). → проверить в игре ввод
   текста; если нет — использовать правку сейва для телепорта.
4. ~~Слой 2 KN2 (0x6400) — назначение~~ РЕШЕНО: номер маски локального света
   (LIGHTS.RES, тёплое освещение уже наложенных тайлов), см. FORMATS.md.
5. Расписание событий (GAME.x @0xC6AAE) — не сломает ли новая деревня
   тайминги рейдов. → наблюдение.

## Итоги стендовых проверок (2026-08-02, стенд Knyaz2Test)

- **Формула клеток подтверждена в игре**: x = col·58 + (row&1)·29, y = row·16.
  Три независимых свидетельства: таблица соседей в exe (VA 0x441344),
  попиксельный матчинг скриншотов с рендером render_village.py (FFT-корреляция,
  tools/campilot.py), герой дважды наблюдался ровно в целочисленных клетках
  ((80,35) и (101,58); анкор спрайта ~+10px ниже точки клетки).
- **Координаты жителей поселения в GAME.x игрой игнорируются**: при старте
  новой игры движок расставляет их сам (по зданиям и рабочим местам — прилавок,
  колодец; часть уходит в интерьеры). Для мода это ХОРОШО: NPC достаточно
  привязать группой к поселению, позиции задавать не нужно. Управлять точным
  местом юнита-жителя через GAME.x нельзя.
- Отряд игрока стартует ОКОЛО записанной клетки, но движок корректирует
  позицию (проходимость/вводное поведение) — точную клетку не гарантировать.
- Камера: прокрутка курсором у ФИЗИЧЕСКОГО края экрана (~570–700 px/с гориз,
  ~440–500 верт); восстановление свёрнутого окна иногда сбрасывает камеру
  к отряду. Наводка камеры на клетку/пиксель: tools/campilot.py.

## Правила безопасности

- **Всегда бэкапить** изменяемый файл (папка игры требует прав администратора).
- Игра проверяет только размеры файлов при чтении — размер должен байт в байт
  совпадать с оригиналом (256516 для KN2, 813902 для GAME.x, 469000 для
  полного QUESTS.RES).
- Кодировка любых текстов — CP866; символы вне неё игра не отрисует.
- Тестовое прохождение начинать новой игрой: GAME.x читается только при старте
  новой игры, старые сейвы не увидят изменений мира.
