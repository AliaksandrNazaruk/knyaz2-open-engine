# Knyaz2Modding — «Князь 2: Кровь Титанов» как редактируемый проект

Игра распакована в текстовые исходники и собирается обратно **байт-в-байт**.
Модмейкер правит JSON, текст и PNG, а не двоичные файлы в hex-редакторе.

```
исходники (текст)        сборка               установка
project/  ──────────►  build/  ──────────►  папка игры
   ▲                                            │
   └──────── tools/unpack_all.py ◄──────────────┘
```

Готовых инструментов для «Князя 2» в сети нет — сообщество разобрало только
формат сохранений и ресурсы первой части. Всё здесь получено
реверс-инжинирингом `konung2.exe`.

## Установка

Нужен Python 3 и Pillow:

```bash
pip install pillow
```

Если игра установлена не по умолчанию, задайте путь:

```bash
set KONUNG2_DIR=D:\Games\Knyaz2
```

## Как этим пользоваться

Распаковать игру в проект (папку игры не трогает):

```bash
python tools\unpack_all.py
```

Собрать файлы игры из проекта и посмотреть, что изменилось:

```bash
python tools\build_all.py --verify
```

Установить мод (нужны права администратора — игра лежит в Program Files;
оригиналы сами копируются в `backup/`):

```bash
python tools\install.py
```

Откатить всё обратно:

```bash
python tools\install.py --restore
```

Повторный `unpack_all.py` в любой момент возвращает проект к «ванильному»
состоянию.

## Утилиты

```bash
python tools\rt_all.py                  # проверка: всё собирается байт-в-байт
python tools\world_report.py 0          # кто и где стоит в мире GAME.0
python tools\world_report.py 0 19       # подробно по карте 19 (Черный Бор)
python tools\graph_report.py            # граф переходов между локациями
python tools\graph_report.py --dot      # он же для Graphviz
python tools\kn2view.py 19 --info       # отрисовать карту в PNG
python tools\res_extract.py palettes    # выгрузить палитры
python tools\res_extract.py objects 0 5 # выгрузить спрайты объектов в PNG
python -m knyaz2.content build --map 19 --output content_build   # ОДНА карта: только для проверки рендера
python -m knyaz2.content verify content_build
# Для ИГРЫ пак собирают со всеми 52 картами — команда в CONTENT_PACK.md:
# с одной картой не открываются деревни, переходы и встречи в пути.
python -m knyaz2.web                    # http://127.0.0.1:8765
```

У браузерной карты есть диагностика рендера: флажки в левой панели показывают
сырые клетки земли и порядок объектов, а наведение выводит индексы тайлов,
маску локального света, ресурс, состояние и якорь. Клавиша `D` включает или выключает
оба оверлея; URL `http://127.0.0.1:8765/?debug=1` открывает их сразу. Флажок
крыши — диагностический: каноническая последовательность оригинала рисует
`main`, затем `walls`, затем условный `roof` с одним и тем же якорем.

### Клиент по модулям

`knyaz2/web/static/` — ES-модули, всего их за шестьдесят. Ниже ядро рендера;
кроме него клиент несёт игровую логику: бой (`combat.js`, `projectiles.js`,
`warband.js`), диалоги и квесты (`dialog.js`, `questitems.js`), торговлю и
инвентарь (`trade.js`, `shops.js`, `inventory.js`, `loot.js`), меню, создание
героя и сейвы (`menu.js`, `creation.js`, `save.js`), звук (`audio.js`,
`sfx.js`, `soundscape.js`), карту мира (`worldmap.js`), деревню (`village.js`)
и агентские ручки (`agent.js`).

| Модуль | Что делает |
|---|---|
| `dom.js` | узлы страницы, больше их никто не ищет |
| `viewport.js` | холст, слои кадра, камера, фильтр времени суток |
| `content.js` | чтение пака и предзагрузка картинок |
| `world.js` | мир в рантайме: земля, сущности, порядок отрисовки |
| `daylight.js` | время суток и часы |
| `light.js` | локальный свет у построек |
| `water.js` | анимированная подложка |
| `shadows.js` | тени |
| `hero.js` | персонаж: движение, кадры, видимость в доме |
| `entities.js` | постройки и реквизит |
| `ambient.js` | атмосфера (наше расширение) |
| `scene.js` | сборка кадра целиком |
| `debug.js` | диагностические оверлеи |
| `input.js` | ввод |
| `app.js` | точка входа: загрузка, цикл кадров, `window.knyaz2` |
| `selfcheck.js` | повторяемая проверка правил света, глубины и отрисовки юнитов (11 проверок) |

Граф импортов без петель: `dom` и `world` ни от кого не зависят,
`scene` собирает остальное, `app` только заводит. Единственная общая изменяемая
величина — текущая цель рисования `viewport.context`: её переключают
`beginSceneLayer` и `withMainContext`, остальные модули видят живую привязку.

### Карта как сущности

Сырые таблицы `.KN2` и `OBJECTS.RES` дальше `konung2.world` не идут: выше
работают с постройками, реквизитом и клетками земли.

```python
from konung2.world import MapModel, Cell

world = MapModel.from_game(19)
print(len(world.buildings), len(world.props))        # 10 107

izba = world.buildings[0]
print(izba.bounds.width, len(izba.cells.floor))      # габариты и пол интерьера
print(izba.interior_is_daylit)                       # True — main не темнеет
print(izba.hides_roof_for(Cell(105, 28)))            # крыша прячется на клетке

cell = Cell(105, 28)
world.building_at(cell)      # чья это клетка
world.interior_at(cell)      # внутри какой постройки стоит
world.passable(cell)         # проходима ли (младшие 12 бит слова)
world.unit_is_daylit(cell)   # бит 22: юнит здесь рисуется дневной палитрой
world.in_draw_order()        # порядок отрисовки движка
```

Каждое правило на сущности снабжено ссылкой на код движка, откуда оно снято.
Сборщик content pack — тонкая сериализация этой модели; на ней же строятся
инструменты и редактор карт.

### Земля: процедурная брусчатка

Клетки земли в оригинале — один тайл, размноженный сеткой: на карте 19 треть
всей площади это тайл 0 без второго слоя. Генератор считает материал по
мировым координатам, поэтому рисунок продолжается через границу клетки и швов
не возникает.

```bash
python tools/ground_experiment.py            # заменить брусчатку в собранном паке
```

```bash
python tools/ground_experiment.py --restore  # вернуть исходные клетки
```

Материал собирается из фотонабора (`project/materials`, CC0) и своих слоёв:
грязь затекает в швы по карте высот, затенение считается из градиента, а
собственные тени рельефа — маршем луча навстречу солнцу. Три вещи оказались
важнее выбора текстуры, и все три проверялись числами:

* **узор идёт по осям земли, а не экрана.** Изометрия — наклонённая
  плоскость, оси даёт ромб клетки (57, 32) и (57, −32). Без этого кладка
  ложится параллельно краю кадра и читается наклейкой поверх сцены.
* **объём даёт не освещение, а собственные тени.** На камне в 15 экранных
  пикселей усиление рельефа меняет кадр на 2.4 из 255, косое солнце — на 4.0:
  незаметно. Тени рельефа с усиленным контрастом высоты — 6.4 и 28 % пикселей.
* **фотография мощения не годится как текстура камня.** Её собственная
  раскладка спорит с нашей, выходит узор в узоре; при своей раскладке
  (`--layout voronoi`) с фотографии берутся только частоты — зерно и цвет.

Снять кадр для сравнения вариантов можно без браузера:

```bash
python tools/render_pack.py --at 2 --size 1000 560 --out scene.png
```

### Движение персонажа

Анимации и правила сняты с движка, а не подобраны.

**Две стойки** — бит `0x04` байта `unit+0x19`. У каждой свои четыре блока:
стойка, ходьба, простой, бег. Боевая — 0, 1, 6, 7; мирная — 16, 17, 18, 19.
Какая какая, видно по тому, кто бит трогает: ставят его переход в бой
(VA `0x4103D6`, `0x411423`) и любая атака (`0x416AF7`, `0x416B85`), а снимают
в четырёх: `and 0xFB` по `0x410DCA` (приказ «стой, с тобой говорят») и `xor 4`
по `0x41145F` (рассудок: дел не осталось), `0x420577`, `0x420D0F` (перевод
блока). При включении бита
текущий блок переводится таблицей `0x45A0C0` (16→0, 17→1, 18→6, 19→7), обратная
`0x45A098` переводит назад. То же говорят слои: у блоков 0, 1, 6, 7 заняты все
54 слоя, включая натянутый лук и заряженный самострел, — с оружием наготове
ходить можно только в них.

**Ходьба и бег** — бит `0x80` того же байта, его ставит режим движения 1
(VA `0x416641`); по нему выбирается блок 7/19 вместо 1/17 (VA `0x4166A5`).
В клиенте одиночный клик даёт шаг, двойной — бег. Скорость следует из длины
цикла: 14 кадров у ходьбы против 9 у бега, клетка — половина цикла.

**Простой** — не таймер, а жребий: пока играет стойка, движок бросает
`rand() % 10` и при нуле включает блок простоя (VA `0x416D92`). Тот доигрывает
23 кадра, из которых 6 разных — остальное задержки, персонаж переминается и
водит головой, — и по таблице возвращается в стойку.

**Удары и выстрелы** — отдельных анимаций под меч, топор или лук у тела нет:
оружие живёт своим слоем экипировки, а блоков действия ровно пять, и какой
играет — решает группа предмета (`[0x45DB08 + тип * 32] >> 16`). Ближний бой
берёт предмет основной руки `unit+0x56` (VA `0x416B50`): группа ≥ `0x0D`
(двуручные мечи, топоры, секиры, палицы) → блок 8, иначе блок 5, если вторая
рука занята, и блок 9, если пуста. Стрельба берёт предмет второй руки
`unit+0x58` (VA `0x416AC8`) и играет блок 10 для боевого самострела (группа
`0x15`) и блок 4 для лука. Блок 2 — не защита, а реакция на полученный урон:
оба вызова стоят сразу после списания здоровья (`0x41418B`, `0x42022F`);
отдельной анимации блока щитом в движке нет, все 20 блоков заняты.

**Смерть** — жребий ровно из трёх вариантов: `rand() % 3` даёт блок 3, 11 или
12 (VA `0x416A5D`), перед этим юнит вычищается из своей клетки (`0x416A52`),
поэтому стеной для других он больше не считается. Номер варианта сохраняется
в позе трупа: движок ставит блок 13 для первой смерти и «блок + 3» для
остальных (`0x41471E`, `0x414727`), то есть 11→14 и 12→15.

**Маршрут** — волна по проходимым клеткам. Движок заполняет волновую карту
(массив `0x59E320`), трассирует её назад по таблице соседей `0x49CFA8` и
кладёт в юнита кусок пути **не длиннее 16 шагов** (VA `0x441441`), а когда
кусок кончается — строит следующий. Поэтому персонаж обходит стены, а не
утыкается в них. Клиент повторяет это устройство: та же волна, тот же предел
куска, та же достройка на ходу. Перед поиском движок вычищает ссылку на
самого юнита из его клетки (VA `0x4165CF`), иначе тот считает себя стеной.

### Проверки освещения и глубины

Правила света снимались с кода движка, и ломались они молча — поэтому на них
две сетки безопасности.

```bash
python -m pytest tests\test_lighting_contract.py -q   # константы против konung2.exe
```

Тесты читают сам `konung2.exe` и падают, если разойдутся порог включения света
(тик 8100, `i16 @0x45FC46`), ночные уровни (`0x00CECEBA` из VA 0x429832), закон
маски (VA 0x43FD70) или бит дневной палитры построек (`hdr+0xFE & 4`).

Кадр проверяется в браузере — консоль страницы:

```js
knyaz2.selfcheck()
```

Прогон занимает около шести секунд и печатает шесть правил с числами: интерьер
постройки день == ночь, стены темнеют по уровню, аура только прибавляет свет и
не трогает синий, свет включается ровно с тика 8100, персонаж внутри дома виден
сквозь стену, светлые кадры не подменяют чужие пиксели. Запускать после любой
перестановки слоёв рендера.

## Пример: новая деревня

```bash
python mods\new_village\make.py --target 32 --name "Новая Весь"
python tools\build_all.py --verify
python tools\install.py
```

Клонирует деревню Черный Бор в слот локации 32, переселяет туда копию её
жителей (со всеми службами — староста, кузнец, знахарь), **прокладывает
двусторонний переход** и переименовывает локацию. Изменяются 8 файлов:
`32.KN2`, шесть `GAME.x` и `konung2.exe`.

Дорога делается так: у Черного Бора берётся южная краевая полоса, которая
раньше означала «уйти с локации», и превращается в переход к новой деревне;
обратный переход строится симметрично. Полосы уже нарисованы разработчиками,
поэтому подбирать проходимые клетки вручную не нужно. Куда вести дорогу,
задаёт ключ `--link <номер локации>`.

**Изменения мира видны только при начале новой игры** — файлы `GAME.x`
читаются один раз при старте.

## Главное о форматах

- Все тексты — **CP866**, размеры файлов менять нельзя.
- Юниты не хранят номер карты: их расставляет **таблица отрядов**
  (отряд знает карту и владеет срезом массива юнитов). Отряд №0 — игрок.
- Переходы между локациями — отдельная таблица в `GAME.x`: источник, цель,
  точка входа и зона-триггер. Координаты в порядке **(строка, столбец)**.
- Клетка карты `0x4FFF` = пусто и проходимо.
- **Слоты локаций 4 и 5 свободны** — вырезанный контент, годятся под новые карты.
- Деревни: Беглое=18, Черный Бор=19, Приволье=20, Поднебесье=21, Борье=33.

Подробности и адреса в коде движка — в [FORMATS.md](FORMATS.md).

## Каталог мира

    python tools\catalog.py

Собирает в `catalog/` полный справочник по содержимому мира:

* `tiles.json`, `tiles/NNN.png` — все тайлы земли: индекс, палитра, размеры;
* `objects.json`, `objects/NNN.png` — все объекты `OBJECTS.RES`: слот, значение
  поля `sprite` записи карты, палитра, якорь, наличие стен и крыши, состояния;
* `cells.json` — какие сочетания признаков клеток встречаются на всех картах;
* `tiles_sheet.png`, `objects_sheet.png` — контактные листы;
* `index.html` — всё вместе для просмотра в браузере.

Слот объекта равен полю `sprite` записи карты плюс 30, палитра — полю `kind`
той же записи (индекс = `kind / 512`) либо палитре слота, если там ноль.
