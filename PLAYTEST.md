# Проверка мода в игре — журнал

## Как запускать без прав администратора

Папка игры лежит в Program Files и защищена от записи. Поэтому мод не
устанавливается в саму игру, а собирается **зеркало** в доступной папке:
корневые файлы копируются, подкаталоги (озвучка, видео, картинки — ~570 МБ)
подключаются junction'ами.

```bash
python tools\build_all.py --verify
powershell -File tools\make_testrig.ps1        # -> Documents\Knyaz2Test
python tools\playtest.py start 18              # запуск + скриншот
```

Оригинал игры при этом не изменяется — скрипт это проверяет.

Для проверки конкретной локации без долгой ходьбы:

```bash
python tools\testbuild_start_at.py 32          # герой стартует прямо в ней
```

Контрольное зеркало **чистой игры** (без мода) — `Documents\Knyaz2Vanilla`,
собирается тем же скриптом с пустой папкой сборки:

```bash
powershell -File tools\make_testrig.ps1 -Dest "$env:USERPROFILE\Documents\Knyaz2Vanilla" -Build "$env:TEMP\k2empty"
```

## Что подтверждено в игре

* Мод запускается: патченый `konung2.exe` проходит заставку и меню.
* Экран выбора героя работает, все шесть персонажей на месте.
* **Клонированная деревня отрисовывается** — избы, мощёная улица, частокол.
* **Жители на месте**: при наведении курсора игра показывает
  «Мстислав, Уров:2, Здор:100» — то есть механика отрядов и юнитов
  (`отряд.map` + срез массива юнитов) работает как разобрано.
* Прокрутка камеры по новой карте не роняет игру (после исправления №2).

## Найденные и исправленные падения

### 1. Нулевой указатель поселения (чтение по 0x3D8, инструкция 0x412D17)

Падало сразу при заходе на клонированную деревню.

Причина: движок ищет поселение для текущей карты, перебирая 12 записей
по адресу 0x83D408 (блок `GAME.x` @0xC3322) и сравнивая байт +3 с номером
карты (VA 0x43E6E4). Для новой карты записи не было, указатель 0x849538
остался нулевым, а первый же «деревенский» объект его разыменовал.

Исправление: `GameWorld.add_village()` копирует запись существующего
поселения в свободный слот и меняет байт карты. Слотов 12, занято 10.

**Побочный результат:** это ответ на давний вопрос «что делает локацию
деревней» — именно запись в этой таблице. Поселений там больше, чем деревень:
Черный Бор, Борье, Темнолесье, Нижний лагерь, Поднебесье, Приволье, Беглое,
Морской лагерь, Торговый пост, Лесной лагерь.

### 2. Переход по нулевому адресу при прокрутке камеры

Падало при движении камеры по новой карте.

Причина: в exe есть таблица параметров локаций (44 записи по 6 байт,
файловое смещение 0x4D1CC). Загрузчик карты (VA 0x43DF9D) выполняет часть
инициализации только если `карта <= 43 && параметры[карта] != 0`.
У карты 32 запись была нулевой, инициализация не выполнялась.

Исправление: `tools\patch_maptable.py` копирует запись локации-образца;
таблица выведена в `project\exe\map_params.json` и применяется при сборке.

## Текущий стенд: деревня с одним подопытным

```bash
python mods\new_village\make.py --target 32 --name "Новая Весь" --link 19 ^
        --residents 1 --npc-name "Ноунейм"
python tools\build_all.py --verify
powershell -File tools\make_testrig.ps1
python tools\testbuild_start_at.py 32      # старт сразу в деревне
python tools\playtest.py demo 0            # весь проход одним запуском
```

Что получается (сверено по собранному `build\GAME.0`):

| | |
|---|---|
| карта | 32, клон Черного Бора, названа «Новая Весь» |
| отряд | #164, база 983, кол-во 1 |
| подопытный | юнит **983**, имя «Ноунейм» (`name_id` 117), клетка строка 79 / столбец 26, тип 16, уровень 6, HP 1600 |
| поселение | запись #10 (копия Черного Бора, id 55) |
| дорога | переходы 51 и 88: Черный Бор ↔ Новая Весь |

Оригинальный Черный Бор не тронут — все девять его жителей на местах.

Имя занимает свободную строку таблицы `npc_names` (была «Хатуволафр», на неё
не ссылался ни один юнит ни в одном из шести миров), поэтому переименование
никого больше не задевает.

### Важно: зоны переходов принадлежат карте, а не файлу .KN2

Зоны заданы в координатах конкретной карты и живут в `GAME.x`, поэтому при
клонировании карты их надо переносить отдельно. Иначе у клона остаются зоны
прежней локации: «Местность у лесной просеки» занимала строки 2…110 и
столбцы 0…48, а клон Черного Бора — строки до 182 и столбцы до 76, и старые
«края» оказывались **посреди деревни** — игрок проваливался на глобальную
карту прямо на улице.

Делает `GameWorld.clone_exits(source, target)`: чужие зоны убираются, зоны
образца переносятся. Копируются только зоны ухода (`to_map = -1`) — связи
с конкретными локациями односторонние, на той стороне обратной записи нет.

После переноса у Новой Веси: южная полоса (строки 169…179) — дорога в
Черный Бор, восточная (столбцы 71…74) — выход на глобальную карту.

### Важно: как выделяются слоты юнитов

Отряд — это непрерывный срез `base_unit .. base_unit+count`, поэтому новые
юниты нельзя селить сразу за чужим отрядом: подрастёт дружина игрока — и наш
NPC молча станет её бойцом. `add_party()` теперь выделяет слоты **за самым
дальним занятым**, отсюда номер 983, а не 3.

### Управление игрой из скриптов

Полноэкранное DirectDraw-приложение сворачивается, как только фокус уходит
другому окну, и после этого его не поднять. Поэтому длинные сценарии надо
гонять одним процессом — команда `playtest.py demo`, а не серией вызовов.
Полезное из наблюдений: `ESC` открывает игровое меню, `M` — карту локации,
подсказка «Выход на карту Лесной страны» подтверждает, что переходы с
`to_map = -1` ведут на глобальную карту.

## РЕШЕНО (диагноз): падение при разговоре — обрезанный QUESTS.RES

Симптом: обращение к любому NPC роняет игру переходом по нулевому адресу,
в том числе в оригинальных локациях и на чистой (без мода) копии игры.

Причина найдена по загрузчику (VA 0x43DAC6). Настоящий QUESTS.RES состоит
из семи секций общим размером **469 000 байт**: пять таблиц структуры
диалогов (160 600 байт), затем блоб строк (307 200) и состояния квестов
(1 200). Файл в этой установке — **308 400 байт**, ровно две последние
секции: пять таблиц отсутствуют. Дата файла 14.04.2025 при остальных файлах
от 09.01.2008 — его пересохранили инструментом, выбросившим служебную часть.

Движок читает файл вслепую фиксированными блоками: первые 160 600 байт
*текста* попадают в таблицы указателей диалогов, разговор уходит по
мусорному адресу — мгновенное падение. Меню, создание героя, карта и бой
работают, потому что не трогают диалоги.

Независимое подтверждение: quests.res соседней игры коллекции
(«Продолжение легенды», тот же движок) начинается с бинарных таблиц,
а наш файл — сразу с текста «МИССИЯ ТИТАНОВ».

Таблицы диалоговых деревьев из текста не восстанавливаются — нужен
оригинальный файл из дистрибутива (переустановка игры или копия файла
из того же издания). Локально копий не найдено (VirtualStore, корзина,
соседние папки, Downloads проверены).
