# Многослойный причинный автомат: прототип живого NPC

Мир, где поведение не написано сценарием, а возникает из связи слоёв:
пространство → тело → потребности → восприятие → знания → отношения →
намерения → действия.

## Важное расхождение с исходным ТЗ

ТЗ предполагало, что в проекте уже есть игровой цикл, отрисовка карты и
управляемый игрок на Python. Этого нет и не может быть: `Knyaz2Modding` —
не движок, а **набор кодеков**. Он читает и пишет двоичные файлы игры, но во
время игры не выполняется ни одной его строки. Сам «Князь 2» — закрытый
бинарник 2004 года на Watcom C++; его ИИ вкомпилирован внутрь и не умеет
обращаться к внешнему коду. Точки расширения нет: `MP.DLL`, которую движок
подгружает, отвечает лишь за проигрывание видео.

Поэтому причинный автомат **не может управлять жителем внутри игры**. Чтобы
не подменять задачу и не строить костыль, сделано так: симуляция автономна,
но берёт настоящие данные — карту деревни из `32.KN2` и жителя из собранного
`GAME.0`. Это полигон на реальной географии, а не отвлечённая песочница.

Что это даёт и чего не даёт:

* правила, слои и причинные цепочки работают по-настоящему;
* поведение воспроизводимо и покрыто тестами;
* но житель внутри `konung2.exe` по-прежнему управляется движком игры.

Перенос поведения в игру потребовал бы либо перехвата кода движка, либо
собственного клиента, читающего наши форматы. Это отдельная большая работа.

## Устройство

```
simulation/
    config.py             все числовые настройки
    world_state.py        состояние мира и инварианты
    commands.py           намерения и наблюдаемые действия
    rules.py              предусловия и последствия
    action_resolver.py    общий исполнитель и разрешение споров
    simulation_loop.py    двухфазный такт
    bridge.py             мост к файлам игры
    debug.py              объяснение решений, текстовая карта
    systems/
        needs.py          голод, энергия, истощение, смерть
        perception.py     радиус зрения и линия обзора
        knowledge.py      личная память, устаревание, опровержение
        movement.py       A* по сетке
        decision.py       выбор действия по оценкам
        relationships.py  доверие, страх, враждебность
```

## Запуск

```bash
python run_sim.py --ticks 1000                # на карте деревни
python run_sim.py --ticks 200 --watch 20      # с текстовой картой
python run_sim.py --synthetic                 # без файлов игры
python run_sim.py --steal-at 20               # игрок забирает еду при свидетеле
python -m pytest tests -q                     # 21 тест
```

## Принципы, заложенные в код

**Одни правила для всех.** `TakeIntent` исполняется одним и тем же кодом
независимо от того, кто его породил. Проверок `if actor.is_player` в правилах
нет; роль влияет только на источник намерения — у игрока это ввод, у жителя
оценка вариантов.

**ИИ не трогает мир.** Система решений возвращает намерение и ничего не
меняет. Проверку, разрешение споров и применение делает `action_resolver`.

**Двухфазный такт.** Сначала все читают снимок начала тика, потом всё
применяется. Порядок обхода списка персонажей на исход не влияет.

**Мир хранит состояние, а не сюжет.** Нет ни стадий квестов, ни флагов вида
«предал». Отчёт о тике существует только для отладки, логика его не читает.

**Житель видит не всё.** Полное состояние мира читает лишь система
восприятия. Решения принимаются по `Perception` и личной памяти, поэтому
житель может ошибаться: он идёт к тому месту, которое помнит.

## Причинная цепочка, которая получается сама

Проверено прогоном на 1000 тиков (`--seed 3`):

```
голод растёт
→ житель замечает еду в поле зрения и запоминает место
→ строит путь и идёт туда
→ берёт и съедает, голод падает
→ игрок, стоящий рядом, видит это и теряет к нему доверие
```

Последняя строка особенно показательна: правило «на моих глазах забрали
еду» универсально, поэтому его применил **игрок к жителю**, хотя писалось
оно ради обратного случая.

За 1000 тиков житель девять раз самостоятельно нашёл и съел еду, сохранив
полное здоровье. Ни маршрута, ни расписания у него нет.

## Что сделано и что нет

Сделано: слои 1–8, общий механизм действий, разрешение споров по ловкости с
детерминированным жребием, A*, utility-выбор с объяснением, отношения по трём
шкалам, устаревание памяти, инварианты, отладочный вывод, 21 тест
(автономность, ограниченное знание, устаревшая память, свидетель, отсутствие
свидетеля, справедливость, детерминизм).

Не сделано: интерактивное управление игроком (в сценарии оно задаётся
намерениями), полноценная интерпретация речевых актов — сейчас житель умеет
только попросить еду, ответной реакции ещё нет. Бой, экономика и LLM не
внедрялись сознательно, как и требовало ТЗ.

Ограничение: правило проходимости `hi != 0` выведено из наблюдения за
контурами построек, а не из кода движка. Оно собрано в одной функции
`bridge.passable_from_cell` и правится в одном месте.
